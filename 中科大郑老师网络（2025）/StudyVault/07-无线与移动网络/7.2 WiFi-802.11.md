# WiFi 802.11（重要性: ★★★）

#networking #wireless #wifi #802-11 #concept

## 概览表（一目了然）
| 条目 | 要点 |
|------|------|
| 标准演进 | b/g/n/ac/ax 等；共享信道用 **CSMA/CA** |
| 架构 | **BSS** + **AP**（基础设施）或纯 ad hoc |
| 关联 | **主动/被动扫描** → 关联 → 鉴别 → DHCP |
| MAC | **CSMA/CA** + 逐帧 ACK；可选 **RTS-CTS** |
| 帧地址 | 4 个地址字段；3 种典型场景 |

## 802.11 标准演进

| 标准 | 频段 | 范围 | 最大速率 | 年份 |
|------|------|------|----------|------|
| 802.11b | 2.4 GHz | 30 m | 11 Mbps | 1999 |
| 802.11g | 2.4 GHz | 30 m | 54 Mbps | 2003 |
| 802.11n (WiFi 4) | 2.4/5 GHz | 70 m | 600 Mbps | 2009 |
| 802.11ac (WiFi 5) | 5 GHz | 70 m | 3.47 Gbps | 2013 |
| 802.11ax (WiFi 6) | 2.4/5 GHz | 70 m | 14 Gbps | 2020 |

**共同点**：共享无线信道上使用 **CSMA/CA**；均有基础设施模式与自组织模式。

## 802.11 架构

| 模式 | 组成 |
|------|------|
| **基础设施模式** | 无线主机 + **AP（基站）** + **BSS（Basic Service Set，cell）** |
| **自组织模式** | 仅无线主机，无 AP |

```
Internet ── switch/router ── AP ── BSS (无线主机)
                              └── 多个 BSS 可共存
```

## 信道与关联

- 频谱分为多个**信道**；AP 管理员选择信道（邻居 AP 可能同信道干扰）
- 主机通信前须与 AP **关联(associate)**

| 步骤 | 内容 |
|------|------|
| 扫描 | 侦听信标帧（含 AP **SSID** 和 MAC）；**主动扫描**（发探测请求）或**被动扫描**（听信标） |
| 选择 AP | 选定要关联的 AP |
| 鉴别 | 基于 MAC/用户名口令，或通过 AP 中继到 **RADIUS** 服务器（见第 8 章） |
| 获址 | **DHCP** 获得 IP 与子网前缀 |

### 扫描流程对比

```
被动扫描:                          主动扫描:
  AP ──(1)信标──→ H1                H1 ──(1)探测请求──→ APs
  H1 ──(2)关联请求──→ AP            APs ──(2)探测响应──→ H1
  AP ──(3)关联响应──→ H1            H1 ──(3)关联请求──→ 选定AP
                                    AP ──(4)关联响应──→ H1
```

## 802.11 MAC：为何 CSMA/CA

802.11 使用 CSMA，但**无法做冲突检测(CD)**：

| 原因 | 说明 |
|------|------|
| 自身信号过强 | 发送站收到的自身信号远强于其他站，CD 困难 |
| 不冲突≠成功 | 隐藏终端/衰减：侦听空闲仍可能接收失败 |
| 暴露终端 | 有冲突迹象不代表发送必然失败 |
| 冲突代价高 | 无线中一旦发送须发完；冲突浪费严重 |

→ 采用 **CA（冲突避免）**：事前措施减少冲突 + **接收端 ACK** 确认。

## CSMA/CA 详细流程

```
发送方                              接收方
  │                                   │
  ├─ 信道空闲持续 DIFS? ──是──→ 发整帧 │
  │                                   ├─ 帧正确?
  ├─ 否 → 选随机回退，空闲时递减       │   └─ SIFS 后发 ACK
  │         (忙碌则冻结计数)           │
  ├─ 计数到 0 → 发整帧               │
  └─ 无 ACK → 倍增回退窗口，重试       │
```

**为何 countdown 到 0 才发？**

- LAN 的 CSMA/CD：A、B 等 C 发完立即发 → CD 检测冲突并放弃（代价低）
- WLAN：无法 CD，冲突代价极高 → A、B 分别选**不同随机回退值**，一个先胜，另一个冻结等待

**仍无法完全避免冲突的情况**：
- 情况 A：A、C 相互隐藏，随机回退后仍可能在 B 处冲突
- 情况 B：A、B 回退值非常接近，信号未达 B 时 B 也到 0 发送

## RTS-CTS 机制（可选）

思想：用**小预约分组**避免**长数据帧**冲突。

```
AP
A ── RTS ──→ AP ── CTS(广播) ──→ 所有节点听到
A ── DATA ──→ AP              其他节点在预约时段内 defer
```

| 步骤 | 说明 |
|------|------|
| 1 | 发送方 CSMA 发送小 **RTS** 给 AP（RTS 冲突浪费小，可重试） |
| 2 | AP 广播 **CTS**（所有相关节点可听到） |
| 3 | 发送方发数据帧；其他节点在预约时段**抑制发送** |

## 802.11 帧格式

```
┌─────────┬──────────┬─────────┬─────────┬─────────┬─────────┬─────────┬─────┐
│ frame   │ duration │ addr 1  │ addr 2  │ addr 3  │ addr 4  │ payload │ CRC │
│ control │          │ (接收方)│ (发送方)│ (路由器)│(ad hoc) │         │     │
└─────────┴──────────┴─────────┴─────────┴─────────┴─────────┴─────────┴─────┘
```

| 地址字段 | 含义 |
|----------|------|
| **Address 1** | 接收方 MAC（主机或 AP） |
| **Address 2** | 发送方 MAC（主机或 AP） |
| **Address 3** | AP 连接的路由器接口 MAC（子网出口路由器，DHCP 获得） |
| **Address 4** | **仅自组织模式**使用 |

### 三种地址场景（基础设施模式，H1 经 AP 到 R1）

**场景：H1 → AP → R1（发往 Internet）**

| 字段 | 值 |
|------|-----|
| Address 1 | AP MAC（接收方） |
| Address 2 | H1 MAC（发送方） |
| Address 3 | R1 MAC（最终目的路由器） |

对应以太网帧：dest=R1 MAC，src=H1 MAC（经 AP 中继后转换）。

> [!warning] 例外
> Address 4 仅在 ad hoc 模式使用；基础设施模式帧中 Address 4 不出现。

## 高级能力（补充）

| 能力 | 机制 |
|------|------|
| **速率自适应** | 连续 2 帧无 ACK → 降速；连续 10 帧 ACK → 升速 |
| **功率管理** | 节点通知 AP 休眠至下一信标；AP 缓存帧；信标列出待传节点列表 |
| **同子网移动** | H1 切换 AP1→AP2，IP 不变；交换机通过 AP 广播更新 MAC-port 映射 |

## 考试/测试常见模式
| 场景/关键词 | 答案 |
|-------------|------|
| "802.11 为何不用 CD" | 自身信号强、**不冲突≠成功**、冲突代价高 |
| "DIFS / SIFS" | DIFS 后发数据；接收方 **SIFS 后发 ACK** |
| "随机回退目的" | **事前避免冲突**（CA） |
| "RTS-CTS 作用" | 预约信道，避免**长帧冲突** |
| "Address 3" | **子网出口路由器** MAC |
| "主动 vs 被动扫描" | 主动=发探测请求；被动=听信标 |
| "BSS / AP / SSID" | BSS=基本服务集；AP=接入点；SSID=网络名 |
