# 移动性管理（重要性: ★★★）

#networking #wireless #mobility #4g-5g #concept

## 概览表（一目了然）
| 条目 | 要点 |
|------|------|
| 移动性谱 | 同 AP 内 → 跨运营商，通信连续性需求递增 |
| 两种原理 | **间接路由**（经归属）vs **直接路由**（经被访） |
| 4G/5G | 归属/被访网络、HSS、MME、GTP 隧道 |
| Mobile IP | 隧道间接路由；归属代理≈HSS+P-GW；**大规模部署少** |

## 移动性谱（网络视角）

```
无移动性 ─────────────────────────────────────→ 高移动性

  关机换网    同运营商AP间    跨运营商AP间    跨运营商且保持通信
  (低关注)      移动              移动           (我们关注的)
```

## 移动性管理原理

### 方案一：让网络（路由器）处理

- 移动节点永久地址不变，向路由器通告存在
- 路由表通过最长前缀匹配指示位置
- **对上百万移动节点不可扩展**

### 方案二：让端系统/边缘处理（主流）

| 概念 | 类比 |
|------|------|
| 移动节点有 **home** | 朋友搬家常换地址，但父母/ Facebook 知道最新位置 |
| **归属网络** | 位置信息的权威来源 |
| **被访网络** | 移动节点当前接入的非归属网络 |

### 间接路由 (Indirect Routing)

```
通信者 ──(1)发往永久地址──→ 归属网关 ──(2)隧道转发──→ 被访网关 ──(3)──→ 移动节点
                                    ↑
                              回复可经归属(4b)或直接(4a)
```

| 优点 | 缺点 |
|------|------|
| 移动性对通信者**透明** | **三角路由**；同网通信效率低 |
| 换被访网只需重新注册 | |
| 可维持 TCP 连接 | |

### 直接路由 (Direct Routing)

```
通信者 ──(1)查 HSS 获被访地址──→ (2)直接发往被访网关 ──(3)──→ 移动节点
```

| 优点 | 缺点 |
|------|------|
| 克服三角路由低效 | 外部地址对通信者**非透明** |
| | 再换被访网需额外操作；维持 TCP 较困难 |

## 归属网络与被访网络

### 4G/5G 蜂窝

| 概念 | 说明 |
|------|------|
| **归属网络** | 用户付费套餐；**HSS** 存身份、服务、当前位置 |
| **被访网络** | 非归属的任何网络；与归属有服务协议 |
| **SIM** | 全局身份（IMSI）含归属网络标识 |

### ISP/WiFi

- **无全局归属网络**概念；各 ISP 需不同用户名/口令
- 例外：**eduroam** 等机构间共享认证
- Mobile IP 架构类似 4G，但**较少使用**

## 4G 移动性实现

### 四大任务

```
1. 基站关联（IMSI 标识 + 归属网络）
2. 控制平面配置（MME ↔ 归属 HSS 建立状态）
3. 数据平面配置（MME 配置转发隧道）
4. 切换（BS 间 handover）
```

### 注册流程

```
1. 移动节点关联被访 MME
2. 被访 MME 向归属 HSS 注册 → HSS 知道当前位置
```

### 数据平面隧道

| 隧道 | 说明 |
|------|------|
| S-GW ↔ BS | BS 切换时**仅改 BS 端 IP** |
| 被访 S-GW ↔ 归属 P-GW | **间接路由**；进出被访网经 P-GW |

### 同运营商内 BS 切换

```
源BS ──(1)选目标BS，发切换请求──→ 目标BS
目标BS ──(2)预分配时隙，HR ACK──→ 源BS
源BS ──(3)通知 M 新 BS 可用──→ M 经新 BS 发送（切换完成）
源BS ──(4)停止直连 M，转发给新BS
目标BS ──(5)通知 MME
MME ──(6)指导 S-GW 改隧道端点到新 BS
目标BS ──(7)ACK 源BS，释放资源
```

## Mobile IP

| 要点 | 说明 |
|------|------|
| 标准化 | RFC 5944；远早于 4G 全 IP 支持 |
| 部署 | **未见大规模部署** |
| 架构 | **隧道间接路由** |
| 归属代理 | 综合 4G **HSS + 归属 P-GW** 角色 |
| 外部代理 | 综合 4G **MME + S-GW** 角色 |
| 注册 | 被访网代理发现协议；归属网 ICMP 扩展注册 care-of 地址 |

## 对高层协议的冲击

| 影响 | 说明 |
|------|------|
| 传输层 | 高 BER、分组丢失/延迟（链路层重传）、**切换丢失** |
| TCP 误动作 | 将恢复延迟当 RTT 增大；将丢失/出错当拥塞 → **不必要减 cwnd** |
| 应用层 | 延迟对实时应用不友好；带宽稀缺；**位置感知**带来新可能 |

> [!warning] 简化陈述的例外
> 逻辑上分层使冲击应很小（IP 尽力而为未变，TCP/UDP 可运行），但**性能**上差异明显。

## 考试/测试常见模式
| 场景/关键词 | 答案 |
|-------------|------|
| "间接路由缺点" | **三角路由** |
| "间接路由优点" | 移动性对通信者**透明**，可维持 TCP |
| "直接路由缺点" | care-of 地址**非透明**；换网复杂 |
| "4G 切换隧道变化" | S-GW↔BS 隧道**改 BS 端**；S-GW↔P-GW **不变** |
| "HSS 角色" | 归属网订户信息 + **当前位置** |
| "Mobile IP 路由方式" | **间接路由（隧道）** |
| "TCP 在无线网问题" | 丢包/延迟被误判为**拥塞** |
