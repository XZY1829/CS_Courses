# UDP 协议（重要性: ★★★）

#networking #transport-layer #udp #concept

## 概览表（一目了然）
| 条目 | 要点 |
|------|------|
| 定位 | "no frills" 互联网传输层协议 |
| 服务模型 | **尽力而为**：可能丢失、乱序 |
| 头部 | 8 字节：源端口、目的端口、长度、校验和 |
| 校验和 | 16 位字的 **1 的补码和**（含伪首部） |
| 适用场景 | 流媒体、DNS、SNMP、HTTP/3（QUIC 底层） |

## UDP 特点

| 特性 | 说明 |
|------|------|
| **无连接** | 无需建立连接（省去 RTT 延迟）；每个数据报独立处理 |
| **尽力而为** | 可能**丢失**、**乱序**交付 |
| **简单** | 发送方/接收方无需维护连接状态 |
| **小头部** | 仅 8 字节开销 |
| **无拥塞控制** | 不受拥塞控制制约，可恒定速率发送（拥塞时仍可发送） |

### 为什么需要 UDP？

- 无连接开销，适合实时应用
- 应用可容忍丢失，对带宽敏感
- 可在 UDP 之上自行实现可靠性（如 HTTP/3/QUIC）

## UDP 报文格式

```
 0                   16                  31
+--------+--------+--------+--------+
|   源端口号 (16)   |  目的端口号 (16)  |
+--------+--------+--------+--------+
|   长度 (16)      |  校验和 (16)     |
+--------+--------+--------+--------+
|          应用层数据 (payload)        |
+------------------------------------+
```

| 字段 | 含义 |
|------|------|
| **源端口/目的端口** | 各 16 位，用于多路复用/解复用 |
| **长度** | UDP 段总长度（字节），含头部 |
| **校验和** | 检测传输错误 |

## UDP 校验和计算

**目标**：检测 UDP 段中可能的位错误。

**发送方**：
1. 将 UDP 内容（含 UDP 头部 + **IP 伪首部**）视为 16 位整数序列
2. 计算这些字的**和**（1 的补码和）
3. 将结果填入校验和字段

**接收方**：
1. 对接收段重新计算校验和
2. 与校验和字段比较：不相等 → 出错；相等 → 大概率无错（**存在漏检**）

**进位回卷**：加法时最高位进位须加到最低位再求和。

```
例子:  5 + 6 = 11 (发送方校验和)
接收: 4 + 6 = 10 ≠ 11 → 检测出错误

漏检例子: 某些位翻转后校验和仍相同 → 无法检测
```

> [!warning]
> 互联网校验和**保护能力有限**：某些错误组合（如两个 16 位字中对应位同时翻转）可能产生相同校验和，导致漏检。

## UDP 适用场景

| 应用 | 原因 |
|------|------|
| **流媒体** | 可容忍丢失，带宽敏感 |
| **DNS** | 短请求-响应，低延迟 |
| **SNMP** | 简单网络管理 |
| **HTTP/3** | QUIC 在 UDP 之上提供可靠传输与拥塞控制 |

若需在 UDP 之上可靠传输：在**应用层**增加可靠性恢复和拥塞控制机制。

## UDP 传输层运行

**发送方**：应用报文 → 确定 UDP 头部 → 创建 UDP 段 → 交给 IP

**接收方**：从 IP 收段 → **检查校验和** → 通过 socket 解复用交给应用
