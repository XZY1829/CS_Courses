# TCP 报文与连接管理（重要性: ★★★）

#networking #transport-layer #tcp #concept

## 概览表（一目了然）
| 条目 | 要点 |
|------|------|
| 特性 | 面向连接、可靠保序字节流、全双工、点到点 |
| 关键字段 | 序号、确认号、标志位（SYN/FIN/ACK/RST）、rwnd |
| 三次握手 | SYN → SYNACK → ACK，同步初始序号 |
| 四次挥手 | FIN → ACK → FIN → ACK，对称释放 |
| 为何三次 | 防止半连接、老重复报文被误接受 |

## TCP 概述

| 特性 | 说明 |
|------|------|
| **面向连接** | 数据传输前握手初始化状态 |
| **可靠保序字节流** | 无应用报文边界；按 **MSS** 切分 |
| **全双工** | 同一连接双向同时通信 |
| **点到点** | 一个发送方、一个接收方 |
| **累积确认** | 类 GBN；流水线 + 拥塞/流量控制协同设置窗口 |
| **套接字模型** | 发送/接收缓存；进程读写 socket |

## TCP 报文段格式

```
 0                              16                             31
+--------+--------+-------------------------------------------+
| 源端口  | 目的端口 |                                           |
+--------+--------+                                           |
|                        序号 (32 bit)                         |
+--------------------------------------------------------------+
|                       确认号 (32 bit)                        |
+--+--+--+--+ 头长  | 保留 |U|A|P|R|S|F|      接收窗口 rwnd      |
|    |    | (4)  |      |R|C|S|S|Y|I|        (16 bit)          |
+--+--+--+--+------+------+---+---+----------------------------+
|           校验和          |        紧急指针 (若 URG=1)        |
+--------------------------------------------------------------+
|                    选项 (可变长) + 应用数据                     |
+--------------------------------------------------------------+
```

| 字段 | 含义 |
|------|------|
| **序号 (seq)** | 段载荷**第一个字节**在整个字节流中的字节编号 |
| **确认号 (ACK)** | 接收方**期待接收的下一个字节号**（累积确认） |
| **ACK 位** | ACK 字段有效时为 1 |
| **SYN/FIN/RST** | 连接管理：建立/释放/重置 |
| **rwnd** | 接收窗口，用于**流量控制** |
| **C, E 位** | 拥塞指示（ECN） |

### 序号与确认号示例（Telnet）

```
Host A 发: Seq=42, ACK=79, data='C'
Host B 回: Seq=79, ACK=43, data='C'  (回显)
Host A 发: Seq=43, ACK=80            (确认)
```

> [!warning]
> 协议规范**未规定**接收方如何处理乱序段——取决于实现（缓存或丢弃）。

## 三次握手

**为何不用两次握手？** 延迟变化、重传、乱序可能导致：服务器端**半连接**（客户端已终止）；**老重复数据**被当成新数据接受。

**解决方案**：变化的初始序号 + 双方分别确认对方序号。

```
Client                          Server
  |                               |  LISTEN
  |--- SYN, seq=x, SYN=1 -------->|
  |                               |  SYN_RCVD
  |<-- SYN+ACK, seq=y, ACK=x+1 ---|
  |  SYN_SENT                     |
  |--- ACK, ACKnum=y+1 ---------->|
  |  ESTAB                        |  ESTAB
```

| 步骤 | 客户端 | 服务器 |
|------|--------|--------|
| 1 | 选 init seq **x**，发 **SYN** | — |
| 2 | — | 选 init seq **y**，发 **SYN+ACK**（ACK=x+1） |
| 3 | 发 **ACK**（ACKnum=y+1）；可携带数据 | 收到 ACK(y) 表示客户端存活 |

第三次握手可携带**客户端到服务器的数据**（减少 RTT）。

**老重复报文处理**：若连接不存在则拒绝；若碰巧存在但序号不在当前连接范围内则丢弃。

## 四次挥手

**对称释放**：每方独立关闭自己一侧；发送 **FIN=1** 的段；收到 FIN 后用 ACK 回应（ACK 可与己方 FIN 合并）。

```
Client                          Server
  |  ESTAB                        |  ESTAB
  |--- FIN, seq=x --------------->|
  |  FIN_WAIT_1                   |  CLOSE_WAIT
  |<-- ACK, ACKnum=x+1 ----------|
  |  FIN_WAIT_2 (仍可收数据)       |
  |<-- FIN, seq=y ----------------|
  |  TIME_WAIT                    |  LAST_ACK
  |--- ACK, ACKnum=y+1 ---------->|
  |  (等待 2×MSL)                  |  CLOSED
  |  CLOSED                       |
```

| 状态 | 含义 |
|------|------|
| **FIN_WAIT_1** | 已发 FIN，等 ACK |
| **FIN_WAIT_2** | 已收 ACK，等对方 FIN；仍可收数据 |
| **CLOSE_WAIT** | 已收 FIN，应用应 close() |
| **LAST_ACK** | 已发 FIN，等最后 ACK |
| **TIME_WAIT** | 等 **2×最大段生存期（MSL）** 后 CLOSED |
| **CLOSED** | 连接完全关闭 |

> [!warning]
> TCP 连接关闭**不完美**，存在**两军问题**——无法保证对方一定收到最后的 ACK。

## 考试/测试常见模式
| 场景/关键词 | 答案 |
|-------------|------|
| "TCP 序号含义" | 段载荷**首字节**在字节流中的编号 |
| "TCP 确认号含义" | 期待接收的**下一个字节号**（累积确认） |
| "为何三次握手" | 防半连接、防**老重复报文**误接受 |
| "TIME_WAIT 时长" | **2×MSL** |
| "SYN/FIN 作用" | SYN=建立连接；FIN=释放连接 |
| "第三次握手可做什么" | 可携带**客户端数据** |
