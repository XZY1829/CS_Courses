# 可靠数据传输原理（重要性: ★★★）

#networking #transport-layer #reliable-transfer #concept

## 概览表（一目了然）
| 条目 | 要点 |
|------|------|
| 抽象 | 在**不可靠信道**上实现**可靠信道** |
| 渐进设计 | rdt1.0 → 2.0 → 2.1 → 2.2 → 3.0 |
| 停等性能 | U_sender = (L/R) / (RTT + L/R)，利用率极低 |
| 流水线 | 发送窗口 > 1，GBN 与 SR 两种策略 |
| SR 约束 | 序号空间大小 ≥ 发送窗口 + 接收窗口 |

## 可靠数据传输抽象

```
应用 ──data──→ [rdt 发送方] ──packet──→ 不可靠信道 ──→ [rdt 接收方] ──data──→ 应用
```

| 术语 | 含义 |
|------|------|
| **Data** | 可靠传输信息单元（如报文） |
| **Packet** | 不可靠传输信息单元（如报文段） |
| **Channel** | IP 传输路径或物理链路 |

协议复杂性取决于信道不可靠程度（丢失、损坏、乱序）。发送方/接收方**互不知晓对方状态**，须通过 packet 交换控制信息。

### 层间接口

| 函数 | 调用者 | 作用 |
|------|--------|------|
| `rdt_send(data)` | 上层 | 交付待发送数据 |
| `udt_send(packet)` | rdt | 放到不可靠信道 |
| `rdt_rcv(packet)` | 下层 | 收到 packet 时触发 |
| `deliver_data(data)` | rdt | 交付数据给上层 |

## rdt 渐进设计（FSM）

### rdt1.0 — 可靠信道

下层信道完全可靠（无比特出错、无丢失）。发送方/接收方 FSM **相互独立**，无需交互控制信息。

```
发送方: Wait for call from above → make_pkt → udt_send → (循环)
接收方: Wait for call from below → extract → deliver_data → (循环)
```

### rdt2.0 — 比特差错信道

- 用**校验和**检测比特差错
- **ACK**（确认）/ **NAK**（否定确认）
- 发送方收到 NAK → **重传**
- **停等（Stop-and-Wait）**：每发一个分组，等待 ACK/NAK

**rdt2.0 两难**：若 ACK/NAK 本身出错，发送方不知该重传老分组还是发新分组 → **致命缺陷**。

### rdt2.1 — ACK/NAK 出错

- 引入**序号**（0 和 1 足够，1 bit）
- ACK/NAK 出错时发送方**重传当前分组**
- 接收方用序号判断**重复**：丢弃重复分组，仍发 ACK

```
发送方状态: Wait for call 0/1 from above ↔ Wait for ACK or NAK 0/1
接收方状态: Wait for 0/1 from below（期望序号 0 或 1）
```

### rdt2.2 — 无 NAK 协议

- 取消 NAK，仅保留**带编号的 ACK**
- 接收方对**最后被正确接收的分组**显式确认
- 发送方收到**重复序号 ACK** → 等同 NAK，重传当前分组
- **TCP 采用此方法**；为流水线协议做准备

### rdt3.0 — 比特差错 + 分组丢失

- 新增机制：**超时定时器**
- 合理时间内未收到 ACK → **超时重传**
- 延迟（非丢失）的 ACK 导致重复 → 序号机制处理

```
发送方 FSM 关键转移:
  发送分组 → start_timer
  收到正确 ACK → stop_timer
  timeout → udt_send(sndpkt); start_timer  (重传)
```

## 停等协议性能分析

**例子**：1 Gbps 链路，15 ms 传播延迟，8000 bit 分组

**传输时延**：
\[
D_{trans} = \frac{L}{R} = \frac{8000}{10^9} = 8\ \mu s
\]

**发送方利用率**：
\[
U_{sender} = \frac{L/R}{RTT + L/R} = \frac{0.008}{30.008} \approx 0.00027
\]

协议本身严重限制信道利用率！

**3 分组流水线**可将利用率提升约 3 倍：
\[
U_{sender} = \frac{3L/R}{RTT + L/R} \approx 0.00081
\]

## 流水线协议与滑动窗口

| 要素 | 说明 |
|------|------|
| **发送缓冲区** | 存放已发送但未确认的分组（需重传） |
| **发送窗口** | 已发送但未确认分组的序号范围；尺寸 ≤ 缓冲区 |
| **接收窗口** | 控制哪些序号的分组可被接收 |
| **前沿移动** | 每发送一个分组，前沿前移 |
| **后沿移动** | 收到**最老分组**的确认，后沿前移 |

停等协议 = 发送窗口尺寸 **1**；流水线协议 > **1**。

## GBN vs SR 比较

| 对比项 | Go-Back-N (GBN) | Selective Repeat (SR) |
|--------|-----------------|----------------------|
| **接收窗口** | = 1（只能顺序接收） | > 1（可乱序接收） |
| **确认方式** | **累计确认** ACK(n) | **单独确认** 每个分组 |
| **乱序分组** | **丢弃** | **缓存** |
| **定时器** | **1 个**，与最老未确认分组关联 | **每个**未确认分组独立定时器 |
| **超时动作** | 重传从 n 开始的**所有**未确认分组 | **选择性**重传超时分组 |
| **适用** | 出错率低、带宽延迟积小 | 带宽延迟积大、出错率高 |
| **资源** | 简单，接收方 1 个缓存单元 | 复杂，接收方多个缓存单元 |

### GBN 发送方要点

- 累积性确认 ACK(n)：确认 n 及之前所有分组
- timeout(n)：重传从 n 开始窗口内**所有**已发送未确认分组

### SR 发送方/接收方要点

- 接收方：乱序到达 → 缓存 + 单独 ACK(n)
- 发送方：仅重传超时的单个分组
- **序号空间约束**：seq # 位数 ≥ log₂(N + W_r)，即 **N ≥ S + W**（S=发送窗口，W=接收窗口）

> [!warning]
> SR 两难：若序号空间过小，旧分组重传可能被接收方误判为新分组（如窗口=3、序号 base 4 时）。

## 考试/测试常见模式
| 场景/关键词 | 答案 |
|-------------|------|
| "rdt2.0 致命缺陷" | **ACK/NAK 出错**时不知重传老/新分组 |
| "rdt2.2 如何用 ACK 代替 NAK" | **重复序号 ACK** → 重传当前分组 |
| "rdt3.0 新增机制" | **超时定时器** |
| "停等利用率公式" | **U = (L/R) / (RTT + L/R)** |
| "GBN 超时重传" | 重传窗口内**所有**未确认分组 |
| "SR 超时重传" | 仅重传**超时**的单个分组 |
| "SR 序号约束" | 序号空间 ≥ 发送窗口 + 接收窗口 |
