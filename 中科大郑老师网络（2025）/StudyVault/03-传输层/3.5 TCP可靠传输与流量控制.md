# TCP 可靠传输与流量控制（重要性: ★★★）

#networking #transport-layer #tcp #reliable-transfer #flow-control #concept

## 概览表（一目了然）
| 条目 | 要点 |
|------|------|
| 可靠机制 | 序号 + 累积确认 + 超时重传 + 快速重传 |
| RTT 估计 | SampleRTT → EstimatedRTT（EWMA）→ DevRTT |
| 超时公式 | **TimeoutInterval = EstimatedRTT + 4×DevRTT** |
| 快速重传 | 收到 **3 个重复 ACK** → 立即重传最小序号段 |
| 流量控制 | 接收方通告 **rwnd**，限制 in-flight 数据量 |

## TCP 可靠传输机制

| 机制 | 说明 |
|------|------|
| **序号** | 按字节编号，检测重复/丢失 |
| **累积确认** | ACK 号 = 期待下一字节；确认该号之前所有字节 |
| **超时重传** | 最老未确认段超时 → 重传该段（类 SR） |
| **快速重传** | 3 个冗余 ACK → 未超时即重传丢失段 |

### 发送方（简化）

| 事件 | 动作 |
|------|------|
| 从应用层收到数据 | 创建段（seq=NextSeqNum），若定时器未运行则启动 |
| 超时 | 重传**最老未确认**段，重启定时器 |
| 收到 ACK(y) | 更新 SendBase；若仍有未确认段则重启定时器，否则停止 |

**定时器**：与**最早未确认**报文段关联；TimeoutInterval 见下文。

### 接收方 ACK 生成 [RFC 5681]

| 事件 | 动作 |
|------|------|
| 期望序号段按序到达，无待发 ACK | **延迟 ACK**（最多等 500ms） |
| 期望序号到达，已有待发 ACK | 立即发**单个累积 ACK** |
| 乱序段到达（gap） | 立即发**重复 ACK**（指明期待下一字节） |
| 段填充 gap 低端 | 立即发 ACK |

### 重传场景

```
丢失 ACK:  发 Seq=92 → 超时 → 重传 Seq=92（过早超时，效率低但正确）
快速重传:  发 Seq=100 丢失 → 收 3 个 ACK=100 重复 → 立即重发 Seq=100
累积确认:  ACK=120 覆盖之前 ACK=100
```

## 超时计算

**SampleRTT**：从段发出到确认返回的时间；**忽略重传**段的测量。

**EstimatedRTT**（指数加权移动平均 EWMA）：
\[
\text{EstimatedRTT} = (1-\alpha) \times \text{EstimatedRTT} + \alpha \times \text{SampleRTT}
\]
典型值：**α = 0.125**

**DevRTT**（SampleRTT 偏离程度的 EWMA）：
\[
\text{DevRTT} = (1-\beta) \times \text{DevRTT} + \beta \times |\text{SampleRTT} - \text{EstimatedRTT}|
\]
典型值：**β = 0.25**

**超时间隔**：
\[
\text{TimeoutInterval} = \text{EstimatedRTT} + 4 \times \text{DevRTT}
\]

| 设置 | 后果 |
|------|------|
| 太短 | 过早超时，不必要重传 |
| 太长 | 丢失恢复反应慢 |

## 快速重传

收到对某段的 **3 个冗余 ACK** 表示：该段很可能丢失，但其后的段已被收到 → **立即重传**最小序号段，无需等待超时。

```
Host A 发: ... Seq=100(丢) ... Seq=120 ... Seq=140 ...
Host B 回: ACK=100, ACK=100, ACK=100, ACK=100  → 触发快速重传 Seq=100
```

## TCP 流量控制

**问题**：网络层提交速率 > 应用从 socket 缓冲区读取速率 → 缓冲区溢出。

**解决**：接收方用 TCP 头部 **rwnd** 字段通告**可用缓冲空间**；发送方限制 in-flight 数据：
\[
\text{LastByteSent} - \text{LastByteAcked} \leq \text{rwnd}
\]

| 要素 | 说明 |
|------|------|
| **RcvBuffer** | 接收缓冲区；典型 4096 字节；许多 OS 自动调整 |
| **rwnd** | RcvBuffer 中**空闲**空间大小 |
| **发送方约束** | in-flight 字节数 ≤ rwnd，防溢出 |

**有效发送窗口**（与拥塞控制联合）：
\[
\text{SendWindow} = \min\{\text{cwnd},\ \text{RcvWin}\}
\]

> [!warning]
> 拥塞控制实验/分析时，常将 RcvWin 设很大，使**拥塞控制**而非流量控制成为瓶颈。

## 考试/测试常见模式
| 场景/关键词 | 答案 |
|-------------|------|
| "TimeoutInterval 公式" | **EstimatedRTT + 4×DevRTT** |
| "EstimatedRTT 更新" | EWMA，**α=0.125** |
| "DevRTT 更新" | EWMA，**β=0.25** |
| "快速重传触发" | **3 个重复 ACK** |
| "rwnd 含义" | 接收方**可用缓冲区**字节数 |
| "延迟 ACK 等待时间" | 最多 **500ms** |
| "SendWindow" | **min(cwnd, RcvWin)** |
