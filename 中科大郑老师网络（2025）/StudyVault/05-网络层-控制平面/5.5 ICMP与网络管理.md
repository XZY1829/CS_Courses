# ICMP 与网络管理（重要性: ★★★）

#networking #network-layer #icmp #snmp #concept

## 概览表（一目了然）
| 条目 | 要点 |
|------|------|
| ICMP | 网络层**控制信息**：错误报告 + 诊断 |
| Traceroute | 递增 TTL + ICMP **超时/端口不可达** |
| SNMP | 传统网络管理：MIB + request/trap |
| NETCONF/YANG | 现代配置管理：XML RPC + 数据建模 |
| 管理架构 | 管理服务器 ↔ agent ↔ 被管设备 |

## ICMP（Internet Control Message Protocol）

| 要点 | 说明 |
|------|------|
| 用途 | 主机和路由器传送**网络层控制信息** |
| 封装 | 在 **IP 数据报**中携带（IP 之上） |
| 格式 | **类型 Type** + **代码 Code** + 触发错误的 IP 头前 8 字节 |

### 常见 ICMP 报文类型

| Type | Code | 描述 |
|------|------|------|
| 0 | 0 | **echo reply**（ping 响应） |
| 3 | 0 | 目的**网络**不可达 |
| 3 | 1 | 目的**主机**不可达 |
| 3 | 2 | 目的**协议**不可达 |
| 3 | 3 | 目的**端口**不可达 |
| 8 | 0 | **echo request**（ping 请求） |
| 11 | 0 | **TTL expired**（超时） |
| 12 | 0 | bad IP header |

## Traceroute 原理

```
源主机                         路由器 R1    R2    …    目标
  │── UDP(TTL=1) ──────────────→│ 丢弃，ICMP 11,0
  │←─ ICMP 超时（含 R1 地址）───│
  │── UDP(TTL=2) ─────────────────────→│ 丢弃，ICMP 11,0
  │←─ ICMP 超时（含 R2 地址）───────────│
  … 每轮 3 个探测包，记录 RTT …
  │── UDP(TTL=n) ─────────────────────────────────→│
  │←─ ICMP 3,3 端口不可达 ───────────────────────────│
  └─ 停止（到达目标）
```

| 步骤 | 行为 |
|------|------|
| 发送 | 一系列 UDP 段，第 n 个 **TTL=n** |
| 中间路由器 | TTL 减为 0 → 丢弃 → 发 **Type 11 Code 0**（含路由器名/IP） |
| 停止条件 | 目标回 **Type 3 Code 3**（端口不可达） |
| 测量 | 记录每跳 **RTT** |

> [!warning]
> Traceroute 使用**高端口** UDP，目标主机通常无应用监听 → 必然端口不可达，以此判断到达终点。

## 网络管理概述

**定义**（课件）：设置、综合和协调软硬件及人力，以合理成本监测、测试、配置和控制网络资源。

### 管理架构

```
管理服务器/控制器
    ↕ 网络管理协议
被管设备 ← agent（代理）→ data（状态/配置/统计）
```

| 元件 | 说明 |
|------|------|
| 管理服务器 | 应用程序 + 管理者（人） |
| 被管设备 | 具备可管理、可配置组件的设备 |
| agent | 驻留在被管设备上的代理 |
| data | 设备状态、配置参数、运行统计 |

### 三种管理方式

| 方式 | 说明 |
|------|------|
| **CLI** | SSH 等直接向单设备发命令 |
| **SNMP/MIB** | 查询/设置 MIB 库数据 |
| **NETCONF/YANG** | 更抽象、网络范围、多设备配置 |

## SNMP 协议

| 要点 | 说明 |
|------|------|
| 模式 1 | **request/response**：管理者向 agent 查询/设置 |
| 模式 2 | **trap**：agent 主动通知管理者异常事件 |

### SNMP 报文类型

| 报文 | 方向 | 功能 |
|------|------|------|
| GetRequest | M→A | 获取数据实例 |
| GetNextRequest | M→A | 获取列表中下一项 |
| GetBulkRequest | M→A | 获取数据块 |
| SetRequest | M→A | 设置 MIB 值 |
| Response | A→M | 响应 Request |
| Trap | A→M | 报告异常事件 |

### MIB（Management Information Base）

- 被管设备运行/配置数据存于 **MIB 模块**
- 400+ RFC 定义 MIB；含供应商专有 MIB
- **SMI**：数据定义语言

示例（UDP MIB）：

| OID | 名称 | 类型 |
|-----|------|------|
| 1.3.6.1.2.1.7.1 | UDPInDatagrams | 32-bit counter |
| 1.3.6.1.2.1.7.2 | UDPNoPorts | 32-bit counter |

## NETCONF 与 YANG

### NETCONF

| 要点 | 说明 |
|------|------|
| 目标 | **主动**管理和配置网络范围设备 |
| 编码 | 报文编码为 **XML** |
| 传输 | **TLS** 等安全可靠传输 |
| 范式 | 远程过程调用 (RPC) |

**会话流程**：

```
<hello> 能力交换 → <rpc>/<rpc-reply> 交互 → <notification> → <close-session>
```

| 操作 | 描述 |
|------|------|
| `<get-config>` | 检索配置 |
| `<get>` | 检索配置+运行状态 |
| `<edit-config>` | 修改配置（含回滚） |
| `<lock>/<unlock>` | 锁定配置存储 |
| `<create-subscription>` | 订阅事件通知 |

### YANG

| 要点 | 说明 |
|------|------|
| 角色 | **数据建模语言**，规范 NETCONF 数据结构 |
| 功能 | 定义语法、语义、约束；生成 XML 文档 |
| 与 SMI 关系 | 类似 SMI，但更现代、面向 NETCONF |

```
YANG 模型 → 生成 XML → 封装在 <edit-config> NETCONF RPC 中
```

> [!warning]
> SNMP 适合**查询/监控**；NETCONF/YANG 更适合**多设备配置管理**和原子操作。

## 考试/测试常见模式
| 场景/关键词 | 答案 |
|-------------|------|
| "ping 使用" | **ICMP Type 8/0**（echo request/reply） |
| "traceroute 中间跳" | **ICMP Type 11 Code 0**（TTL expired） |
| "traceroute 终点" | **ICMP Type 3 Code 3**（端口不可达） |
| "SNMP 主动上报" | **Trap** 报文 |
| "NETCONF 编码" | **XML**，传输 **TLS** |
| "数据建模" | **YANG** |
