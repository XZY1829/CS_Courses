# 域间路由：BGP（重要性: ★★★）

#networking #network-layer #bgp #distance-vector #concept

## 概览表（一目了然）
| 条目 | 要点 |
|------|------|
| BGP 角色 | AS 间路由**事实标准**，"把互联网粘在一起的胶水" |
| 类型 | **eBGP**（AS 间）+ **iBGP**（AS 内传播） |
| 本质 | **路径矢量**（非简单 DV），携带 AS 序列 |
| 关键属性 | **AS-PATH**、**NEXT-HOP** |
| 选择策略 | 局部偏好 → 最短 AS 路径 → **热土豆** → 附加标准 |
| 商业策略 | 客户/提供商/对等，控制通告与过境流量 |

## BGP 的作用

```
AS3 网关 3a ──eBGP──→ AS2 网关 2c
  通告: "AS3 可达子网 X，NEXT-HOP = 3a"
```

| 功能 | 说明 |
|------|------|
| 可达性通告 | AS 通告其拥有的网络及可达的其他 AS 目标 |
| eBGP | 邻居 AS 间交换子网可达信息 |
| iBGP | 向 AS **内部**路由器传播从外部获知的可达信息 |
| 路径选择 | 基于策略和可达信息选择"好的"路径 |

**与简单 DV 的区别**：携带到达各目标的**详细 AS 路径序列**，可**避免 DV 路由环路**。

## eBGP vs iBGP

```
AS1 ←──eBGP──→ AS2 ←──eBGP──→ AS3
  ↑                              ↑
  └──── iBGP（逻辑全连接）────────┘
        网关同时运行 eBGP + iBGP
```

| 类型 | 范围 | 说明 |
|------|------|------|
| **eBGP** | AS **之间** | 对等体通过半永久 **TCP** 连接交换 BGP 报文 |
| **iBGP** | AS **内部** | 网关将从外部学到的路径通告给本 AS 所有内部路由器 |

## BGP 报文类型

| 报文 | 功能 |
|------|------|
| **OPEN** | 打开 TCP 连接，身份认证 |
| **UPDATE** | 通告**新路径**或**收回**旧路径 |
| **KEEPALIVE** | 无 UPDATE 时保活；确认 OPEN |
| **NOTIFICATION** | 报告错误；关闭连接 |

## 路径属性

BGP 通告 = **prefix** + **attributes**

| 属性 | 说明 |
|------|------|
| **AS-PATH** | 通告经过的 **AS 列表**（路径序列） |
| **NEXT-HOP** | 到下一跳 AS 的**特定内部路由器** IP |
| 其他 | 路由偏好指标、插入方式等 |

### 路径再通告示例

```
3a ──eBGP──→ 2c:  AS3, X
2c ──iBGP──→ 2a,2b,2d:  AS2, AS3, X   （加上 AS2）
2a ──eBGP──→ 1c:  AS2, AS3, X
1c 还从 3a 直接学到: AS3, X
→ 1c 基于策略选择 AS3,X（更短 AS 路径）
```

## 转发表项如何设置

**AS 内 + AS 间路由共同决定**：

```
1d 通过 iBGP 学到: "经 1c 可达 X (AS3,X)"
1d 通过 OSPF 学到: 到达 1c 走 interface 1
→ 1d 到 X 的转发表: dest=X, interface=1
```

IP 目标地址不变；MAC/接口由 IGP 决定如何到达 NEXT-HOP 网关。

## 热土豆路由（Hot Potato Routing）

```
2d 通过 iBGP 学到: 经 2a 或 2c 均可达 X
热土豆: 选 AS 内 OSPF 代价最低的本地网关（如 2a）
       不考虑 AS 间路径长短！
```

| 策略 | 关注点 |
|------|--------|
| 热土豆 | **AS 内**代价最小，尽快把分组"扔"出本 AS |
| 冷土豆 | 考虑端到端 AS 路径（课件未详述） |

## 路由策略：客户/提供商/对等

```
legend:  provider(A,B,C)  customer(x,w,y)

A 通告 Aw 给 B、C
B 不向 C 通告 BAw → C 看不到经 B 到 w 的路径
→ 不同 ISP 看到的互联网视图不同
```

| 关系 | 策略要点 |
|------|----------|
| **客户** | ISP **希望**承载客户流量（有收入） |
| **提供商** | 客户向提供商付费接入 |
| **对等 peer** | 通常**不**帮对方承载过境流量 |
| 双接入 | 客户 x 接入 A、B，可控制不向某方通告特定路径 |
| 过境流量 | ISP **不希望**免费承载其他 ISP 的过境流量 |

**输入策略**：决定收到的路由通告是否**接收/丢弃**（如：不想经过某 AS、已有更优路径）。

## BGP 路由选择顺序

1. **局部偏好值**（策略函数对 AS 序列打分）
2. **最短 AS 路径**
3. **最近的 NEXT-HOP**（热土豆）
4. 附加评判标准

## AS 内 vs AS 间路由为何不同

| 维度 | AS 内（OSPF） | AS 间（BGP） |
|------|---------------|--------------|
| 目标 | **性能**优先 | **策略**远重要于性能 |
| 资源 | 同一管理者 | 资源属不同 AS，需控制谁可路由 |
| 规模 | AS 内可控；太大可再分 AS | 每增 AS 仅增一个"节点" |

> [!warning]
> BGP 基于**策略**的路由意味着：全球 Internet 路由**不一定**是最短路径；商业关系决定可达性视图。
