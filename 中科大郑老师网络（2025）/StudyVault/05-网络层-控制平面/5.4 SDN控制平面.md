# SDN 控制平面（重要性: ★★★）

#networking #network-layer #sdn #concept

## 概览表（一目了然）
| 条目 | 要点 |
|------|------|
| 传统方式 | **每路由器控制**：各路由器独立运行路由算法 |
| SDN 方式 | **逻辑集中控制**：远程控制器计算并安装转发表 |
| 三层架构 | 数据平面 / 控制平面 / **管理平面（应用）** |
| 南向 API | **OpenFlow**（控制器↔交换机） |
| 控制器 | **ODL**（OpenDaylight）、**ONOS** |
| 核心优势 | 可编程、流量工程、开放创新 |

## 两种控制平面构建方法

```
传统（每路由器）:                    SDN（集中控制）:
  ┌─Routing Alg─┐                      Remote Controller
  │ control     │                           │
  │ data plane  │                      CA CA CA CA CA
  └─────────────┘                      data plane (交换机)
  各路由器独立交互                      控制器安装流表
```

| 方式 | 特点 |
|------|------|
| 每路由器控制 | 路由算法元件运行在**每个路由器**，控制平面交互 |
| SDN | 远程控制器计算，在交换设备**安装转发表** |

## SDN 三层架构

```
┌─────────────────────────────────────┐
│  网络控制应用（routing, firewall,    │  ← 管理/北向
│  load balance, …）                   │
├─────────────────────────────────────┤
│  SDN Controller（网络操作系统）      │  ← 控制平面
│  维护网络状态、南北向 API            │
├─────────────────────────────────────┤
│  SDN-controlled switches            │  ← 数据平面
│  通用"基于流"的转发（OpenFlow）      │
└─────────────────────────────────────┘
     southbound API ↑        ↑ northbound API
```

| 平面 | 组件 | 职责 |
|------|------|------|
| **数据平面** | 商用交换机硬件 | 快速、简单；按**流表**转发 |
| **控制平面** | SDN 控制器 | 维护网络状态；与上下层交互 |
| **管理平面** | 网络控制应用 | 路由、接入控制、负载均衡等"大脑" |

## 为什么需要集中控制

| 动机 | 说明 |
|------|------|
| 简化管理 | 避免逐路由器错误配置 |
| 可编程转发 | 基于表的转发（OpenFlow API） |
| 流量工程 | 传统 LS/DV 仅能通过**链路权重**控制路径 |
| 开放创新 | 控制平面开放实现，非专有 |

**传统路由的局限**（课件 u-z 拓扑）：
- 希望 u-z 流量走 u-v-w-z 而非 u-x-y-z → 只能**重新定义链路权重**
- 希望 u-z 流量**负载均衡**两条路径 → **无法做到**
- 希望区分同色/异色流量 → **无法做到**（基于目标的 LS/DV）

> SDN 通用化转发可实现任意所需路由（见第 4 章）。

## OpenFlow 协议

| 要点 | 说明 |
|------|------|
| 作用 | 控制器与交换机之间**互操作** |
| 传输 | **TCP**；加密可选 |
| 与 OpenFlow API 区别 | API 定义通用转发行为；协议是报文交换 |

### 控制器→交换机报文

| 报文 | 功能 |
|------|------|
| **Features** | 查询交换机特性 |
| **Configuration** | 查询/设置配置参数 |
| **Modify-State** | 增删改**流表**表项 |
| **Packet-Out** | 经指定端口发送分组 |

### 交换机→控制器报文

| 报文 | 功能 |
|------|------|
| **Packet-In** | 将分组发给控制器 |
| **Flow-Removed** | 流表项被删除 |
| **Port-Status** | 端口状态变化（如链路失效） |

## SDN 控制/数据平面交互实例

```
1. s1 链路失效 → OpenFlow Port-Status 通告控制器
2. 控制器更新链路状态信息
3. 注册的 Dijkstra 路由应用被触发
4. 应用访问拓扑信息，计算新路由
5. 流表计算元件生成新流表
6. 控制器通过 OpenFlow 安装新流表到各交换机
```

## SDN 控制器

### OpenDaylight (ODL)

| 组件 | 说明 |
|------|------|
| 服务抽象层 (SAL) | 连接内外部应用和服务 |
| 南向协议 | OpenFlow、NETCONF、SNMP、OVSDB |
| 北向 API | REST / RESTCONF / NETCONF |
| 应用 | 流量工程、防火墙、负载均衡等 |

### ONOS

| 特点 | 说明 |
|------|------|
| 控制应用分离 | 与 ODL 类似 |
| **Intent 框架** | 描述**做什么**而非如何做 |
| **分布式核心** | 可靠性、复制、可扩展性 |

## SDN 优势与挑战

**优势**：
- 集中可编程流量工程
- 快速创新（开放接口，类比 PC 革命 vs 大型机）
- 5G 网络中非常关键

**挑战**：
- 可信、可靠、可扩展的分布式控制器
- 全网（不仅单 AS）部署
- 安全与容错

> [!warning]
> 运营商通常**不直接**编写 OpenFlow 报文，而是使用控制器上的**高级抽象**（Intent、REST API）。
