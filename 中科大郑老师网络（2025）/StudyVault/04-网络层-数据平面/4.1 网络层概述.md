# 网络层概述（重要性: ★★★）

#networking #network-layer #concept

## 概览表（一目了然）
| 条目 | 要点 |
|------|------|
| 网络层功能 | 端到端传送段；主机与路由器均实现 |
| 转发 vs 路由 | **转发**=单路由器局部动作；**路由**=全网路径规划 |
| 数据平面 | 每个路由器：输入端口 → 输出端口 |
| 控制平面 | 计算转发表/路由表（传统 per-router 或 SDN 远程控制器） |
| 服务模型 | Internet **尽力而为**（best effort） |

## 网络层功能

网络层在发送主机与接收主机之间传送**段**：

- **发送端**：将段封装到**数据报**，交给链路层
- **接收端**：将段上交给传输层
- **路由器**：检查 IP 数据报头部，从输入端口转发到输出端口，逐跳传输

网络层协议存在于**每一个互联网设备**（主机 + 路由器）。

## 转发 vs 路由

| 功能 | 范围 | 类比 | 说明 |
|------|------|------|------|
| **转发 (forwarding)** | **局部**，单个路由器 | 通过单个立交 | 决定到达分组从哪个输出端口发出 |
| **路由 (routing)** | **网络范围** | 规划旅行路线 | 路由算法/协议确定端到端路径 |

```
routing (控制平面) → 生成转发表
forwarding (数据平面) → 查表转发每个分组
```

## 数据平面 vs 控制平面

| 平面 | 功能 | 时间尺度 | 实现 |
|------|------|----------|------|
| **数据平面** | 局部转发：输入 → 输出 | **纳秒级**（硬件） | 查转发表，线速处理 |
| **控制平面** | 决定端到端路径 | **微秒~秒级**（软件） | 路由算法或 SDN 控制器 |

### 两种控制平面方法

| 方式 | 说明 |
|------|------|
| **传统 per-router** | 每个路由器独立运行路由算法，路由器间交互 |
| **SDN** | 远程控制器计算转发表，下发到交换设备 |

## 网络服务模型

Internet 采用 **best effort（尽力而为）** 服务模型——对以下指标**均不提供保障**：

| 指标 | Internet best effort |
|------|---------------------|
| **交付** | 不保证成功到达 |
| **延迟** | 无保证 |
| **顺序** | 不保证保序 |
| **带宽** | 无保证 |

### 与其他体系结构对比

| 体系 | 服务模型 | 带宽 | 丢失 | 次序 | 延迟 |
|------|----------|------|------|------|------|
| **Internet** | best effort | none | no | no | no |
| **ATM CBR** | Constant Bit Rate | 恒定 | yes | yes | yes |
| **Intserv** | Guaranteed | yes | yes | yes | yes |
| **Diffserv** | 差异化 | possible | possibly | possibly | no |

### 尽力而为为何成功

- 简单机制使 Internet 广泛部署、包容异构网络
- 带宽充足时实时应用"足够好"
- CDN/数据中心副本使服务靠近用户
- 端系统**弹性拥塞控制**（TCP）帮助网络正常运行

> [!warning]
> "尽力而为"不等于"不工作"——在带宽充足时多数应用性能可接受；滥用会导致拥塞，依赖端系统降速。

## 考试/测试常见模式
| 场景/关键词 | 答案 |
|-------------|------|
| "转发 vs 路由" | 转发=**局部**单跳；路由=**全网**路径规划 |
| "数据平面 vs 控制平面" | 数据平面=转发（纳秒）；控制平面=路由计算 |
| "Internet 服务模型" | **best effort**，四项均无保证 |
| "SDN 控制平面" | **远程控制器**计算转发表 |
| "传统控制平面" | 每路由器**独立**运行路由算法 |
