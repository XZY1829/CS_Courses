# 通用转发与 SDN（重要性: ★★★）

#networking #network-layer #sdn #router #concept

## 概览表（一目了然）
| 条目 | 要点 |
|------|------|
| 通用转发 | **匹配+行动**：匹配头部字段 → 执行动作 |
| vs 传统转发 | 传统仅基于**目的 IP**；通用可匹配任意字段 |
| OpenFlow | 流表表项：Match + Action + Stats |
| SDN | 远程控制器计算流表，下发到交换设备 |
| 中间盒 | 路径上执行非标准路由功能的设备 |

## 通用转发：匹配+行动

**回顾**：每个路由器含转发表 → "匹配+行动"抽象。

| 类型 | 匹配 | 行动 |
|------|------|------|
| **基于目标的转发** | **目的 IP 地址**（最长前缀） | 通过对应端口转发 |
| **通用转发** | 链路/网络/传输层**任意头部字段** | 丢弃/转发/修改/送控制器 |

### 流表抽象

**流 (flow)**：由头部字段值定义的数据包集合。

| 要素 | 说明 |
|------|------|
| **匹配** | 头部字段值的模式（支持通配符 *） |
| **行动** | 丢弃、转发、修改字段、送控制器 |
| **优先级** | 消除重叠匹配歧义 |
| **计数器** | 字节数、包数 |

**流表示例**：

| 匹配 | 行动 |
|------|------|
| src=10.1.2.3, dest=*.*.*.* | send to controller |
| src=1.2.*.*, dest=*.*.*.* | **drop** |
| src=*.*.*.*, dest=3.4.*.* | forward(2) |

## OpenFlow 协议

OpenFlow 定义**流表表项**结构：

| 部分 | 内容 |
|------|------|
| **Match** | 入端口、MAC、Eth 类型、VLAN、IP ToS、IP 协议、IP 源/目的、TCP/UDP 端口等 |
| **Action** | ① 转发到端口 ② 丢弃 ③ 修改头部 ④ 封装送控制器 |
| **Stats** | 包/字节计数 |

### OpenFlow 例子

| 场景 | 匹配 | 行动 |
|------|------|------|
| 基于目标转发 | dest IP = 51.6.0.8 | forward port 6 |
| 防火墙 | TCP d-port = 22 | **drop** |
| 防火墙 | src IP = 128.119.1.1 | **drop** |
| L2 转发 | dst MAC = 22:A7:23:11:E1:02 | forward port 3 |

### OpenFlow 抽象统一设备

| 设备 | 匹配 | 行动 |
|------|------|------|
| **路由器** | 目的 IP 最长前缀 | 转发到链路端口 |
| **交换机** | 目的 MAC | 转发或泛洪 |
| **防火墙** | IP + 端口 | 允许/拒绝 |
| **NAT** | IP + 端口 | 写入新 IP/端口 |

## SDN 数据平面

**Software-Defined Networking**：

```
传统:  每路由器独立运行路由算法（per-router 控制平面）
SDN:   远程 Controller 计算流表 → 下发到交换设备
```

```
        Remote Controller
       /    |    |    \
   Switch Switch Switch Switch
   (数据平面: 匹配+行动执行)
```

- 控制器**编排**网络范围行为（如 h5/h6 → h3/h4 的流量路径）
- 数据平面在交换设备上以**线速**执行流表

**可编程扩展**：P4 语言（p4.org）实现更通用的每分组处理。

## 中间盒

**定义**（RFC 3234）：源到目标路径上，执行 IP 路由器**标准功能之外**的任何设备。

| 类型 | 例子 |
|------|------|
| **NAT** | 家庭、蜂窝、机构网络 |
| **Firewall/IDS** | 公司、机构、服务提供商 |
| **Load Balancer** | 机构、数据中心、移动网络 |
| **Cache/CDN** | 服务提供商、移动网络 |

### 演化趋势

| 阶段 | 特点 |
|------|------|
| 早期 | 专有封闭硬件 |
| 现在 | **白盒**硬件 + 开放 API |
| SDN | 逻辑集中控制与配置 |
| NFV | 基于白盒的可编程网络功能虚拟化 |

### 与 Internet 架构原则

**IP 沙漏模型**：IP 为瘦腰，必须在数十亿设备上实现。

**端到端原则**（RFC 1958）：目标是**连接性**，手段是 IP，**智能在边缘**而非网络中间。

| 原则 | 含义 |
|------|------|
| 连接简单性 | IP 瘦腰 |
| 智能在边缘 | 可靠传输、拥塞控制在端系统（TCP） |

> [!warning]
> 中间盒（NAT、防火墙、缓存）在网内操作，与"智能在边缘"原则存在张力，但已成为 Internet 现实。

## 考试/测试常见模式
| 场景/关键词 | 答案 |
|-------------|------|
| "通用转发 vs 传统" | 传统=仅**目的IP**；通用=**任意字段**+多种动作 |
| "OpenFlow 三要素" | **Match + Action + Stats** |
| "SDN 控制平面" | **远程控制器**计算并下发流表 |
| "中间盒定义" | 路径上执行**非标准路由功能**的设备 |
| "端到端原则" | 功能（可靠传输、拥塞控制）在**边缘**实现 |
| "流表优先级" | 多表项匹配时用**优先级最高**的 |
