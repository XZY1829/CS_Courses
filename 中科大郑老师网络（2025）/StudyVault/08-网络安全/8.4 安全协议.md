# 安全协议（重要性: ★★★）

#networking #security #tls #ipsec #encryption #authentication #concept

## 概览表（一目了然）
| 条目 | 要点 |
|------|------|
| 安全邮件 | 对称加密数据 + 公钥加密 K_S；签名 H(m) |
| TLS | 握手认证 + 密钥派生 + 记录传输 + 安全关闭 |
| IPSec | **AH**（完整性）/ **ESP**（+机密性）；传输/隧道模式 |
| SA | 单向安全关联；**IKE** 自动建立 |
| TLS 1.3 | **DH** 密钥交换，1-RTT 握手 |

## 安全电子邮件 (PGP 思想)

### 机密性

```
Alice: 随机 K_S → K_S(m)；K_B^+(K_S) → 发送 K_S(m) + K_B^+(K_S)
Bob:   K_B^-(K_B^+(K_S)) → K_S → K_S(m) → m
```

### 完整性与认证

```
Alice: 发送 m + K_A^-(H(m))
Bob:   H(m) ?= K_A^+(K_A^-(H(m)))
```

### 三者兼备

Alice 用 3 个 key：**自己私钥**（签名）、**Bob 公钥**（加密 K_S）、**新对称 K_S**（加密 m）。

## TLS 协议

| 能力 | 机制 |
|------|------|
| 机密性 | 对称加密 |
| 完整性 | 加密 MAC（HMAC，nonce 参与） |
| 认证 | 公钥体系 + 证书 |
| 部署 | HTTPS(443)、QUIC 协作 |

历史：SSL 3.0 → TLS 1.0(1999) → TLS 1.2(2008) → **TLS 1.3(2018)**

### TLS 四阶段（t-tls 玩具版）

```
┌──────────┐    ┌──────────┐    ┌──────────┐    ┌──────────┐
│ TLS握手  │ → │ 密钥导出  │ → │ 数据传输  │ → │ 连接关闭  │
└──────────┘    └──────────┘    └──────────┘    └──────────┘
```

### 1. 握手（t-tls）

```
Client                          Server
  │── TCP SYN/SYNACK/ACK ────────→│
  │── t-tls hello ───────────────→│
  │←─ 公钥证书 ───────────────────│  Alice 用 CA 公钥验证 Bob 身份
  │── K_B^+(MS) ─────────────────→│  主密钥 MS 用 Bob 公钥加密
```

- 问题：含 TCP 建立约 **3 RTT**

### 2. 密钥派生 (KDF)

从主密钥 MS 导出 4 个 key（+ IV）：

| Key | 用途 |
|-----|------|
| **Kc** | Client → Server 加密 |
| **Mc** | Client → Server MAC |
| **Ks** | Server → Client 加密 |
| **Ms** | Server → Client MAC |

KDF 输入：**MS + IV/nonce**（破除 MS 与 key 固定对应）。

### 3. 数据传输

- 字节流 → **记录(record)** 分割（非流式 MAC，否则无法逐段校验）
- 记录结构：`Kc( length || data || MAC )`
- **MAC = H(Mc, seq || type || data)** — 防重排、重放

| 攻击 | 防御 |
|------|------|
| 重排 | MAC 含 **sequence** |
| 重放 | 每握手不同 **nonce** → 不同 key |
| 截断 | 记录 **type**：0=数据，1=关闭；type=1 后才允许 TCP FIN |

### 4. 连接关闭

TLS 记录 type=1 表示关闭 → 之后才 TCP FIN，防截断攻击。

### 真实 TLS 1.2 握手（6 步 + MAC）

```
1. Client: 算法列表 + nonce1
2. Server: 选定算法 + 证书 + nonce2
3. Client: 验证证书；K_B^+(PMS) 发送 pre_master_secret
4. 双方: MS = f(PMS, nonce1, nonce2)；导出 4 keys
5. Client: 握手阶段 MAC（加密）
6. Server: 握手阶段 MAC（加密）— 防算法降级
```

**两个 nonce 原因**：若仅 Client nonce，Trudy 重放旧会话 → 相同 key → 重放攻击成功。

### TLS 1.3 变化

| 特性 | 说明 |
|------|------|
| 加密套件 | 仅 **5 个**（vs 1.2 的 37 个），防降级 |
| 密钥交换 | **Diffie-Hellman**（不仅 RSA） |
| 握手 | **1-RTT**（DH 参数在 ClientHello/ServerHello） |
| 0-RTT | 恢复会话 ticket 可立即发加密数据；**易受重放** |
| 算法 | AEAD（加密+认证合一）；HMAC-SHA256/384 |

### TLS 1.3 快速握手（1 RTT）示例

```
公开 p=97, g=5
Client: a=36 → A=5^36 mod 97=50
Server: b=58 → B=5^58 mod 97=44
共享 key = 44^36 mod 97 = 50^58 mod 97 = 75
```

## IPSec

位置：**IP 之上、传输层之下**；"地毯覆盖"所有 IP 载荷。

### 子协议

| 协议 | 提供 |
|------|------|
| **AH** | 源认证 + 完整性；**不提供机密性** |
| **ESP** | 源认证 + 完整性 + **机密性**（更常用） |

### 两种模式

| 模式 | 场景 | 保护范围 |
|------|------|----------|
| **传输模式** | 主机↔主机 | 仅**载荷**加密/认证，IP 头明文 |
| **隧道模式** | 路由器↔路由器 (VPN) | **整个原 IP 报文**封装在新 IP 中 |

### 安全关联 (SA)

- **一个方向一个 SA**；发送前须建立 SA
- IP 无连接；IPSec **面向连接**（维护状态）

SA 状态（SAD 中）：SPI、源/目的 IP、加密类型(如 3DES-CBC)、加密 key、完整性算法(如 HMAC-MD5)、MAC key

**VPN 示例**：总部+分支+n 个销售 → **2+2n 个 SA**

### ESP 隧道模式（R1 发送）

```
1. 原 IP 报文尾部加 ESP trailer（填充）
2. 加密（原 IP 头 + 载荷 + trailer）
3. 前插 ESP 头（SPI, Seq#）
4. 对 enchilada 计算 MAC，附 ESP auth
5. 新 IP 头（协议=50 ESP，源 R1，目的 R2）
```

- **Seq#**：防重放；新 SA 从 0 递增
- Trudy 无法：读内容（加密）、改 bits（MAC）、伪装 R1、重放（序号）

### SPD vs SAD

| 数据库 | 作用 |
|--------|------|
| **SPD** | **是否**用 IPSec；选哪个 SA |
| **SAD** | **如何**处理（具体算法和 key） |

### IKE（Internet Key Exchange）

手工配置 SA 对大规模 VPN 不现实 → **IKE 自动建立**。

```
阶段1: 建立 IKE SA（双向）
  - 协商加密/MAC 算法
  - 生成共享 IKE 密钥
  - 相互认证（PSK 或 PKI 证书）
  - 主模式（身份保护）/ 侵略模式（更快）

阶段2: 建立 2 个数据 SA（各单向）
  - 协商 ESP/AH 算法
  - 生成加密/MAC key
  - 周期性密钥更新
```

| 认证方式 | 说明 |
|----------|------|
| **PSK** | 预共享 secret + IKE |
| **PKI** | 公钥/证书 + IKE（类似 SSL 握手） |

## 考试/测试常见模式
| 场景/关键词 | 答案 |
|-------------|------|
| "TLS 四阶段" | 握手/密钥派生/传输/关闭 |
