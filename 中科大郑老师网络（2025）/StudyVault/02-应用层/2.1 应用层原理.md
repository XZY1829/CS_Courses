# 应用层原理（重要性: ★★★）

#networking #application-layer #socket #p2p #concept

## 概览表（一目了然）
| 条目 | 要点 |
|------|------|
| 应用架构 | **C/S**（固定服务器）vs **P2P**（对等体直接通信） |
| 进程通信 | IP + Port 标识端点；**Socket** 为层间 API |
| 传输需求 | 可靠性、吞吐量、延迟、安全性 |
| 协议选择 | 文件/Web/Email → **TCP**；实时/游戏 → **UDP** 或 TCP |

## 网络应用特点

- 软件运行在**端系统**，不在网络核心部署
- 允许快速应用部署和传播

## C/S 架构

| 角色 | 特点 |
|------|------|
| **服务器** | 始终运行；**固定 IP**；部署在数据中心 |
| **客户端** | 间歇连接；可能**动态 IP**；客户端间通常不直接通信 |
| 示例 | HTTP, IMAP, FTP |

## P2P 架构

| 特点 | 说明 |
|------|------|
| 无（或极少）始终运行的服务器 | 任意端系统直接通信 |
| **自扩展性** | 新 peer 带来新请求 + 新服务能力 |
| 间歇连接、IP 可变 | 管理复杂 |
| 示例 | P2P 文件共享（BitTorrent） |

> [!warning]
> P2P 架构的应用**也有**客户端进程和服务器进程之分——发起通信的是客户端进程，等待连接的是服务器进程。

## 进程通信与 Socket

进程 = 端系统中运行的程序。

| 概念 | 说明 |
|------|------|
| **端点标识** | (IP, Port) + (IP', Port') |
| **Socket** | 应用层与传输层的**接口/API**；类似"门" |
| TCP Socket | 整数代表 **(IP, Port, IP', Port')** 连接关系 |
| UDP Socket | 整数代表本地 **(IP, Port)**；每报文携带对方地址 |

```
应用层 ──Socket,M──→ 传输层
         ↑
    整数简化编址（像文件句柄）
```

## 传输层服务需求

| 需求 | 说明 | 典型应用 |
|------|------|----------|
| **可靠性** | 100% 可靠 vs 可容忍丢失 | 文件/Web 需可靠；音频可容忍丢失 |
| **延迟** | 低延迟 vs 不敏感 | 电话/游戏需 10's ms；Web 不敏感 |
| **吞吐量** | 最小带宽 vs 弹性 | 视频需 10K–5Mbps；Web 弹性 |
| **安全性** | 加密、完整性、认证 | TLS（应用层实现） |

## TCP vs UDP 选择

| | TCP | UDP |
|---|-----|-----|
| 可靠性 | **可靠**字节流 | **不可靠**数据报 |
| 连接 | 面向连接（握手） | 无连接 |
| 额外服务 | 流量控制、拥塞控制 | 无 |
| 不提供 | 延迟/吞吐量/安全保证 | 同上 |
| 典型应用 | HTTP, SMTP, FTP, Email | 互联网电话、交互游戏 |

| 应用 | 应用层协议 | 传输层 |
|------|-----------|--------|
| 文件传输 | FTP | TCP |
| Email | SMTP | TCP |
| Web | HTTP | TCP |
| 互联网电话 | SIP/RTP | TCP or UDP |
| 交互游戏 | 专有 | **UDP or TCP** |

**为何不用 IP 直接服务？** UDP 提供**进程到进程**（端口）复用，IP 仅主机到主机。

## 考试/测试常见模式
| 场景/关键词 | 答案 |
|-------------|------|
| "C/S vs P2P" | C/S=固定服务器；P2P=**自扩展**、无中心服务器 |
| "进程标识" | **IP + Port** |
| "Socket 作用" | 传输层 API，简化编址 |
| "TCP Socket 代表" | **(IP, Port, IP', Port')** 连接 |
| "UDP Socket 代表" | 本地 **(IP, Port)** |
| "Web 用什么传输协议" | **TCP** |
