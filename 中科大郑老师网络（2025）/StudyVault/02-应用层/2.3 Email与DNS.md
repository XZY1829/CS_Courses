# Email 与 DNS（重要性: ★★★）

#networking #application-layer #smtp #dns #concept

## 概览表（一目了然）
| 条目 | 要点 |
|------|------|
| Email 组件 | **MUA**（用户代理）+ **MTA**（邮件服务器/SMTP）+ **MAA**（IMAP/POP/HTTP） |
| SMTP | TCP 端口 **25**；推模式；持久连接 |
| DNS 功能 | 主机名→IP；别名；邮件服务器；负载均衡 |
| DNS 结构 | 根 → TLD → 权威；本地 DNS 服务器 |

---

## Email 架构

```
用户A ──MUA──→ [邮件服务器A] ──SMTP──→ [邮件服务器B] ──MAA──→ 用户B(MUA)
                  ↑ 发件队列              ↑ 收件箱
```

| 组件 | 别名 | 功能 |
|------|------|------|
| **用户代理** | MUA | 撰写/阅读邮件（Outlook、手机客户端） |
| **邮件服务器** | MTA | 存储邮箱和发件队列；SMTP 服务器间转发 |
| **邮件访问协议** | MAA | 从服务器读取邮件 |

### 发送流程（Alice → Bob）

1. Alice 用 MUA 撰写邮件
2. MUA 用 **SMTP** 发送到 Alice 的邮件服务器（放入队列）
3. Alice 的邮件服务器作为 SMTP 客户端，打开到 Bob 邮件服务器的 TCP 连接
4. 通过 SMTP 传输邮件
5. Bob 的邮件服务器放入 Bob 邮箱
6. Bob 用 MUA 通过**访问协议**读取

## SMTP 协议

| 特性 | 说明 |
|------|------|
| 传输 | **TCP** 端口 25，可靠传输 |
| 模式 | **推**（client 推送邮件到 server） |
| 连接 | **持久连接** |
| 报文结束 | **CRLF.CRLF** |
| 阶段 | 握手(HELO) → 传输(MAIL FROM/RCPT TO/DATA) → 关闭(QUIT) |

```
C: HELO crepes.fr
S: 250 Hello
C: MAIL FROM: <alice@crepes.fr>
S: 250 Sender ok
C: RCPT TO: <bob@hamburger.edu>
S: 250 Recipient ok
C: DATA
S: 354 Enter mail, end with "." on line by itself
C: ...message...
C: .
S: 250 Message accepted
```

### SMTP vs HTTP

| | SMTP | HTTP |
|---|------|------|
| 模式 | **推** | **拉** |
| 报文 | 多个邮件对象在一个邮件中 | 每个对象各自响应报文 |
| 格式 | ASCII 命令/响应 | ASCII 请求/响应 |

### 邮件报文格式

- **RFC 2822** 定义邮件语法（To/From/Subject 头部 + 正文）
- 头部行 ≠ SMTP 命令（MAIL FROM / RCPT TO 是 SMTP 命令）

## 邮件访问协议

| 协议 | 特点 |
|------|------|
| **IMAP** | 邮件**存储在服务器**；支持读取/删除/目录管理 |
| **POP3** | 下载到本地（课件提及） |
| **HTTP** | Web 邮件（Gmail 等）：SMTP 发 + IMAP/HTTP 收 |

## DNS（Domain Name System）

### 为什么需要 DNS？

- IP 地址不便记忆；人类使用**有意义的字符串**
- DNS 负责 **字符串 → IP 地址** 转换

### DNS 服务

| 服务 | 说明 |
|------|------|
| **主机名→IP** | 核心功能 |
| **主机别名** | CNAME 记录 |
| **邮件服务器别名** | MX 记录 |
| **负载均衡** | 一个名字对应多个 IP |

- 运行在 **UDP 端口 53** 的应用层协议
- 分布式数据库，在网络**边缘**处理复杂性

### 层次结构

```
                    [根 DNS 服务器]  (13 个 IPv4 逻辑根)
                           │
              ┌────────────┼────────────┐
           [.com TLD]  [.edu TLD]   [.cn TLD]
              │            │
        [权威 DNS]    [权威 DNS]
        yahoo.com     umass.edu
```

| 服务器类型 | 职责 |
|-----------|------|
| **根服务器** | 指向 TLD 服务器 |
| **TLD 服务器** | 负责 .com/.edu/.cn 等顶级域 |
| **权威 DNS** | 组织机构的 DNS，提供域名-IP 映射 |
| **本地 DNS** | ISP/公司/大学的默认 DNS，**代理**转发查询 |

### 资源记录（RR）

格式：`(name, value, type, TTL)`

| Type | Name | Value |
|------|------|-------|
| **A** | 主机名 | **IP 地址** |
| **NS** | 域 | 该域**权威名字服务器**主机名 |
| **CNAME** | 别名 | **规范名字** |
| **MX** | 域 | **邮件服务器**名字 |

### 查询方式

| 类型 | 行为 | 负担 |
|------|------|------|
| **迭代查询** | 被查询服务器返回**下一级服务器地址** | 查询主机承担 |
| **递归查询** | 被查询服务器**代为完成**全部查询 | 上层服务器负担重 |

```
迭代: Local DNS → Root → "问 TLD" → TLD → "问权威" → 权威 → IP
递归: Local DNS → Root（Root 代为查询到底）
```

> [!warning]
> 实际中，本地 DNS 到上层通常用**递归**，层间用**迭代**。

### DNS 缓存

- 名字服务器获得映射后**缓存**，TTL 到期后删除
- TLD 服务器通常被本地 DNS 缓存（无需每次问根）
- 缓存可能**过期**：主机换 IP 后，在 TTL 到期前可能解析到旧地址

### 新增域的步骤

1. 向注册机构注册域名
2. 在 TLD 服务器插入 NS 和 A 记录
3. 在权威 DNS 上运行名字服务器，添加 A/MX 等记录

## 考试/测试常见模式
| 场景/关键词 | 答案 |
|-------------|------|
| "SMTP 端口" | **25**，TCP |
| "SMTP vs HTTP 推拉" | SMTP=**推**；HTTP=**拉** |
| "DNS 端口" | **UDP 53** |
| "RR 类型" | A=IP, NS=权威服务器, CNAME=别名, MX=邮件 |
| "迭代 vs 递归" | 迭代=返回下一跳；递归=**代为查询** |
| "IMAP 特点" | 邮件**存服务器**，支持目录管理 |
