# HTTP 协议（重要性: ★★★）

#networking #application-layer #http #concept

## 概览表（一目了然）
| 条目 | 要点 |
|------|------|
| 模式 | C/S；基于 **TCP**（默认端口 80） |
| 状态 | **无状态**（stateless） |
| 连接 | 非持久（每对象一新连接）vs 持久（HTTP/1.1） |
| 演进 | HTTP/1.1 → HTTP/2（多路复用）→ HTTP/3（QUIC/UDP） |

## HTTP 概述

- **HTTP**：HyperText Transfer Protocol，Web 的应用层协议
- **Client**：浏览器请求/接收/显示对象
- **Server**：Web 服务器（如 Apache）响应请求
- Web 页 = **base HTML** + 若干被引用对象（JPEG、音频等）
- URL 格式：`http://host:port/path`（如 `www.school.edu/dept/pic.gif`）

## 连接类型

### 非持久 HTTP（HTTP/1.0）

```
每个对象: 建立TCP → 请求/响应 → 关闭TCP
含10个JPEG的页面 = 1(HTML) + 10(JPEG) = 11次 TCP 连接
响应时间/对象 = 2RTT + 传输时间
  (1 RTT 建连 + 1 RTT 请求响应 + 文件传输)
```

### 持久 HTTP（HTTP/1.1）

- 传输完一个对象后**保留 TCP 连接**
- **流水线**：遇到引用对象立即发请求
- 理想情况：所有引用对象在**一个 RTT** 内获取

| 模式 | 行为 |
|------|------|
| 非流水线 | 按序请求，等待响应后再发下一个 |
| **流水线** | 连续发出所有请求，减少约一半响应时间 |

## 请求/响应报文

### 请求报文（ASCII）

```
GET /index.html HTTP/1.1\r\n
Host: www.example.edu\r\n
User-Agent: ...\r\n
Connection: keep-alive\r\n
\r\n                          ← 空行结束头部
```

| 方法 | 用途 |
|------|------|
| **GET** | 请求 URL 对象（数据可放 URL ? 后面） |
| **POST** | 实体体中发送用户输入 |
| **HEAD** | 仅请求头部 |
| **PUT** | 上传/替换服务器文件 |

### 响应报文

```
HTTP/1.1 200 OK\r\n
Date: ...\r\n
Content-Type: text/html\r\n
Content-Length: 2651\r\n
\r\n
data data data...
```

| 状态码 | 含义 |
|--------|------|
| **200 OK** | 成功 |
| **301 Moved Permanently** | 永久重定向（Location 字段） |
| **400 Bad Request** | 请求无法理解 |
| **404 Not Found** | 文档未找到 |
| **304 Not Modified** | 条件 GET，缓存仍有效 |
| **505** | HTTP 版本不支持 |

## Cookie：维护状态

HTTP 本身**无状态**，Cookie 在客户端/服务器间维持状态。

四个组成部分：
1. 响应头部 `Set-Cookie: id`
2. 请求头部 `Cookie: id`
3. 用户端系统中的 **Cookie 文件**（浏览器管理）
4. Web 站点**后台数据库**

用途：认证、购物车、推荐、会话管理（Web Email）。

> [!warning]
> Cookie 存在**隐私问题**：第三方追踪 Cookie 可跨站点追踪用户。

## Web 缓存（代理服务器）

- 既是**客户端**（对源服务器）又是**服务器**（对浏览器）
- 命中缓存 → 直接返回（低延迟）；未命中 → 向源服务器请求并缓存

**收益**：降低响应时间、减少接入链路流量、减轻源服务器负担。

### 缓存计算例题

| 参数 | 值 |
|------|-----|
| 接入链路 | 1.54 Mbps |
| RTT 到服务器 | 2 sec |
| 对象大小 | 100 Kbits |
| 请求速率 | 15 次/s |
| 缓存命中率 | 0.4 |

- 经接入链路速率 = 0.6 × 1.50 = **0.9 Mbps**（利用率 0.58）
- 平均延迟 ≈ 0.6 × 2.01 + 0.4 × ms ≈ **1.2 sec**

### 条件 GET

```
请求: If-Modified-Since: <date>
响应: 304 Not Modified（无对象体）或 200 OK + 数据
```

## HTTP/2 与 HTTP/3

| 版本 | 关键改进 | 局限 |
|------|----------|------|
| **HTTP/1.1** | 持久连接 + 流水线 | FCFS 导致 **HOL 阻塞** |
| **HTTP/2** | 流号区分请求；帧交错传输；优先级调度；**服务器推送**；HPACK 头部压缩 | 仍基于 TCP，丢段暂停所有流 |
| **HTTP/3** | **QUIC over UDP**；独立流控/拥塞控制；与 TLS 1.3 协作 | 详见传输层 |

```
HTTP/1.1 HOL:  O1(大) 阻塞 O2,O3,O4
HTTP/2:        O2,O4 帧交错，小对象先到达
HTTP/3:        HTTP/2 + QUIC（UDP），丢包不影响其他流
```

## 考试/测试常见模式
| 场景/关键词 | 答案 |
|-------------|------|
| "HTTP 无状态" | 服务器**不维护**客户端状态 |
| "非持久响应时间" | **2RTT + 传输时间**/对象 |
| "HTTP/2 缓解 HOL" | **帧交错** + 优先级调度 |
| "304 含义" | **Not Modified**，缓存有效 |
| "Cookie 四组件" | Set-Cookie / Cookie头 / 本地文件 / 后台DB |
