# 协议层次与服务模型（重要性: ★★★）

#networking #overview #layered-architecture #protocol #concept

## 概览表（一目了然）
| 条目 | 要点 |
|------|------|
| 五层模型 | 应用→传输→网络→链路→物理 |
| 七层 OSI | 五层 + **表示层** + **会话层**（Internet 协议栈无此两层） |
| 服务 vs 协议 | 服务=**垂直**（下层为上层）；协议=**水平**（对等实体间） |
| 封装 | message → segment → datagram → frame → bits |

## 为什么分层？

| 好处 | 说明 |
|------|------|
| **概念化** | 结构清晰，标示组件位置与关系 |
| **结构化** | 便于设计、实现、调试；层间接口不变时可独立升级 |
| **标准化** | 便于讨论和交流 |

> [!warning]
> 分层缺点：**复杂、效率低**。Internet 协议栈"缺少" OSI 的表示层和会话层——这些服务由**应用层**自行实现（如 TLS 加密）。

## 五层 Internet 协议栈

```
┌─────────────┐
│  应用层      │  HTTP, SMTP, DNS, FTP — 网络应用
├─────────────┤
│  传输层      │  TCP, UDP — 进程到进程
├─────────────┤
│  网络层      │  IP + 路由协议 — 主机到主机
├─────────────┤
│  链路层      │  Ethernet, WiFi, PPP — 相邻节点帧传输
├─────────────┤
│  物理层      │  在线路上传送 bit
└─────────────┘
```

| 层次 | 功能 | PDU 名称 |
|------|------|----------|
| 应用层 | 为人类/应用进程提供网络服务 | **message（报文）** |
| 传输层 | 进程到进程；可靠/不可靠 | **segment（段）** |
| 网络层 | 主机到主机端到端 | **datagram（数据报）** |
| 链路层 | 相邻节点帧传输 | **frame（帧）** |
| 物理层 | bit 传输 | **bits** |

## ISO/OSI 七层模型

Internet 五层 + **表示层**（加密、压缩）+ **会话层**（同步、检查点）

Internet 协议栈**没有**这两层——需要时由应用层实现。

## 服务类型

| 类型 | 特点 | 示例 |
|------|------|------|
| **面向连接** | 建立连接→通信→拆除；通常可靠 | TCP |
| **无连接** | 不预留资源；可能重复/失序 | UDP、IP |

## 服务 vs 协议

| | 服务 | 协议 |
|---|------|------|
| 方向 | **垂直**（下层→上层） | **水平**（对等实体间） |
| 机制 | 原语（primitive）操作 | 报文格式+次序+动作 |
| 关系 | 本层协议实现**依赖**下层服务 | 本层协议为上层提供**更高级服务** |

**SAP（服务访问点）**：接口上的具体位置，如传输层 **port**。

## 封装与解封装

```
源端封装:
  M → [Ht|M] → [Hn|Ht|M] → [Hl|Hn|Ht|M] → bits

目的端解封装（端到端）:
  传输层/网络层: 源→目的全程
  链路/物理层: 每跳路由器/交换机解封装再封装
```

```
源主机                    路由器                    目的主机
  M                        —                         M
 [Ht|M]                  [Ht|M]                   [Ht|M]
[Hn|Ht|M]  ──→  [Hl|Hn|Ht|M]  ──→  [Hn|Ht|M]
  frame           frame (仅链路层)        datagram
```
