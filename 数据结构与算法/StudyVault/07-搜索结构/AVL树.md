# AVL 树（★★★）

#data-structure #search #tree #avl #concept

## 概览表（一目了然）
| 条目 | 要点 |
|------|------|
| **定义** | 高度平衡的 BST：左右子树均为 AVL 树，高度差绝对值 ≤ 1 |
| **平衡因子 bf** | bf = 右子树高度 − 左子树高度；AVL 树中 bf ∈ {-1, 0, 1} |
| **搜索** | O(log₂n)（保证平衡 → 高度 O(log₂n)） |
| **旋转** | 4 种：左单旋(LL)、右单旋(RR)、先左后右(LR)、先右后左(RL) |
| **插入** | 插入后沿路径回溯，发现不平衡即旋转 |

## AVL 树定义

**为什么需要 AVL？** BST 在有序插入时退化为链表，搜索变成 O(n)。AVL 树的核心承诺是：**无论怎么插入/删除，树的高度始终保持 O(logn)**——代价是每次操作后可能需要旋转来恢复平衡。

**AVL 树**（Adelson-Velsky & Landis, 1962）：或为空树，或满足：
1. 是一棵**二叉搜索树**（左<根<右）
2. 左子树和右子树都是 AVL 树
3. **|左子树高度 − 右子树高度| ≤ 1**

**平衡因子**（Balance Factor）：

$$bf(v) = height(v.right) - height(v.left)$$

AVL 树中每个结点的 bf 只能取 **-1、0、1**。一旦出现 ±2 就需要旋转修复。

```
合法 AVL 树:                 非法（bf=2）:
      30(0)                       30(+2)
     /    \                          \
   20(-1)  40(0)                     40(+1)
   /                                    \
  10(0)                                 50(0)

每个结点旁标注 bf 值
```

> [!important] AVL 树的高度保证
> n 个结点的 AVL 树高度为 **O(log₂n)**，精确上界约 1.44·log₂(n+2)。
> 因此搜索、插入、删除均为 **O(log₂n)**——这是 AVL 的核心价值。

### AVL 的代价与收益

| 维度 | 收益 | 代价 |
|------|------|------|
| **搜索** | 最坏 O(logn)，不会退化 | — |
| **插入** | 最多一次旋转（O(1)）恢复平衡 | 需要维护/更新平衡因子 |
| **删除** | 恢复平衡 | 可能需要 O(logn) 次旋转（沿路径向上传播） |
| **空间** | — | 每个结点额外存储 bf 或高度（1 字节/4 字节） |
| **实现** | — | 代码比裸 BST 复杂得多 |

## 四种平衡化旋转

插入新结点后，沿插入路径回溯检查平衡因子。发现不平衡时，取**三个关键结点**进行旋转。

### 如何判断旋转类型？

**思维口诀**：从不平衡点出发，看"不平衡来自哪个方向"——沿两步方向就确定了类型：

| 不平衡形状 | 两步方向 | 形状 | 旋转类型 | 记忆 |
|-----------|---------|------|----------|------|
| bf=+2, 右子bf=+1 | 右→右 | 直线 | **左单旋转** | 把中间结点提上去 |
| bf=-2, 左子bf=-1 | 左→左 | 直线 | **右单旋转** | 把中间结点提上去 |
| bf=-2, 左子bf=+1 | 左→右 | 折线 | **先左后右双旋转** | 先捋直再提 |
| bf=+2, 右子bf=-1 | 右→左 | 折线 | **先右后左双旋转** | 先捋直再提 |

**直觉**：
- **直线型**（同方向）→ 一次旋转就能把"重心"拉回来
- **折线型**（不同方向）→ 先把折线捋成直线，再做一次单旋

### 左单旋转（RotateLeft）—— 右-右型

**场景**：A 的右子树太高（bf=+2），而且右子 C 的右子树更高（bf=+1）

```
    A(+2)              C(0)
   / \               /   \
  B   C(+1)  -->   A(0)   E
     / \          / \
    D   E        B   D

操作：C 上升替代 A；A 成为 C 的左子女；D（C的左子树）成为 A 的右子女
```

**为什么 D 要挂到 A 的右边？** 因为 D 原来在 C 的左子树中，所以 A < D < C（BST 性质）。C 提升后 A 变成 C 的左子，A 的右子树位置空出来了，正好放 D。

```
RotateL(ptr):          // ptr 指向 A
  subL = ptr           // A
  ptr = subL.right     // C 上升
  subL.right = ptr.left // D → A.right
  ptr.left = subL      // A → C.left
  ptr.bf = subL.bf = 0
```

### 右单旋转（RotateRight）—— 左-左型

**场景**：A 的左子树太高（bf=-2），而且左子 B 的左子树更高（bf=-1）

```
      A(-2)           B(0)
     / \             /   \
   B(-1) E  -->    D    A(0)
   / \                  / \
  D   C                C   E

操作：B 上升替代 A；A 成为 B 的右子女；C（B的右子树）成为 A 的左子女
```

### 先左后右双旋转（RotateLR）—— 左-右型

**场景**：A 的左子树太高，但左子 B 的**右**子树更高（折线型）

```
第一步：对 B 做左单旋（把折线捋直）    第二步：对 A 做右单旋
      A(-2)          A(-2)               E(0)
     / \            / \                 /   \
   B(+1) G  -->  E(-1) G  -->       B(0)  A(0)
   / \           / \                / \   / \
  D  E(?)      B   F              D   C F   G
    / \       / \
   C   F     D   C
```

**两步**：先对 B 做左单旋转（把 B-E 的折线变成 E-B 的直线），再对 A 做右单旋转（把 E 提到顶部）。

**E 的子树 C、F 如何分配？** E 提到顶部后：
- C 原来是 E 的左子 → 分配给 B 的右子（B < C < E）
- F 原来是 E 的右子 → 分配给 A 的左子（E < F < A）

### 先右后左双旋转（RotateRL）—— 右-左型

与 LR 镜像对称：先对右子女做右单旋转（捋直），再对根做左单旋转（提升）。

### 旋转的完整手推示例

依次插入 [50, 25, 70, 15, 35, 30]：

```
插入50,25,70:  平衡，无需旋转
       50(0)
      /    \
    25(0)  70(0)

插入15:  平衡
       50(-1)
      /    \
    25(-1)  70(0)
   /
  15(0)

插入35:  平衡
       50(-1)
      /    \
    25(0)  70(0)
   / \
  15  35

插入30:  不平衡！
       50(-2)         ← bf=-2，左子树太高
      /    \
    25(+1)  70        ← 左子bf=+1 → 左-右型（LR）！
   / \
  15  35(-1)
     /
    30

执行 LR 双旋转:
步骤1: 对25做左旋 → 35上升
       50(-2)
      /    \
    35(-1)  70
   / \
  25   (空)
 / \
15  30

步骤2: 对50做右旋 → 35提到顶部
       35(0)
      /    \
    25(0)  50(0)
   / \      \
  15  30    70

结果：平衡恢复！高度从4回到3。
```

## AVL 树插入流程

```
1. 按 BST 规则插入新结点（叶结点）
2. 从插入点沿路径向根回溯
3. 更新各结点的平衡因子
4. 若某结点 |bf| = 2：
   a. 判断旋转类型（LL/RR/LR/RL）
   b. 执行对应旋转
   c. 旋转后子树高度恢复 → 停止回溯（不需要继续往上检查）
```

> [!tip] 插入只需一次旋转
> AVL 树插入至多执行**一次旋转**（单旋或双旋）即可恢复平衡。原因：旋转后子树高度回到插入前的值，上面的结点 bf 自然不会变化。
>
> 但**删除**可能需要 O(logn) 次旋转——因为删除可能让子树高度减小，影响会向上传播。

---

## AVL 树删除

删除比插入复杂，因为旋转可能让树变矮，导致祖先结点也需要旋转：

```
1. 按 BST 规则删除结点
2. 从删除位置沿路径向根回溯
3. 每个结点检查 bf，若 |bf| = 2 则旋转
4. 旋转后继续向上检查（不能停！可能连锁不平衡）
```

**插入 vs 删除的旋转次数对比**：

| 操作 | 最多旋转次数 | 原因 |
|------|-------------|------|
| 插入 | 1 次 | 旋转后高度恢复，不影响上层 |
| 删除 | O(logn) 次 | 旋转可能让高度减小，继续影响上层 |

---

## AVL 树 vs 普通 BST vs 红黑树

| 比较维度 | BST | AVL 树 | 红黑树 |
|---------|-----|--------|--------|
| **最坏搜索** | O(n)（退化为链） | **O(log₂n)** | **O(log₂n)** |
| **插入旋转** | 无 | 至多 1 次 | 至多 2 次 |
| **删除旋转** | 无 | 至多 O(logn) 次 | 至多 3 次 |
| **平衡严格度** | 无保证 | 极严格（|bf|≤1） | 较宽松（最长路径≤2倍最短） |
| **搜索速度** | 不确定 | **最快**（树最矮） | 略慢于 AVL |
| **插入/删除速度** | 最快（无维护） | 较慢（严格平衡） | **较快**（宽松平衡） |
| **实现复杂度** | 简单 | 中等 | 复杂 |
| **典型用途** | 教学 | 查找密集型（数据库索引） | 插入删除密集型（C++ map、Java TreeMap） |

**面试回答模板**：
- "AVL 用严格平衡换来了最优搜索性能，代价是插入/删除时可能需要更多旋转"
- "红黑树放松了平衡条件（允许高度差到 2 倍），因此修改操作更快，但搜索略慢"
- "如果读多写少选 AVL，如果读写均衡选红黑树"

## 考试/测试常见模式
| 场景/关键词 | 答案 |
|-------------|------|
| "判断是否为 AVL 树" | **检查每个结点 \|bf\| ≤ 1** |
| "插入后需要哪种旋转" | **看两步方向：同向=单旋，折线=双旋** |
| "左-右型不平衡" | **先左后右双旋转（LR 旋转）** |
| "AVL 树搜索最坏复杂度" | **O(log₂n)**（不会退化） |
| "画出依次插入序列后的 AVL 树" | **每次插入后检查平衡，必要时旋转** |
| "bf = 右子树高 - 左子树高" | **注意定义方向，有些教材定义相反（左-右）** |
| "AVL 插入最多几次旋转" | **1 次**（单旋或双旋算 1 次） |
| "AVL 删除最多几次旋转" | **O(logn) 次**（可能沿路径连锁） |
| "AVL vs 红黑树选择" | **读多用 AVL（更矮）；写多用红黑树（旋转少）** |
