# 静态搜索与二叉搜索树（★★★）

#data-structure #search #bst #tree #time-complexity #concept

## 概览表（一目了然）
| 条目 | 要点 |
|------|------|
| **搜索** | 在数据集合中寻找满足条件的数据对象 |
| **关键码** | 唯一标识对象的属性域 |
| **静态搜索表** | 结构不变；顺序搜索 O(n)、折半搜索 O(log₂n) |
| **动态搜索表** | 结构随插入/删除调整（BST、AVL） |
| **ASL** | 平均搜索长度 = Σpᵢ·cᵢ |
| **BST** | 左 < 根 < 右；中序遍历有序 |

## 搜索基本概念

**搜索**：在数据集合中寻找**关键码**等于给定值的数据对象。

| 术语 | 含义 |
|------|------|
| **搜索结构** | 用于搜索的数据集合 |
| **关键码（Key）** | 唯一标识对象的属性 |
| **搜索成功** | 返回对象位置/信息 |
| **搜索失败** | 返回失败标志 |

### 两种搜索环境

| 类型 | 特点 | 代表结构 |
|------|------|----------|
| **静态搜索表** | 插入/删除前后结构不变 | 有序数组 |
| **动态搜索表** | 操作后自动调整结构 | BST、AVL |

---

## 顺序搜索

从表头开始逐一比较，直到找到或遍历完毕。

**监视哨技巧**：将目标值 x 放在表末尾（`Element[n].key = x`），省去越界检查。

```
SeqSearch(x):
  Element[CurrentSize].key = x  // 监视哨
  i = 0
  while Element[i].key ≠ x: i++
  return i + 1
```

### ASL 分析

| 情形 | ASL |
|------|-----|
| **等概率成功** | ASL_succ = (n+1)/2 |
| **搜索失败** | ASL_unsucc = n+1 |
| **时间复杂度** | **O(n)** |

---

## 折半搜索（二分搜索）

**前提**：有序顺序表。每次与中间元素比较，缩小一半搜索范围。

```
BinarySearch(x):
  low = 0, high = n-1
  while low ≤ high:
    mid = ⌊(low+high)/2⌋
    if x == Element[mid].key: return mid  // 成功
    if x < Element[mid].key: high = mid-1  // 左半
    else: low = mid+1                      // 右半
  return -1  // 失败
```

### 判定树与 ASL

折半搜索过程对应一棵**判定树**（二叉树），第 k 层的结点需比较 k 次。

| 情形 | 公式 | 示例（n=6） |
|------|------|-------------|
| **成功** | ASL_succ ≈ log₂(n+1) - 1 | 14/6 ≈ 2.33 |
| **失败** | ASL_unsucc 由外部结点层次决定 | 20/7 ≈ 2.86 |
| **时间复杂度** | **O(log₂n)** | — |

> [!warning] 折半搜索的局限
> 仅适用于**有序顺序表**（数组），不适用于链表（无法随机访问）。

## 二叉搜索树（BST）

**核心直觉**：BST 把"二分搜索"的思想嵌入到树结构中。在有序数组中二分搜索时，每次比较都排除一半数据；BST 中，每次比较都决定走左还是走右——本质上就是在做"活的二分搜索"。

**定义**：二叉搜索树或为空树，或满足：
1. 每个结点有唯一关键码
2. **左子树**所有关键码 **<** 根结点关键码
3. **右子树**所有关键码 **>** 根结点关键码
4. 左右子树也是 BST

**核心性质**：BST 的**中序遍历**产生**升序序列**（故又称二叉排序树）。

```
         53                   中序遍历: 9, 17, 23, 45, 53, 65, 78, 81
        /  \                  
      17    78                验证 BST 性质:
     / \   / \                · 左子树最大值(45) < 根(53) < 右子树最小值(65) ✓
    9  45 65  81              · 每个子树内部也满足 ✓
      /
    23
```

> [!warning] BST 要求的是"左子树**所有**结点 < 根"，不仅仅是左孩子
> 错误理解：只检查 左孩子 < 父 < 右孩子
> 正确理解：左子树**整棵**所有结点都 < 根；右子树**整棵**所有结点都 > 根
> 
> 反例：下面不是 BST（7 在 5 的右子树中，但 7 < 10 不够，因为 7 在 15 的左子树中却 < 10）
> ```
>       15
>      /  \
>    10    20
>   /  \
>  5    7    ← 7 < 10 ✓ 但 7 < 15 才是需要满足的！实际上 7 确实 < 15 ✓
> ```
> 真正的反例：
> ```
>       10
>      /  \
>     5    15
>    / \
>   3   12    ← 12 > 10！虽然 12 > 5 (只看父子没问题)，但 12 在 10 的左子树中 → 违反！
> ```

### BST 搜索

```
Search(x, ptr):
  if ptr == NULL: return NULL      // 失败
  if x < ptr.key: Search(x, ptr.left)
  if x > ptr.key: Search(x, ptr.right)
  return ptr                        // 成功
```

- 沿根到叶路径搜索，最多比较次数 = **树的高度 h**

### BST 插入

先搜索确认不存在，再在搜索失败位置插入新叶结点。

```
Insert(e1, ptr):
  if ptr == NULL: ptr = new Node(e1)  // 作为叶结点插入
  else if e1 < ptr.key: Insert(e1, ptr.left)
  else if e1 > ptr.key: Insert(e1, ptr.right)
  else: return false  // 已存在
```

> [!important] 插入顺序决定树形 — BST 退化的根源
> 同一组关键码，不同插入顺序产生**完全不同**的 BST：
> ```
> 插入顺序 [53,17,78,9,45,65,81]:      插入顺序 [9,17,23,45,53,65,78]:
>          53（平衡）                       9（退化为链）
>         /  \                               \
>       17    78                              17
>      / \   / \                               \
>     9  45 65  81                             23
>                                                \
>   高度=3, ASL≈O(logn)                         45
>                                                  \
>                                                  ...
>                                             高度=7, ASL≈O(n)
> ```
> 这就是为什么需要 AVL/红黑树——它们通过旋转防止退化。

### BST 删除（三种情况 ★★★）

删除是 BST 最复杂的操作，需要分三种情况：

| 情况 | 处理方法 | 直觉 |
|------|----------|------|
| **叶结点** | 直接删除，父指针置 NULL | 叶子没有子树，删了无影响 |
| **仅有一个子树** | 用子树根顶替被删结点 | "独生子直接继承" |
| **有两个子树** | 用**中序后继**（右子树最小值）替换，再删除该后继 | "找最接近的人来顶替" |

**情况3的详细图解**：删除结点 45

```
步骤1: 找到45的中序后继 = 右子树的最左结点 = 没有右子树？则找左子树最大值
       这里45只有左子树23，所以用中序前驱23来替换（也可以）

原树:                         删除45后:
        53                         53
       /  \                       /  \
     17    78      ------>      17    78
    /  \                       /  \
   9   45                     9   23
      /
    23

步骤: 45有左子树(23) → 用23顶替45的位置
```

**更复杂的例子**：删除有两个子树的结点 17

```
原树:                         用中序后继(23)替换:
        53                         53
       /  \                       /  \
     17    78      ------>      23    78
    /  \                       /  \
   9   45                     9   45
      /
    23

步骤:
1. 17 有左子树(9)和右子树(45) → 情况3
2. 找17的中序后继 = 17的右子树中最小值 = 沿45→23走到底 = 23
3. 将23的值复制到17的位置
4. 删除原来的23（23是叶结点 → 情况1，直接删）
```

> [!tip] 为什么用中序后继/前驱替换？
> 中序后继是"比被删结点大的最小元素"——用它替换后，BST 性质仍然成立：
> - 它比左子树所有元素都大 ✓（因为它是右子树的一部分）
> - 它比右子树其余元素都小 ✓（因为它是右子树中最小的）

### BST 性能分析

| 情形 | ASL | 说明 |
|------|-----|------|
| **最好**（平衡） | O(log₂n) | 类似折半搜索 |
| **最坏**（退化为链） | O(n) | 有序插入时 |
| **平均** | O(log₂n) | 随机插入 |

**为什么 BST 会退化？**

```
n 个结点的 BST:
  最好情况: 高度 = ⌈log₂(n+1)⌉ ≈ log₂n（平衡二叉树）
  最坏情况: 高度 = n（单链）
  平均情况: 高度 ≈ 1.39·log₂n（随机插入）

退化条件: 按升序/降序/近乎有序 插入 → 每次新结点都在最右/最左
```

**BST 退化的实际影响**：
- 有序数据非常常见（日志按时间、ID 递增等）
- 一旦退化，搜索/插入/删除全部变为 O(n)——和链表没区别
- 这就是为什么实际工程中几乎不用裸 BST，而用 AVL/红黑树/B树

## BST、AVL、堆的对比（★ 面试高频）

| 维度 | BST | AVL（平衡BST） | 堆 |
|------|-----|------|------|
| **有序性** | 全局有序（中序=升序） | 全局有序 | 仅父子有序（局部） |
| **搜索任意值** | O(h)，h=logn~n | O(logn) 保证 | O(n)（必须遍历） |
| **取最小/最大** | O(h)（最左/最右） | O(logn) | **O(1)**（堆顶） |
| **插入** | O(h) | O(logn)+旋转O(1) | O(logn) |
| **删除任意值** | O(h) | O(logn)+旋转O(logn) | O(n)找+O(logn)调整 |
| **适用问题** | 需要有序遍历 | 需要有序+最坏保证 | 只需反复取极值（Top K、调度） |
| **中序遍历** | 升序输出 ✅ | 升序输出 ✅ | 无法有序输出 ❌ |

**一句话区分**：
- 需要"找任意值"→ BST/AVL
- 需要"不断取最大/最小"→ 堆
- 需要"防止退化"→ AVL（或红黑树）

## 搜索方法综合比较

| 方法 | 时间复杂度 | 数据要求 | 适用场景 |
|------|-----------|----------|----------|
| **顺序搜索** | O(n) | 无要求 | 小规模/无序数据 |
