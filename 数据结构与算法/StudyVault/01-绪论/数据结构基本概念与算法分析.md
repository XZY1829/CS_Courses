## 什么是数据结构（1.1）

数据结构是一门关注**非数值计算**程序设计问题中，计算机**操作对象**及其**关系**和**操作**的学科。描述这类问题的数学模型是表、树、图等结构，而非数学方程。

- **学生表** → 线性关系 → 遍历、查找、插入、删除
- **博弈树** → 一对多层次关系 → 树型结构
- **社交网络** → 多对多关系 → 图型结构

```
实际问题 → 分析抽象 → 逻辑结构 + 逻辑运算
                ↓
         物理结构 + 运算实现 → 程序 → 结果
```

## 基本概念和术语（1.2）

### 数据层次

| 术语 | 定义 | 示例（学生表） |
|------|------|----------------|
| **数据（Data）** | 信息的载体，可被程序识别处理的符号集合 | 整张表 |
| **数据元素（Data Element）** | 数据的基本单位，也称结点/顶点/记录 | 一行学生记录 |
| **数据项（Data Item）** | 组成数据元素的最小单位，有特定意义 | 学号、姓名、性别 |
| **数据对象（Data Object）** | 性质相同的数据元素集合 | 全体学生记录 |

层次关系：**数据项 ⊂ 数据元素 ⊂ 数据对象 ⊂ 数据**

### 数据结构的形式定义

**Data_Structure = {D, R}**
- **D**：数据对象（元素集合）
- **R**：D 上关系的有限集合

例：班级结构 Class = (D, S)，D 含班长/组长/组员，S 含 R1（班长-组长）、R2（组长-组员）。

### 逻辑结构（四种）

| 类型 | 关系特征 | 前驱/后继 |
|------|----------|-----------|
| **集合** | 同属集合，无其他关系 | 无序 |
| **线性** | 有序序列，1 对 1 | 首尾无单向前/后继 |
| **树型** | 1 对多 | 根无前驱，其余有唯一前驱 |
| **图型** | 多对多 | 前驱后继均不限 |

### 存储结构（四种）

| 类型       | 要点                  |
| -------- | ------------------- |
| **顺序存储** | 逻辑相邻 → 物理相邻，连续内存    |
| **链式存储** | 结点可分散，用**指针**表示逻辑关系 |
| **索引存储** | 索引表存元素地址，间接寻址       |
| **散列存储** | 地址 = Hash(关键字)      |

> [!warning] 逻辑结构与存储结构
> 同一逻辑结构可有多种存储实现（如线性表 → 数组或链表）。**算法设计取决于逻辑结构，实现依赖存储结构**。

### 数据的运算

创建、清除、插入、删除、搜索、更新、访问、遍历。

## 抽象数据类型 ADT（1.3）

**数据类型**：一组性质相同的值的集合 + 定义于该集合上的操作。

**ADT（Abstract Data Type）**：用户定义的、表示应用问题的数据模型，由基本类型组成并含一组相关服务（操作）。

**三元组表示**：**(D, R, P)**
- D：数据对象
- R：关系集合
- P：基本操作集合

```
ADT 抽象数据类型名 {
  数据对象D：<定义>
  数据关系R：<定义>
  基本操作P：<定义>
} ADT 抽象数据类型名
```

- **抽象**：抽取本质，不涉及实现细节
- **设计者**：定义 ADT 并实现，提供公共接口
- **用户**：通过接口操作，**黑盒**使用
- C++ 的**类**是 ADT 的典型体现

## 算法与算法分析（1.4）

### 算法定义与特性

**算法**：有穷的指令集，为特定任务规定运算序列（求解步骤的描述）。

| 特性 | 含义 |
|------|------|
| **输入** | 0 个或多个 |
| **输出** | 1 个或多个 |
| **确定性** | 每步确切无歧义，相同输入相同结果 |
| **有穷性** | 有限步后结束（程序可无限循环，不一定是算法） |
| **有效性** | 每步可经基本操作在有限次内完成 |

**程序 ≠ 算法**：程序是算法的语言实现，但程序不一定满足有穷性。

### 算法性能标准

正确性、可使用性、可读性、**效率**、健壮性、简单性。

### 时间复杂度

用**关键操作**重复次数 T(n) 度量，忽略常系数与低阶项：

**T(n) = O(f(n))** — 上界，随 n 增长与 f(n) 同阶。

常见阶（由低到高）：
```
O(1) < O(log₂n) < O(n) < O(n log₂n) < O(n²) < O(n³) < O(2ⁿ) < O(n!)
```

**运算规则**：
- **加法**（并列段）：T = O(max(f(n), g(m)))
- **乘法**（嵌套段）：T = O(f(n) × g(m))
- 常数项 → O(1)

**例：矩阵乘法** 三重循环 → T(n) = O(n³)

### 最坏、最好、平均

| 记号 | 含义 |
|------|------|
| **O(f(n))** | 上界，通常指**最坏情况** |
| **Ω(f(n))** | 下界，**最好情况** |
| **Θ(f(n))** | 上界与下界同时成立，**紧确界** |

日常简说"时间复杂度"多指 **O 表示法**。

### 深入理解：O 的本质、怎么算、有什么用（★★★）

上面的内容过于抽象，这里用大白话把三个核心问题讲透。

#### 一、O 到底是什么意思？

**O(f(n)) 的严格含义**：存在正常数 c 和 n₀，使得当 n ≥ n₀ 时，T(n) ≤ c · f(n)。

翻译成人话就是：**当数据量足够大以后，算法实际运行时间 T(n) 的增长速度不会超过 f(n) 的某个常数倍。**

几个关键要点：
- **O 是"上界"而非"精确值"**：说一个算法是 O(n²) ，意思是"最坏也不会比 n² 的某个倍数更慢"。从数学上说 O(n) 的算法你也可以说它是 O(n²)（因为 n 当然不超过 n² ），但我们习惯写**最紧的上界**。
- **忽略常数和低阶项**：`3n² + 100n + 9999` 和 `0.01n²` 都是 O(n²)。因为当 n 足够大时（比如 n = 100万），`100n` 和 `9999` 相比 `3n²` 可以忽略不计，而常数系数 3 也只影响"快几倍"，不影响"量级"。
- **O 描述的是"增长趋势"**：它不告诉你"跑 1 秒还是 2 秒"，而告诉你"数据翻倍时，时间大概变成几倍"。

| 复杂度 | n 翻倍后时间变为 | 直觉 |
|--------|------------------|------|
| O(1) | 不变 | 与数据量无关 |
| O(log n) | 多一丁点 | 每次减半 |
| O(n) | 约 2 倍 | 线性增长 |
| O(n log n) | 略超 2 倍 | 排序的典型 |
| O(n²) | 约 **4 倍** | 数据翻倍→时间×4 |
| O(2ⁿ) | 约 **平方** | 指数爆炸 |

#### 二、怎么计算复杂度？（实操三步法）

**第 1 步：找到"最深层"的循环（或递归）嵌套，数清楚每层执行几次**

```cpp
for (int i = 0; i < n; i++)          // 外层：n 次
    for (int j = 0; j < n; j++)      // 内层：每次 n 次
        sum += a[i][j];              // 最内层操作
// 总次数 = n × n = n²  →  O(n²)
```

**第 2 步：并列的代码段取最大**

```cpp
// 段 A：O(n)
for (int i = 0; i < n; i++) doSomething();

// 段 B：O(n²)
for (int i = 0; i < n; i++)
    for (int j = 0; j < n; j++) doOther();

// 总复杂度 = O(max(n, n²)) = O(n²)
```

**第 3 步：对于"非标准"循环，分析循环变量的变化规律**

```cpp
// 例 1：循环变量乘 2
for (int j = 1; j < n; j *= 2)
    doSomething();
// j 的取值：1, 2, 4, 8, ..., 2^k（当 2^k ≥ n 时停止）
// 所以 k = log₂n  →  O(log n)

// 例 2：循环变量平方
for (int i = 2; i < n; i = i * i)
    doSomething();
// i 的取值：2, 4, 16, 256, ...（即 2^1, 2^2, 2^4, 2^8, ...）
// 经过 k 步后 i = 2^(2^k)，当 2^(2^k) ≥ n 时停止
// 所以 2^k = log₂n → k = log₂(log₂n)  →  O(log log n)
```

**常见计算模式速查**

| 代码模式 | 复杂度 | 关键识别 |
|----------|--------|----------|
| 无循环、固定次数循环 | O(1) | 与 n 无关 |
| `for(i=0; i<n; i++)` | O(n) | 线性遍历 |
| `for(i=0; i<n; i++) for(j=0; j<n; j++)` | O(n²) | 双重嵌套 |
| `for(j=1; j<n; j*=2)` | O(log n) | 每次翻倍 |
| `for(j=n; j>0; j/=2)` | O(log n) | 每次减半 |
| `for(i=0;i<n;i++) for(j=0;j<i;j++)` | O(n²) | 内层 0+1+...+(n-1) = n(n-1)/2 |
| 排序后二分查找 | O(n log n) | 排序 O(n log n) + 查找 O(log n) |

#### 三、复杂度在实际中到底意味着什么？

复杂度不是一个"理论玩具"，它直接决定了**你的程序能不能在时限内跑完**。

假设计算机每秒执行 10⁸ 次操作，1 秒时限下各复杂度能处理的最大 n：

| 复杂度 | 1 秒可处理的 n | 直觉 |
|--------|---------------|------|
| O(log n) | 任意大 | 随便来 |
| O(n) | ~10⁸ | 一亿 |
| O(n log n) | ~10⁶ ∼ 10⁷ | 百万级 |
| O(n²) | ~10⁴ | 一万 |
| O(n³) | ~10² ∼ 500 | 几百 |
| O(2ⁿ) | ~25 | 二十几 |
| O(n!) | ~12 | 十来个 |

> [!tip] 实用判断法
> 考试/竞赛中看到 n 的范围就能反推需要什么复杂度的算法：
> - n ≤ 20 → 可以暴力 O(2ⁿ)
> - n ≤ 5000 → 需要 O(n²) 及以下
> - n ≤ 10⁵ ∼ 10⁶ → 需要 O(n log n) 及以下
> - n ≤ 10⁸ → 必须 O(n)
>
> **如果你的算法复杂度 × 数据规模 > 10⁸，大概率超时。**

#### 四、一个完整的计算示例

分析以下函数的时间复杂度：

```cpp
void example(int n) {
    int count = 0;

    for (int i = 0; i < n; i++)           // ①
        for (int j = i; j < n; j++)       // ②
            count++;

    for (int k = 1; k < n; k *= 2)        // ③
        count++;
}
```

**分析过程**：
1. **段 ①②（嵌套循环）**：内层循环次数依赖 i。当 i=0 时执行 n 次，i=1 时 n-1 次，……，i=n-1 时 1 次。总次数 = n + (n-1) + … + 1 = **n(n+1)/2** → O(n²)
2. **段 ③（独立循环）**：k 每次 ×2，执行 log₂n 次 → O(log n)
3. **两段并列**：取最大 → O(max(n², log n)) = **O(n²)**

> [!warning] 常见误区
> - ❌ "O(n²) 就是执行 n² 次"——不对，O(n²) 是说**增长趋势**是 n² 量级，实际可能是 0.5n² 或 3n²+100。
> - ❌ "O(1) 就是只执行 1 次"——不对，O(1) 是说**不随 n 变化**，哪怕固定执行 10000 次也是 O(1)。
> - ❌ "两个 O(n) 的循环嵌套是 O(n)"——不对，**嵌套是乘法** → O(n²)；只有**并列**才取最大。

### 算法不变量（Loop Invariant）（★★★）

**一句话定义**：算法不变量是在算法执行过程中**每一轮迭代（或每一次递归调用）的开始/结束时都为真**的逻辑断言，它描述了"到目前为止，算法已经正确地完成了什么"。

为什么重要？
- **证明正确性**：只要证明三件事——① 初始化时不变量为真（基础）、② 每轮迭代保持不变量为真（保持）、③ 循环结束时不变量 + 终止条件 = 正确结果（终止），就能严格证明算法正确。
- **指导编程**：写代码时先想清楚不变量，循环体的每一步都是为了在修改状态后**恢复不变量**，这样不容易写错边界。

#### 例 1：移除有序数组重复项（快慢指针）

```cpp
int removeDuplicates(vector<int>& nums) {
    if (nums.empty()) return 0;
    int slow = 0;
    for (int fast = 1; fast < nums.size(); fast++) {
        if (nums[fast] != nums[slow]) {
            slow++;
            nums[slow] = nums[fast];
        }
    }
    return slow + 1;
}
```

**不变量**：`nums[0..slow]` 中保存的元素**互不重复且保持原始相对顺序**，并且这些元素恰好是 `nums[0..fast-1]` 中所有不重复元素的完整集合。

验证：
- **初始化**：`slow=0, fast=1`，`nums[0..0]` 只有一个元素，天然无重复 ✓
- **保持**：若 `nums[fast]` 与 `nums[slow]` 不同（即发现新值），`slow++` 后将新值写入 `nums[slow]`，不变量恢复；若相同（即重复），跳过即可，不变量自然保持 ✓
- **终止**：`fast == nums.size()` 时，`nums[0..slow]` 包含了全部不重复元素 ✓

#### 例 2：链表环检测（Floyd 快慢指针）

```cpp
bool hasCycle(ListNode* head) {
    ListNode *slow = head, *fast = head;
    while (fast != NULL && fast->next != NULL) {
        slow = slow->next;
        fast = fast->next->next;
        if (slow == fast) return true;
    }
    return false;
}
```

**不变量**：经过 k 轮迭代后，`slow` 走了 k 步，`fast` 走了 2k 步；若链表存在环，则每轮迭代 fast 与 slow 的**距离差减少 1**（fast 以每轮 1 步的速度追赶 slow）。

验证：
- **初始化**：`slow=head, fast=head`，两者都在起点，距离差为 0（还没进环），k=0 ✓
- **保持**：每轮 slow 走 1 步、fast 走 2 步。若两者都在环内，设 fast 在 slow 后方距离为 d，一轮后距离变为 d-1。距离差严格递减 ✓
- **终止**：距离差减到 0 时 `slow == fast`，检测到环；若无环则 `fast` 先到 NULL，正常退出 ✓

> [!tip] 不变量的实用价值
> 写双指针、滑动窗口、二分查找等算法时，先用一句话写出不变量，再围绕"保持不变量"编写循环体——这比凭直觉写代码再调试要靠谱得多。

### 空间复杂度

**S(n) = O(f(n))**：算法执行所需**辅助存储空间**随 n 的变化（不含输入本身占用的空间，教材语境下指额外空间）。
