# 插入排序与交换排序（★★★）

#data-structure #sort #insertion-sort #exchange-sort #quick-sort #concept

## 概览表（一目了然）
| 算法 | 最好 | 最坏 | 平均 | 空间 | 稳定 |
|------|------|------|------|------|------|
| **直接插入** | O(n) | O(n²) | O(n²) | O(1) | ✅ |
| **折半插入** | O(nlog₂n) | O(n²) | O(n²) | O(1) | ✅ |
| **Shell** | — | — | O(n^1.3)~O(n²) | O(1) | ❌ |
| **冒泡** | O(n) | O(n²) | O(n²) | O(1) | ✅ |
| **快速排序** | O(nlog₂n) | O(n²) | **O(nlog₂n)** | O(log₂n) | ❌ |

## 排序基本概念

- **排序**：将一组数据按排序码的某种顺序排列
- **排序码（Key）**：用作排序依据的属性域
- **稳定性**：相等排序码的元素在排序后保持原相对顺序 → **稳定**；否则 → **不稳定**
- **内排序 vs 外排序**：数据全在内存 vs 需内外存交换

## 直接插入排序

**核心直觉**：想象你手持一把扑克牌，每摸到新牌时，从右往左找到合适位置插入，使手中的牌始终有序。

**思想**：将第 i 个元素插入到前面已排好序的 V[0..i-1] 中的正确位置。

```
InsertSort(L, left, right):
  for i = left+1 to right:
    if L[i] < L[i-1]:
      temp = L[i], j = i-1
      while j ≥ left AND temp < L[j]:
        L[j+1] = L[j], j--
      L[j+1] = temp
```

**关键机制**：
- **外层循环**：从第 2 个元素开始，每次将一个新元素纳入"已排序区间"
- **内层循环**：将大于 temp 的元素逐个右移一位，腾出插入位置
- **提前终止**：一旦遇到 ≤ temp 的元素就停止——这就是为什么"基本有序"时极快

**示例**：排序 [21, 25, 49, 25*, 16, 08]（25* 表示第二个 25，用于观察稳定性）

```
初始: [21, 25, 49, 25*, 16, 08]
       ───── 已排序区间逐步扩大 ──────
i=1: [21, 25, 49, 25*, 16, 08]  temp=25, 25≥21 → 不需移动，直接放回
i=2: [21, 25, 49, 25*, 16, 08]  temp=49, 49≥25 → 不需移动
i=3: [21, 25, 25*, 49, 16, 08]  temp=25*, 25*<49 → 49右移；25*≥25 → 停！插入位置3
                                  注意：25*排在25后面 → 稳定！
i=4: [16, 21, 25, 25*, 49, 08]  temp=16, 逐个比较：16<49,25*,25,21 → 全部右移，插入位置0
                                  移动了4个元素 → 逆序对多时代价大
i=5: [08, 16, 21, 25, 25*, 49]  temp=08, 所有元素都比08大 → 移动5个，插入最前
```

| 复杂度 | 比较次数 | 移动次数 | 直觉解释 |
|--------|----------|----------|----------|
| **最好**（已有序） | n-1 | 0 | 每个元素只需和前一个比一次就知道不用动 |
| **最坏**（逆序） | n(n-1)/2 | (n+4)(n-1)/2 | 每个元素都要移到最前面，比较+移动都是满的 |
| **平均** | ≈ n²/4 | ≈ n²/4 | 平均每个元素需要移动一半的已排序区间 |

> [!tip] 为什么"基本有序"时直接插入最快？
> 内层循环的终止条件是遇到 ≤ temp 的元素。如果数据基本有序，每个元素离正确位置很近，内层循环只执行 1~2 次就退出，总时间接近 O(n)。这就是为什么快排在小规模子数组时会切换到插入排序。

## 折半插入排序

**核心直觉**：找插入位置可以用二分搜索加速——既然左侧已排序，为什么还要线性扫描？

**改进**：用折半搜索代替顺序搜索确定插入位置（减少比较次数，移动次数不变）。

```
BinaryInsertSort(L, left, right):
  for i = left+1 to right:
    temp = L[i]
    lo = left, hi = i-1
    while lo ≤ hi:                // 折半找插入位置
      mid = (lo + hi) / 2
      if temp < L[mid]: hi = mid-1
      else: lo = mid+1           // 等于时 lo 右移 → 保证稳定性
    // lo 即为插入位置
    for j = i-1 downto lo: L[j+1] = L[j]  // 移动仍是逐个搬
    L[lo] = temp
```

| 项目 | 值 | 说明 |
|------|----|----|
| **比较次数** | ≈ n·log₂n | 与初始排列**无关**（每次插入都做完整二分） |
| **移动次数** | 与直接插入相同 | 确定位置后仍需逐个右移，这一步无法优化 |
| **稳定性** | ✅ | 等于时 lo 右移，保证相同元素插在后面 |

> [!warning] 折半插入 vs 直接插入 — 一个反直觉的结论
> **已有序时**，直接插入只需 n-1 次比较（每次 temp ≥ L[i-1] 立即退出）；而折半插入仍然做完整的 O(log i) 次二分比较。所以折半插入在**已有序**情形下比较次数**多于**直接插入。
> 
> 折半插入真正的优势场景是：**数据量中等、初始排列随机**——此时比较次数从 O(n²) 降到 O(nlogn)，但移动仍为 O(n²)，整体仍为 O(n²)。

## Shell 排序（缩小增量排序）

**核心直觉**：直接插入在"基本有序"时接近 O(n)。如果我们能先让数据"大致有序"，最后一趟插入就很快。Shell 排序通过先对"远距离"元素排序实现这一目标。

**思想**：取递减增量序列 gap₁ > gap₂ > ... > 1，每次按间隔 gap 将元素分组，对各组做直接插入排序。随着 gap 缩小，数据越来越有序；当 gap=1 时退化为普通直接插入，但此时数据已基本有序。

```
ShellSort(L, left, right):
  gap = (right-left+1) / 2
  while gap > 0:
    for i = left+gap to right:
      temp = L[i], j = i-gap
      while j ≥ left AND temp < L[j]:
        L[j+gap] = L[j], j -= gap
      L[j+gap] = temp
    gap = gap / 2
```

**手推示例**：排序 [49, 38, 65, 97, 76, 13, 27, 49*]

```
gap=4: 分为4组 {49,76} {38,13} {65,27} {97,49*}
       排序后: [49, 13, 27, 49*, 76, 38, 65, 97]
       效果：远距离的逆序对被消除（13从位置5跳到位置1）

gap=2: 分为2组 {49,27,76,65} {13,49*,38,97}
       排序后: [27, 13, 49, 38, 65, 49*, 76, 97]
       效果：中等距离的逆序对被消除

gap=1: 普通直接插入，但此时已基本有序
       排序后: [13, 27, 38, 49, 49*, 65, 76, 97]
       效果：只有少量短距离移动
```

| 项目 | 值 | 说明 |
|------|----|----|
| **稳定性** | ❌ 不稳定 | 不同组独立排序可能改变相等元素顺序（上例中 49 和 49* 顺序可能被打乱） |
| **时间复杂度** | O(n^1.3) ~ O(n²) | 取决于增量序列选择 |
| **空间** | O(1) | 原地排序 |

> [!tip] 为什么 Shell 排序能突破 O(n²)？
> 关键在于**远距离交换**。O(n²) 排序（插入/冒泡/选择）每次只消除相邻逆序对；Shell 排序在 gap 较大时，一次移动就能消除**远距离**的逆序对，所以能做到更少的总移动次数。最后一趟 gap=1 时，绝大多数逆序对已经被前面的趟消除了。

## 冒泡排序

**核心直觉**：每一趟扫描像气泡一样把最大元素"浮"到数组末端。n-1 趟后所有元素就位。

**思想**：相邻元素两两比较，逆序则交换，每趟将最大元素"冒泡"到末端。

```
BubbleSort(L, left, right):
  for i = 0 to n-2:
    swapped = false
    for j = 0 to n-2-i:
      if L[j] > L[j+1]:
        swap(L[j], L[j+1])
        swapped = true
    if not swapped: break  // 提前终止：无交换说明已有序
```

**手推示例**：排序 [5, 2, 4, 6, 1, 3]

```
第1趟: [5,2,4,6,1,3] → 比较5>2交换 → [2,5,4,6,1,3] → 5>4交换 → [2,4,5,6,1,3]
       → 5<6不动 → 6>1交换 → [2,4,5,1,6,3] → 6>3交换 → [2,4,5,1,3,|6]
       结果：最大值6冒泡到末端

第2趟: [2,4,5,1,3] 范围内操作
       → 2<4不动 → 4<5不动 → 5>1交换 → 5>3交换 → [2,4,1,3,|5,6]

第3趟: [2,4,1,3] → 4>1交换 → 4>3交换 → [2,1,3,|4,5,6]

第4趟: [2,1,3] → 2>1交换 → 2<3不动 → [1,2,|3,4,5,6]

第5趟: [1,2] → 1<2不动，swapped=false → 提前终止！
```

| 复杂度 | 值 | 直觉解释 |
|--------|----|----------|
| **最好** | O(n) | 已有序，第一趟扫完无交换直接退出 |
| **最坏** | O(n²) | 完全逆序，每趟只能确定一个元素位置 |
| **稳定** | ✅ | 只有严格 `>` 才交换，相等元素不会互换位置 |

> [!note] 冒泡排序的实际意义
> 工程中几乎不用冒泡排序（交换次数多、cache 不友好）。它的教学价值在于：
> 1. 最简单的 O(n²) 排序，容易理解正确性
> 2. `swapped` 标志是**自适应排序**的典型设计——能检测"已有序"并提前退出
> 3. 冒泡的每趟保证至少一个元素就位 → 这是**不变量思维**的练习

## 快速排序（★★★ 重点）

**核心直觉**：选一个"裁判"（基准），把所有比它小的放左边，比它大的放右边。裁判本身就到了最终位置。然后递归地对左右两部分做同样的事。

**思想**：选基准元素，划分为左（≤基准）右（>基准）两部分，递归排序。

### SPLIT（划分）算法 — 详细图解

```
SPLIT(A, low, high):
  x = A[low]          // 取第一个元素为基准
  while low < high:
    while low < high AND A[high] > x: high--   // 从右找小于等于x的
    A[low] = A[high]                            // 填到左边空位
    while low < high AND A[low] ≤ x: low++     // 从左找大于x的
    A[high] = A[low]                            // 填到右边空位
  A[low] = x           // 基准归位
  return low           // 返回基准的最终位置
```

**划分的"挖坑填数"过程 — 完整手推**：

以 A = [49, 38, 65, 97, 76, 13, 27] 为例，基准 x=49：

```
初始状态:  [49, 38, 65, 97, 76, 13, 27]    x=49
            ↑low                      ↑high

步骤1: high 从右找 ≤49 的：A[6]=27 ≤ 49 → 停
       A[low]=A[high]: [27, 38, 65, 97, 76, 13, 27]
                        ↑low                  ↑high

步骤2: low 从左找 >49 的：A[1]=38≤49跳过, A[2]=65>49 → 停
       A[high]=A[low]: [27, 38, 65, 97, 76, 13, 65]
                            ↑low              ↑high

步骤3: high 从右找 ≤49 的：A[5]=13≤49 → 停
       A[low]=A[high]: [27, 38, 13, 97, 76, 13, 65]
                            ↑low          ↑high

步骤4: low 从左找 >49 的：A[3]=97>49 → 停
       A[high]=A[low]: [27, 38, 13, 97, 76, 97, 65]
                                ↑low  ↑high

步骤5: high 从右找 ≤49 的：A[4]=76>49跳过, high-- → high=3, low=high → 退出循环

归位: A[3]=x=49: [27, 38, 13, 49, 76, 97, 65]
                              ↑ 基准在最终位置！

结果：左半部 [27,38,13] 全 ≤ 49；右半部 [76,97,65] 全 > 49
```

**关键性质**：一趟划分后，基准元素 49 到达了它在最终排序结果中的**确切位置**。

### 快速排序主算法

```
QuickSort(A, low, high):
  if low < high:
    w = SPLIT(A, low, high)
    QuickSort(A, low, w-1)    // 递归排序左半部
    QuickSort(A, w+1, high)   // 递归排序右半部
```

### 递归树与复杂度分析

```
最好情况（每次均匀二分）：        最坏情况（每次极端划分）：
         [n]                              [n]
        /    \                           /    \
     [n/2]  [n/2]                      [0]   [n-1]
     /  \    /  \                            /    \
  [n/4]...                                [0]   [n-2]
                                                 ...
  深度：log₂n                         深度：n-1
  每层工作量：O(n)                     每层工作量：递减
  总计：O(nlog₂n)                      总计：O(n²)
```

| 情形 | 递推方程 | 复杂度 | 何时发生 |
|------|----------|--------|----------|
| **最好/平均** | T(n) = 2T(n/2) + Θ(n) | **O(nlog₂n)** | 基准大致在中间 |
| **最坏** | T(n) = T(n-1) + Θ(n) | **O(n²)** | 数组已排序/逆序且总取首元素为基准 |

| 项目 | 说明 |
|------|------|
| **空间复杂度** | O(log₂n) 平均（递归栈）；最坏 O(n)（退化为线性递归） |
| **稳定性** | ❌ 不稳定（划分时的覆盖式移动可能改变相等元素顺序） |

### 为什么快排"平均最快"？ — 工程视角

| 优势因素 | 解释 |
|----------|------|
| **cache 友好** | 划分是对连续内存的顺序扫描，L1/L2 命中率高 |
| **分支预测好** | 内层循环方向单一（high-- 或 low++），CPU 分支预测器容易学习 |
| **原地操作** | 不需要辅助数组（归并需要 O(n) 额外空间） |
| **常数因子小** | 每次比较只做一次 `<` 判断，不像堆排序还要比较两个子结点 |
| **自然递归** | 子问题独立，天然适合并行化 |

### 快排优化策略

| 策略 | 目的 | 做法 |
|------|------|------|
| **随机化选基准** | 避免最坏情况 | `swap(A[low], A[random(low,high)])` 后再划分 |
| **三数取中** | 更稳定的基准选择 | 取 A[low], A[mid], A[high] 的中位数 |
| **小规模切换插入** | 减少递归开销 | 当 high-low < 16 时直接用插入排序 |
| **尾递归优化** | 限制栈深度 | 先递归较短的一半，另一半用循环代替递归 |
