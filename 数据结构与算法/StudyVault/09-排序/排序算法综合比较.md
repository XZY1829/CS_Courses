# 排序算法综合比较（★★★）

#data-structure #sort #time-complexity #space-complexity #concept

## 概览表（一目了然）
| 条目 | 要点 |
|------|------|
| **稳定排序** | 直接插入、折半插入、冒泡、归并 |
| **不稳定排序** | Shell、快速、直接选择、堆 |
| **最优平均** | 快排、堆排序、归并 — 均 O(nlog₂n) |
| **原地排序** | 直接插入、Shell、冒泡、快排、直接选择、堆 |
| **需额外空间** | 归并 O(n)、锦标赛 O(n)、快排 O(logn) 栈 |

| 算法 | 最好时间 | 最坏时间 | 平均时间 | 空间 | 稳定 |
|------|----------|----------|----------|------|------|
| **直接插入** | O(n) | O(n²) | O(n²) | O(1) | ✅ |
| **折半插入** | O(nlog₂n) | O(n²) | O(n²) | O(1) | ✅ |
| **Shell** | — | — | O(n^1.3) | O(1) | ❌ |
| **冒泡** | O(n) | O(n²) | O(n²) | O(1) | ✅ |
| **快速排序** | O(nlog₂n) | **O(n²)** | **O(nlog₂n)** | O(log₂n) | ❌ |
| **直接选择** | O(n²) | O(n²) | O(n²) | O(1) | ❌ |
| **锦标赛** | O(nlog₂n) | O(nlog₂n) | O(nlog₂n) | O(n) | ✅ |

| **归并排序** | O(nlog₂n) | O(nlog₂n) | **O(nlog₂n)** | O(n) | ✅ |

## 按特性分类

### 按时间复杂度

| 级别 | 算法 |
|------|------|
| **O(n²)** | 直接插入、折半插入、冒泡、直接选择 |
| **O(nlog₂n)** | 快排（平均）、堆排序、归并、锦标赛 |
| **介于两者** | Shell 排序 O(n^1.3) |

### 按稳定性

| 稳定 | 不稳定 |
|------|--------|
| 直接插入、折半插入、冒泡、归并、锦标赛 | Shell、快排、直接选择、堆排序 |

> [!tip] 记忆口诀
> **不稳定**：**"快 选 Shell 堆"**（快速排序、选择排序、Shell排序、堆排序）

### 按空间开销

| O(1) 原地 | O(logn) | O(n) |
|-----------|---------|------|
| 直接插入、折半插入、Shell、冒泡、直接选择、堆排序 | 快排（栈） | 归并、锦标赛 |

## 适用场景建议

| 场景 | 推荐算法 | 理由 |
|------|----------|------|
| **小规模数据 (n ≤ 50)** | 直接插入 | 简单，常数小 |
| **基本有序** | 直接插入 / 冒泡 | 接近 O(n) |
| **大规模随机数据** | 快速排序 | 平均最快 |
| **要求最坏 O(nlogn)** | 堆排序 / 归并 | 不退化 |
| **要求稳定** | 归并排序 | 稳定 + O(nlogn) |
| **空间受限** | 堆排序 | O(1) + O(nlogn) |
| **外排序** | 归并排序 | 顺序访问，适合磁盘 |

### 深度决策指南 — "为什么选它"

面试和实际工程中，不能只背表格，需要能**推导**出选择。以下是决策链：

```
输入规模 n？
├── n ≤ 50（小规模）
│   └── 直接插入排序
│       WHY: O(n²) 在小 n 时常数项占主导，插入排序代码极简、无递归开销、
│            cache 友好（连续内存操作），实测比 O(nlogn) 算法更快
│
├── n > 50 且数据基本有序？
│   └── 直接插入排序
│       WHY: 内层循环几乎不执行，退化为 O(n) 线性扫描
│       反例: 千万别用快排——已排序数据是快排的最坏情况！
│
├── n > 50 且要求稳定？
│   ├── 空间足够 → 归并排序
│   │   WHY: 唯一的 O(nlogn) 稳定排序
│   └── 空间不足 → 无完美方案
│       妥协: 链表归并（不需要 O(n) 额外数组）或使用 TimSort 变体
│
├── n > 50 且空间严格受限（O(1)）？
│   └── 堆排序
│       WHY: 唯一的 O(nlogn) + O(1) 空间的算法
│       代价: 常数因子大、cache 不友好
│
├── n > 50 且需要最坏保证？
│   └── 堆排序（或归并排序）
│       WHY: 快排最坏 O(n²)，虽然概率极低但实时系统不允许
│       应用: 嵌入式系统、实时调度、安全关键系统
│
└── n > 50 一般情况？
    └── 快速排序（随机化 + 三数取中 + 小规模切插入）
        WHY: 平均常数最小、cache 友好、分支预测好
        工程实践: C++ std::sort = IntroSort（快排主体 + 堆排序兜底 + 插入排序扫尾）
```

### 工业级排序算法（面试加分项）

| 算法 | 使用者 | 策略 |
|------|--------|------|
| **IntroSort** | C++ `std::sort` | 快排为主；递归深度超 2log₂n 时切堆排序；小规模切插入 |
| **TimSort** | Python `sorted()`, Java `Arrays.sort(Object[])` | 自然归并变体；利用已有序的"run"；小规模切插入 |
| **pdqsort** | Rust `sort_unstable` | 快排+堆排序+插入；对已排序数据特别优化到 O(n) |

**共同思想**：没有"银弹"排序，工业级实现都是**混合策略**——根据实际数据特征动态选择子算法。

## 排序下界定理

> [!important] 基于比较的排序下界
> 任何基于比较的排序算法，其最坏情况下的比较次数至少为 **Ω(nlog₂n)**。
> 因此快排、堆排序、归并排序在渐进意义上是**最优**的。

**证明直觉**：n 个元素有 n! 种排列（即 n! 种可能的输入）。每次比较最多排除一半的可能性（二叉判定树的一次分支）。要区分 n! 种情况，至少需要 log₂(n!) 次比较。由 Stirling 公式：log₂(n!) ≈ nlog₂n - n·log₂e ∈ Ω(nlog₂n)。

**非比较排序如何突破下界？** 它们利用了数据本身的结构信息，不是通过比较来确定位置：

| 算法 | 时间 | 条件 | 原理 |
|------|------|------|------|
| **计数排序** | O(n+k) | 值域 [0,k] 有界且 k 不大 | 用数组下标直接定位 |
| **基数排序** | O(d(n+k)) | d 位数字，每位值域 k | 按位做计数排序 |
| **桶排序** | O(n) 平均 | 数据均匀分布 | 先分桶再桶内排序 |

## 稳定性为什么重要？ — 实际场景

稳定性看似学术概念，实际在以下场景**不可或缺**：

| 场景 | 为什么需要稳定 | 例子 |
|------|---------------|------|
| **多关键字排序** | 先按次关键字排序、再按主关键字稳定排序 → 主关键字相同的保持次关键字顺序 | 先按姓名排序，再按成绩稳定排序 → 同分的人保持姓名字母序 |
| **数据库排序** | 用户先按时间排序再按类型排序 → 同类型保持时间序 | SQL 多级 ORDER BY |
| **UI 排序** | 用户反复点击列头排序 → 前一次排序结果应作为相同元素的顺序保留 | 电子表格排序 |

**不稳定排序的补救**：给每个元素附加原始下标作为"仲裁键"，但增加空间和比较开销。

| 场景/关键词 | 答案 |
|-------------|------|
| "哪些排序平均 O(nlogn)" | **快排、堆排序、归并排序** |

| "稳定且 O(nlogn)" | **归并排序** |

| "排序下界" | **Ω(nlog₂n)（基于比较）** |
| "n 较小适合什么排序" | **直接插入排序** |
