# 选择排序与归并排序（★★★）

#data-structure #sort #selection-sort #merge-sort #heap #concept

## 概览表（一目了然）
| 算法 | 最好 | 最坏 | 平均 | 空间 | 稳定 |
|------|------|------|------|------|------|
| **直接选择** | O(n²) | O(n²) | O(n²) | O(1) | ❌ |
| **锦标赛** | O(nlog₂n) | O(nlog₂n) | O(nlog₂n) | O(n) | ✅ |
| **堆排序** | O(nlog₂n) | O(nlog₂n) | **O(nlog₂n)** | O(1) | ❌ |
| **归并排序** | O(nlog₂n) | O(nlog₂n) | **O(nlog₂n)** | O(n) | ✅ |

## 直接选择排序

**核心直觉**：每一轮从"未排序区"中找出最小的那个，把它放到"已排序区"的末尾。像选课代表一样：每次从剩余同学中选出成绩最好的一个，让他站到队列最前面。

**思想**：每趟从未排序部分选出最小元素，与未排序部分首元素交换。

```
SelectSort(L, left, right):
  for i = left to right-1:
    k = i                          // 假设当前位置最小
    for j = i+1 to right:
      if L[j] < L[k]: k = j       // 找真正的最小值下标
    if k ≠ i: swap(L[i], L[k])    // 放到已排序区末尾
```

**手推示例**：排序 [64, 25, 12, 22, 11]

```
i=0: 未排序区[64,25,12,22,11]，最小值=11(下标4)
     swap(L[0],L[4]) → [11, 25, 12, 22, 64]
     
i=1: 未排序区[25,12,22,64]，最小值=12(下标2)
     swap(L[1],L[2]) → [11, 12, 25, 22, 64]

i=2: 未排序区[25,22,64]，最小值=22(下标3)
     swap(L[2],L[3]) → [11, 12, 22, 25, 64]

i=3: 未排序区[25,64]，最小值=25(下标3)
     k==i，不交换 → [11, 12, 22, 25, 64]
```

| 项目 | 值 | 直觉解释 |
|------|----|----|
| **比较次数** | 始终 n(n-1)/2 | 无论数据如何排列，每趟都必须扫完整个未排序区才能确定最小值 |
| **移动次数** | 最好 0，最坏 3(n-1) | 每次最多一次 swap（3次赋值），比插入/冒泡的逐个移动少得多 |
| **稳定性** | ❌ 不稳定 | 交换可能跳过相等元素（如 [5a, 5b, 3]，swap 后 5a 到了 5b 后面） |

> [!tip] 选择排序的独特优势
> 虽然比较次数总是 O(n²)，但**移动次数最少**（最多 n-1 次交换）。当数据的"比较"代价低而"移动"代价高时（如大记录排序），选择排序有优势。

## 锦标赛排序（树形选择排序）

**思想**：将 n 个元素建成**完全二叉树**，两两比较（类似淘汰赛），胜者（最小值）上升到根。输出根后将对应叶设为 ∞，沿路径重新比较。

- **时间复杂度**：O(nlog₂n)（每次选最小需 log₂n 次比较）
- **空间复杂度**：O(n)（需额外的树结点存储）
- **稳定**：是

> [!warning] 锦标赛排序的缺点
> 辅助空间大（约 2n 个结点），且多次比较中有大量冗余比较。实际中更常用**堆排序**。

---

## 堆排序（★★★ 重点）

**核心直觉**：锦标赛排序用完整二叉树找最小值，但需要 O(n) 额外空间且有冗余比较。堆排序用**数组原地模拟**完全二叉树（最大堆），每次取出堆顶最大元素放到数组末尾，然后修复堆——整个过程不需要额外数组。

利用**堆**结构进行排序，是对锦标赛排序的改进。

### 堆的性质回顾

```
最大堆：每个结点 ≥ 其子结点
数组存储：下标 i 的左子 = 2i+1，右子 = 2i+2，父 = ⌊(i-1)/2⌋

       97
      /    \
    76      65
   /  \    /  \
  49   38 13   27

数组表示: [97, 76, 65, 49, 38, 13, 27]
```

### 排序过程（以最大堆为例）

```
HeapSort(L):
  1. 建堆：将 L[0..n-1] 调整为最大堆
  2. for i = n-1 downto 1:
     a. swap(L[0], L[i])     // 堆顶（最大）与末尾交换 → 最大值就位
     b. siftDown(L, 0, i-1)  // 对 L[0..i-1] 重新调整为最大堆
```

**排序过程图解**（以 [49, 38, 65, 97, 76, 13, 27] 为例）：

```
1. 建最大堆后: [97, 76, 65, 49, 38, 13, 27]

2. swap(97, 27) → [27, 76, 65, 49, 38, 13, |97]  → siftDown → [76, 49, 65, 27, 38, 13, |97]
3. swap(76, 13) → [13, 49, 65, 27, 38, |76, 97]  → siftDown → [65, 49, 13, 27, 38, |76, 97]
4. swap(65, 38) → [38, 49, 13, 27, |65, 76, 97]  → siftDown → [49, 38, 13, 27, |65, 76, 97]
5. swap(49, 27) → [27, 38, 13, |49, 65, 76, 97]  → siftDown → [38, 27, 13, |49, 65, 76, 97]
6. swap(38, 13) → [13, 27, |38, 49, 65, 76, 97]  → siftDown → [27, 13, |38, 49, 65, 76, 97]
7. swap(27, 13) → [13, |27, 38, 49, 65, 76, 97]  → 结束

最终: [13, 27, 38, 49, 65, 76, 97]  "|"右边是已排序区
```

### 筛选法建堆

从最后一个非叶结点 ⌊n/2⌋-1 开始，逐个向前做**下滤（siftDown）**：

```
siftDown(L, start, end):
  i = start, j = 2*i + 1  // j 为左子女
  temp = L[i]
  while j ≤ end:
    if j < end AND L[j] < L[j+1]: j++  // 取较大子女
    if temp ≥ L[j]: break              // 已满足堆性质
    L[i] = L[j], i = j, j = 2*i + 1   // 较大子上移，继续向下
  L[i] = temp
```

### 建堆时间为什么是 O(n) 而非 O(nlogn)？

直觉：大部分结点在树的底层，需要下滤的距离很短。

```
层数(从底往上)    结点数        每个结点最多下滤次数
第0层(叶子)      ~n/2         0（不需处理）
第1层            ~n/4         1
第2层            ~n/8         2
...
第k层            ~n/2^(k+1)   k

总工作量 = Σ (n/2^(k+1)) × k = n × Σ k/2^(k+1) ≈ n × 2 = O(n)
```

### 堆排序复杂度

| 项目 | 值 | 说明 |
|------|----|------|
| **建堆** | O(n) | 大部分结点在底层，下滤距离短 |
| **n-1 次取顶+筛选** | 每次 O(log₂n) | 每次从根下滤到叶子 |
| **总时间** | **O(nlog₂n)** | 最好/最坏/平均相同——不会退化！ |
| **空间** | **O(1)** | 原地排序，只需一个 temp 变量 |
| **稳定性** | **❌ 不稳定** | 堆顶与末尾交换会跳过中间的相等元素 |

> [!tip] 堆排序 vs 快速排序 — 如何选择？
> | 维度 | 堆排序 | 快排 |
> |------|--------|------|
> | 最坏时间 | O(nlogn) ✅ | O(n²) ❌ |
> | 平均常数 | 较大（每次比较两个子结点） | 较小（连续内存扫描） |
> | Cache 友好 | ❌（跳跃式访问父子结点） | ✅（连续扫描） |
> | 实际速度 | 慢 20~50% | 更快 |
> | 适用场景 | 需要严格 O(nlogn) 保证时 | 一般情况 |
> 
> **结论**：需要最坏保证选堆排序；追求平均速度选快排。C++ STL 的 `sort()` 实际使用 IntroSort（快排+堆排序+插入排序的混合）。

## 归并排序（★★★ 重点）

**核心直觉**：合并两个已排序的序列非常高效（只需线性扫描）。如果我们把原始数组递归拆分到单元素（天然有序），再逐层合并上来，就能在 O(nlogn) 时间内完成排序——这就是**分治策略**的典范应用。

**思想**：将序列不断二分，直到单元素（天然有序），再**两两归并**成有序序列。

### MERGE 操作 — 归并的核心

将两个有序子数组 A[p..q] 和 A[q+1..r] 合并为一个有序数组：

```
MERGE(A, p, q, r):
  创建辅助数组 B
  s = p, t = q+1, k = p
  while s ≤ q AND t ≤ r:
    if A[s] ≤ A[t]: B[k++] = A[s++]   // 取左边较小的（≤保证稳定性）
    else: B[k++] = A[t++]              // 取右边较小的
  // 拷贝剩余部分（左或右有一边已空）
  将剩余元素拷贝到 B
  A[p..r] = B[p..r]                    // 写回原数组
```

**MERGE 的直觉**：像合并两副已排好的扑克牌——每次比较两副牌顶的牌，取小的放到新牌堆。

### 递归归并排序

```
MergeSort(A, low, high):
  if low < high:
    mid = ⌊(low+high)/2⌋
    MergeSort(A, low, mid)       // 递归排左半
    MergeSort(A, mid+1, high)    // 递归排右半
    MERGE(A, low, mid, high)     // 合并两个有序半部
```

### 完整手推示例

以 [38, 27, 43, 3, 9, 82, 10] 为例：

```
                    [38, 27, 43, 3, 9, 82, 10]
                   /                           \
          [38, 27, 43, 3]                [9, 82, 10]
          /            \                  /         \
     [38, 27]       [43, 3]          [9, 82]      [10]
      /    \         /    \           /    \         |
   [38]   [27]    [43]   [3]      [9]   [82]     [10]
      \    /         \    /           \    /         |
     [27, 38]       [3, 43]         [9, 82]      [10]
          \            /                  \         /
       [3, 27, 38, 43]               [9, 10, 82]
                   \                      /
            [3, 9, 10, 27, 38, 43, 82]
```

**最后一次 MERGE 的详细过程**：合并 [3,27,38,43] 和 [9,10,82]

```
左: [3, 27, 38, 43]    右: [9, 10, 82]    结果: []
     ↑s                      ↑t

比较 3 vs 9:  3≤9 → 取3    结果: [3]         s→27
比较 27 vs 9: 27>9 → 取9   结果: [3,9]       t→10
比较 27 vs 10: 27>10 → 取10 结果: [3,9,10]   t→82
比较 27 vs 82: 27≤82 → 取27 结果: [3,9,10,27] s→38
比较 38 vs 82: 38≤82 → 取38 结果: [3,9,10,27,38] s→43
比较 43 vs 82: 43≤82 → 取43 结果: [3,9,10,27,38,43] s用完
拷贝右边剩余:               结果: [3,9,10,27,38,43,82] ✓
```

### 迭代归并排序（自底向上）

不用递归，从长度 1 开始，每轮将相邻的有序段两两归并：

```
段长=1: [38][27] [43][3] [9][82] [10]
        → [27,38] [3,43] [9,82] [10]

段长=2: [27,38][3,43] [9,82][10]
        → [3,27,38,43] [9,10,82]

段长=4: [3,27,38,43][9,10,82]
        → [3,9,10,27,38,43,82]
```

**优势**：无递归开销，更适合链表排序和外排序。

### 归并排序复杂度

| 项目 | 值 | 说明 |
|------|----|------|
| **递推方程** | T(n) = 2T(n/2) + O(n) | 拆分 O(1) + 合并 O(n) |
| **时间** | **O(nlog₂n)**（所有情况） | 无论数据如何排列都是 nlogn——不会退化 |
| **空间** | **O(n)**（辅助数组 B） | 这是归并排序的主要缺点 |
| **稳定性** | **✅ 稳定** | MERGE 中 `≤` 保证左边的相等元素先被取出 |

### 为什么归并排序时间稳定？

```
递归树每一层：每个元素恰好被比较一次（合并操作总共扫描全部 n 个元素）
递归树深度：固定 log₂n 层（无论数据如何，都是均匀二分）
总计：n × log₂n，与数据分布无关
```

对比快排：快排的划分可能极不均匀（一边0个，一边n-1个），导致递归树深度退化到 n。

> [!tip] 归并排序的工程价值
> | 应用场景 | 为什么选归并 |
> |----------|------------|
> | **链表排序** | 链表不支持随机访问，快排/堆排序效率差；归并只需顺序访问 |
> | **外排序** | 磁盘/SSD 顺序读写快，随机访问慢；归并天然顺序访问 |
> | **稳定性要求** | Java 的 `Arrays.sort(Object[])` 和 Python 的 `sorted()` 都基于归并变体（TimSort） |
> | **并行计算** | 归并的两个子问题完全独立，天然适合并行 |

### 应用扩展：用归并统计逆序对（★★★）

**逆序对**：若 `i < j` 但 `A[i] > A[j]`，则 `(A[i], A[j])` 是一对逆序对。例如 `[3,1,2]` 有 `(3,1)` 和 `(3,2)`，共 2 对。

**核心直觉**：MERGE 本来就要比较左右两段的当前元素。当**右边当前值更小**、准备取出右边时，说明左边还没取完的那些元素全都比它大，且它们的下标都更靠前——于是**一次就能数出多对**逆序，不必两两枚举。

左右两段各自已经有序。一次 MERGE 中能直接发现的，是「左段某元素 × 右段某元素」这类**跨段**逆序；段内逆序已在递归排序子问题时累计过。

```
MERGE_COUNT(A, p, q, r):          // 返回本层新增的跨段逆序对数
  创建辅助数组 B
  s = p, t = q+1, k = p
  count = 0
  while s ≤ q AND t ≤ r:
    if A[s] ≤ A[t]:
      B[k++] = A[s++]             // 取左边：不产生新逆序
    else:
      B[k++] = A[t++]             // 取右边：左边剩余都比它大
      count += (q - s + 1)        // 关键：左段还剩几个，就加几
  拷贝剩余元素到 B，写回 A
  return count
```

**为什么加 `q - s + 1`？**

```
左段（已有序）:  [ ...  a_s, a_{s+1}, ..., a_q ]     右段当前: b_t
                  ↑s 还没取完的这一段

此时选 b_t，是因为 b_t < a_s ≤ a_{s+1} ≤ ... ≤ a_q
又因为左段整体在右段之前，所以 (a_s,b_t), (a_{s+1},b_t), ..., (a_q,b_t)
全部是逆序对 → 一次加上「左段剩余个数」= q-s+1
```

**完整手推**：统计 `[3,1,2]` 的逆序对

```
MergeSort([3,1,2])
  ├─ 左半 [3]          → 单元素，逆序 0
  └─ 右半 [1,2]
       ├─ [1] → 0
       └─ [2] → 0
       MERGE [1] 与 [2]：1≤2，取左；拷贝右 → 跨段逆序 0
  MERGE 左[3] 与 右[1,2]：

  左: [3]     右: [1, 2]     count=0
       ↑s          ↑t

  比较 3 vs 1：3 > 1 → 取右边的 1
               左段还剩 1 个（就是 3）→ count += 1  → count=1
               结果暂存: [1]

  比较 3 vs 2：3 > 2 → 取右边的 2
               左段还剩 1 个 → count += 1  → count=2
               结果暂存: [1, 2]

  左段剩余拷贝 3 → [1, 2, 3]

总逆序对 = 各层 count 之和 = 0 + 0 + 2 = 2  ✓
（对应 (3,1) 与 (3,2)）
```

| 项目 | 值 | 说明 |
|------|----|------|
| **时间** | **O(n log₂n)** | 与归并排序同阶：每层 O(n)，共 log₂n 层 |
| **空间** | O(n) | 仍需辅助数组 |
| **对比暴力** | 暴力两重循环 O(n²) | 归并法用有序性把「一对一对查」变成「一次加一段」 |

> [!tip] 考试答法一句话
> 归并合并时，若取右段元素，则它与左段**尚未取出的全部元素**构成逆序对，累加 `leftRemaining`；总复杂度与归并相同，为 O(n log n)。

## 考试/测试常见模式
| 场景/关键词 | 答案 |
|-------------|------|
| "比较次数与初始排列无关的排序" | **直接选择排序（比较始终 n(n-1)/2）** |
| "原地排序且 O(nlogn)" | **堆排序**（空间 O(1)） |
| "稳定的 O(nlogn) 排序" | **归并排序** |
| "建堆的时间复杂度" | **O(n)**（不是 O(nlogn)） |
| "堆排序第一步" | **建最大堆，然后交换堆顶与末尾** |
| "归并排序空间开销" | **O(n) 辅助数组** |
| "用归并统计逆序对" | **取右段时加左段剩余个数；O(n log n)** |
