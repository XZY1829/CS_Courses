# 线性表与顺序表（★★★）

#data-structure #linear #sequential-list #time-complexity #concept

## 概览表（一目了然）
| 条目 | 要点 |
|------|------|
| **定义** | n(n≥0) 个元素 a₁…aₙ 的有限序列 L=(a₁,…,aₙ) |
| **逻辑特征** | 有且仅有一个开始结点、一个终端结点；中间结点一对一前后关系 |
| **顺序表** | 逻辑顺序 = 物理顺序，连续存储 |
| **定位公式** | Loc(aᵢ) = V₀ + i×m（V₀ 为基址偏移） |
| **查找** | 顺序搜索 O(n)；按位访问 O(1) |
| **插入/删除** | 需移动元素，平均 O(n) |

## 线性表的逻辑结构（2.1）

**线性表**：由 n(n≥0) 个数据元素 a₁, a₂, …, aₙ 组成的有限序列。
- n = 0 → **空表**；n > 0 → L = (a₁, a₂, …, aₙ)
- a₁ 为**表头**，aₙ 为**表尾**；aᵢ 为**表项**

**逻辑特征**（非空表）：
1. 有且仅有一个开始结点 a₁（无直接前趋，有后继 a₂）
2. 有且仅有一个终端结点 aₙ（无直接后继，有前趋 aₙ₋₁）
3. 内部结点 aᵢ (2≤i≤n-1) 有且仅有一个直接前趋和一个直接后继

```
a₁ → a₂ → a₃ → … → aₙ
表头              表尾
```

- 元素可含多个**数据项** → 称**记录**；大量记录的线性表称**文件**
- 分**有序表**与**无序表**（按元素值是否有序）

## 顺序表（2.2）

**顺序表（SeqList）**：把线性表结点按**逻辑顺序**依次存放在**地址连续**的存储单元中。

**地址关系**：Loc(aᵢ₊₁) = Loc(aᵢ) + m（m 为每个元素占用的字节数）

**随机访问公式**：
```
Loc(aᵢ) = (i-1)×m + Loc(a₁) = V₀ + i×m
```
其中 V₀ = Loc(a₁) - m，已知基址与元素大小即可 O(1) 定位第 i 个元素。

### 静态 vs 动态存储

| 类型 | 特点 |
|------|------|
| **静态** | `T data[maxSize]` 固定数组 |
| **动态** | `T *data` + maxSize，可 reSize 扩容 |

### 核心操作与复杂度

| 操作 | 实现要点 | 时间复杂度 |
|------|----------|-----------|
| **Search(x)** | 从表头到表尾顺序比较 | O(n) |
| **Locate(i)** | 直接下标 i-1 访问 | O(1) |
| **Insert(i, x)** | i 合法且未满；j 从 n 到 i 后移，再写入 | 移动 n-i+1 项，平均 **O(n)** |
| **Remove(i, x)** | 取出 aᵢ，i+1…n 前移 | 移动 n-i 项，平均 **O(n)** |

### 插入移动次数分析

在第 i 个位置插入（1≤i≤n+1），需移动 **n-i+1** 个元素。
各位置等概率时，平均移动次数 AMN = **n/2**。

### 删除移动次数分析

删除第 i 个元素，需前移 **n-i** 个元素。
各位置等概率时，平均移动次数 AMN = **(n-1)/2**。

### 顺序查找比较次数

- 成功：位置 i 比较 i 次；等概率时 ACN = **(1+n)/2**
- 失败：比较 **n** 次

### 顺序表优缺点

| 优点 | 缺点 |
|------|------|
| 实现简单，支持**随机访问** O(1) | 插入删除需**大量移动** O(n) |
| 无需指针，无结构性开销 | 需**预先分配**固定空间 |
| 逻辑与物理一致，存取快 | 长度难估计时可能浪费或溢出 |

> [!warning] 集合运算复杂度
> 用顺序表实现集合并：对每个 LB 元素在 LA 中 Search + 可能 Insert → **O(m×n)**。交集类似 **O(m×n)**。

## 数组动态扩容与均摊分析（★★★）

上面"静态 vs 动态存储"提到动态顺序表可以 reSize 扩容，但扩容的**时间代价**是多少？为什么说"均摊 O(1)"？它和"每次都 O(1)"有什么区别？

### 扩容策略：倍增法

当数组满了（`n == maxSize`）需要插入新元素时：
1. 分配一个**2 倍大小**的新数组（也有用 1.5 倍的，如 C++ `std::vector`）
2. 将旧数组的 n 个元素**全部拷贝**到新数组 → 这一步是 O(n)
3. 释放旧数组，指向新数组

```
初始: [_ _ _ _]  maxSize=4
插入4个: [a b c d]  n=4, 满了！
扩容:    [a b c d _ _ _ _]  maxSize=8, 拷贝了 4 个元素
继续插入4个: [a b c d e f g h]  n=8, 又满了！
扩容:    [a b c d e f g h _ _ _ _ _ _ _ _]  maxSize=16, 拷贝了 8 个元素
```

### 为什么均摊 O(1)？

**关键观察**：扩容不是每次插入都发生，而是越来越少发生。

假设从空数组开始，连续插入 n 个元素，倍增策略下扩容发生在第 4、8、16、32、…次插入时。

总拷贝次数 = 4 + 8 + 16 + … + n/2 + n（最后一次扩容拷贝 n 个）

这是一个等比数列求和：
```
S = 1 + 2 + 4 + 8 + … + n = 2n - 1 < 2n
```

所以 n 次插入的**总代价** < 2n（拷贝）+ n（写入）= 3n → **均摊到每次插入 = 3n/n = O(1)**

### 均摊 O(1) ≠ 每次都 O(1)

| | 每次都 O(1) | 均摊 O(1) |
|--|-------------|-----------|
| **含义** | 任意一次操作都不超过常数时间 | n 次操作的**总时间** ≤ c·n |
| **单次最坏** | O(1) | 可能高达 **O(n)**（扩容那一次） |
| **举例** | 链表尾插（有尾指针） | 动态数组尾插 |
| **实际感受** | 每次都很快 | 绝大多数很快，偶尔卡一下 |

> [!tip] 直觉记忆
> **均摊 O(1) 像"分期付款"**：扩容时一次性还了一大笔（O(n)），但这笔钱是之前 n 次廉价插入"攒下来"的。平均到每次只有 O(1)。

### 如果不倍增而是每次加固定值？

如果每次满了就扩容 `maxSize += k`（加法扩容），那么 n 次插入的总拷贝：
```
k + 2k + 3k + … + (n/k)·k = k · (1+2+…+n/k) = O(n²/k) = O(n²)
```
均摊到每次 = O(n) —— **比倍增差一个量级**。所以实际系统（如 C++ vector、Java ArrayList、Python list）都用**倍增**策略。

| 场景/关键词 | 答案 |

| "线性表逻辑特征" | 唯一表头、唯一表尾、中间**一对一**前后关系 |
