# 链表（★★★）

#data-structure #linear #linked-list #concept

## 概览表（一目了然）
| 条目         | 要点                                     |
| ---------- | -------------------------------------- |
| **结点结构**   | data（数据域）+ link（指针域）                   |
| **单链表**    | 结点可不连续，first 指向首元结点                    |
| **头结点**    | 不存数据，统一空表与非空表操作                        |
| **建表**     | **前插法**（逆序）/ **后插法**（正序，需尾指针）          |
| **循环链表**   | 尾结点 link → 表头；可用 rear 尾指针 O(1) 访问首尾    |
| **双向链表**   | lLink + data + rLink，通常**带头结点的双向循环链表** |
| **vs 顺序表** | 插入删 O(1)（定位后）；按序号访问 O(n)               |

## 单链表（2.3）

每个元素由**结点（Node）**构成：`element | link`

```
first → [a₁|•] → [a₂|•] → … → [aₙ|∧]
                              表尾
```

- 结点**物理位置可不连续**，表长可动态扩充
- 插入/删除只需修改**指针**，不需移动元素

### 三种插入情形

```
(1) 表头插入:  new→link = first;  first = new;

(2) 中间插入:  new→link = current→link;  current→link = new;

(3) 表尾插入:  同上，current 指向最后一个结点
```

### 删除操作

找到待删结点的前驱 p，令 `p→link = q→link`，释放 q。

> [!warning] 空表与边界
> 无头结点时需单独处理**空表**、**删首元**等特殊情况。**带头结点**可统一操作。

### 带头结点的单链表

```
first → [头|•] → [a₁|•] → … → [aₙ|∧]
         ↑
      不存有效数据，仅标志表头
```

- 空表：first→link = NULL
- 表头插入：`new→link = p→link; p→link = new;`

### 深入理解：有无头结点对插入/删除边界的影响（★★★）

这是单链表中**最容易写出 bug 的地方**。核心问题在于：**没有头结点时，表头位置本身就是特殊的**——它存储在一个独立的指针变量 `first` 中，而不是某个结点的 `link` 字段里。一旦操作涉及表头，就需要单独修改 `first`，与操作其他位置的代码**不统一**。

#### 无头结点：必须逐一处理的边界

**① 插入操作 — 三种不同写法**

```cpp
// 情形 A：在空表中插入（表为空 → first == NULL）
newNode->link = NULL;
first = newNode;          // 修改的是 first 指针本身

// 情形 B：在表头插入（在第 1 个元素之前）
newNode->link = first;
first = newNode;          // 修改的还是 first

// 情形 C：在中间/表尾插入（在 p 指向的结点之后）
newNode->link = p->link;
p->link = newNode;        // 修改的是 p->link
```

> 注意：情形 A 和 B 的代码碰巧可以合并（`newNode->link = first; first = newNode;`），但它们的**语义不同**，而且都与情形 C 的写法不一样——C 修改的是 `p->link`，A/B 修改的是 `first`。

**② 删除操作 — 必须分两种情况**

```cpp
// 情形 A：删除首元结点（first 指向的那个）
Node* q = first;
first = first->link;     // 修改 first
delete q;

// 情形 B：删除非首元结点（p 是待删结点 q 的前驱）
p->link = q->link;       // 修改 p->link
delete q;
```

> 删除首元时必须改 `first`，删除其他结点时改前驱的 `link`——两套代码。如果**忘了判断是否在删表头**，就会导致 `first` 没有更新，链表断裂。

**③ 完整的「按位置插入」函数（无头结点）**

```cpp
bool Insert(Node*& first, int pos, int val) {
    if (pos < 1) return false;

    Node* newNode = new Node(val);

    if (pos == 1) {                    // ← 特殊情况：表头
        newNode->link = first;
        first = newNode;
        return true;
    }

    Node* p = first;
    for (int i = 1; i < pos - 1 && p != NULL; i++)
        p = p->link;

    if (p == NULL) { delete newNode; return false; }

    newNode->link = p->link;           // ← 通用情况
    p->link = newNode;
    return true;
}
```

注意 `pos == 1` 那个 `if` 分支——这就是无头结点带来的**额外代码路径**。

#### 有头结点：统一为一种写法

头结点的关键作用：**让 `first` 永远指向一个固定的结点**，真正的第 1 个数据元素存储在 `first->link` 指向的结点中。这样，"在第 i 个位置插入"永远等价于"找到第 i-1 个结点 p，修改 `p->link`"——而 i=1 时，第 0 个结点就是头结点本身，`p` 就是 `first`。

**① 插入操作 — 只有一种写法**

```cpp
// 无论在表头、中间还是表尾，代码完全相同：
newNode->link = p->link;
p->link = newNode;
// 其中 p 为插入位置的前驱
// 当插在第 1 个位置时，p 就是头结点 first
```

**② 删除操作 — 也只有一种写法**

```cpp
// 无论删首元还是其他元素：
Node* q = p->link;       // q 是待删结点
p->link = q->link;
delete q;
// p 为 q 的前驱，删首元时 p 就是头结点 first
```

**③ 完整的「按位置插入」函数（有头结点）**

```cpp
bool Insert(Node* first, int pos, int val) {
    if (pos < 1) return false;

    Node* p = first;                   // 从头结点出发
    for (int i = 0; i < pos - 1 && p != NULL; i++)
        p = p->link;

    if (p == NULL) return false;

    Node* newNode = new Node(val);
    newNode->link = p->link;           // ← 只有这一种写法
    p->link = newNode;
    return true;
}
```

**对比无头结点版本：没有 `if (pos == 1)` 的特判分支。**

#### 对比总结

| 场景 | 无头结点 | 有头结点 |
|------|----------|----------|
| **空表表示** | `first == NULL` | `first->link == NULL`（头结点始终存在） |
| **插入到第 1 个位置** | 需特判，修改 `first` | 与其他位置**完全一致** |
| **删除第 1 个元素** | 需特判，修改 `first` | 与其他位置**完全一致** |
| **函数参数** | 需传 `Node*&`（引用）因为可能改 `first` | 传 `Node*` 即可（`first` 不变） |
| **代码分支数** | 2（表头 + 其他） | 1（统一） |
| **出 bug 概率** | 高（忘判表头是经典错误） | 低 |

> [!tip] 一句话记忆
> **头结点的本质是：把 `first` 这个"孤儿指针"变成一个正常结点的 `link` 字段**，从而让所有位置的插入/删除都归结为"修改某个结点的 `link`"这同一种操作。代价仅仅是多占一个结点的空间。

### 建表方法

| 方法 | 过程 | 结果顺序 |
|------|------|----------|
| **前插法** | 每读入一值，插入 first 之后（表头侧） | 与输入**相反** |
| **后插法** | 维护 last 尾指针，新结点接在 last 之后 | 与输入**相同** |

### 单链表操作复杂度

| 操作 | 时间复杂度 |
|------|-----------|
| 按值 Search | O(n) |
| 按序号 Locate(i) | O(n) |
| Insert（定位后） | O(1) |
| Remove（定位后） | O(1) |
| 整体 Insert/Remove（含定位） | O(n) |

**核心洞察**：链表优势不在"找第 i 个"（仍是 O(n)），而在**找到位置后**插入删除无需移动元素。

## 循环链表（2.4）

**循环链表**：尾结点 link **指向表头**（而非 NULL），头尾相接。

```
first → [a₁|•] → [a₂|•] → … → [aₙ|•]─┐
  ↑___________________________________|
```

- 从任一结点可遍历全体
- 扫描终止条件：`current != first`（而非 NULL）
- **尾指针 rear**：`rear→next→next` 为 a₁，`rear` 为 aₙ，访问首尾均 **O(1)**

**应用**：Josephus 问题（n 人环，每数 m 出列）——循环链表或循环数组 `(t+1)%maxSize` 实现。

---

## 双向链表（2.4）

结点结构：**lLink | data | rLink**（前驱指针 + 数据 + 后继指针）

- 通常采用**带头结点的双向循环链表**
- 对称性：`p == p→lLink→rLink == p→rLink→lLink`

### 后继方向插入（在 current 之后）

```
new→rLink = current→rLink;
current→rLink = new;
new→rLink→lLink = new;
new→lLink = current;
```

### 删除 current

```
current→rLink→lLink = current→lLink;
current→lLink→rLink = current→rLink;
```

- 可沿**前驱或后继**两个方向搜索/定位（参数 d 控制方向）
- 删除已知结点时无需找前驱（对比单链表）

## 顺序表 vs 链表

| 维度 | 顺序表 | 链表 |
|------|--------|------|
| **存储** | 连续数组，预分配 | 动态分配，指针连接 |
| **按序号访问** | **O(1)** | **O(n)** |
| **按值查找** | O(n) | O(n) |
| **插入/删除** | O(n) 移动元素 | 定位 O(n) + 改指针 **O(1)** |
| **空间开销** | 无指针开销 | 每结点额外指针 |
| **适用场景** | 静态数据、频繁随机访问 | 频繁插入删除、长度难估计 |

> [!warning] 本章小结中的表述
> 教材指出：链表插入删除"时间代价 O(n)"是**含定位**的整体代价；若**不考虑查找**，仅改指针则为 **O(1)**。

---

## 静态链表（补充）

用数组实现链式逻辑：每个元素含 `data + link`（link 为**数组下标**而非地址）。
- 0 号单元为表头结点
- 非循环：尾 link = -1；循环：尾 link = 0
- 为**无指针语言**设计，插入删除不移动元素，仅改 link

## 考试/测试常见模式
| 场景/关键词 | 答案 |
|-------------|------|
| "前插法建表顺序" | 输入 1,2,3 → 链表 **3→2→1** |
| "后插法建表顺序" | 输入 1,2,3 → 链表 **1→2→3** |
| "头结点作用" | **统一空表与非空表**操作，简化插入删除 |
| "单链表表头插入两句" | `new→link=first; first=new;` |
| "循环链表判结束" | `current != first` |
| "尾指针 rear 优势" | 访问 a₁ 和 aₙ 均为 **O(1)** |
| "双向链表删除" | 改**四个指针**，无需找前驱 |
| "Josephus 问题结构" | **循环链表**或循环数组 |
| "链表第 i 个元素" | **O(n)** 顺序扫描 |
| "稀疏多项式表示" | 链表存 (coef, exp)，节省空间 |
