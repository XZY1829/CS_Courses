## Q1：DQN 为什么需要经验回放和目标网络？少了哪个会怎样？

### DQN 面临的两大核心问题

深度神经网络逼近 $Q^*$ 时，满足**致命三要素**（函数逼近 + 自举 + 离策略），训练天然不稳定。DQN 的两个创新技术分别解决两个不同的不稳定来源。

### 创新技术一：目标网络（Target Network）

**解决的问题**：追逐移动目标

- TD 目标 $y = r + \gamma\max_{a'}\hat{Q}(s',a';w)$ 依赖于 $w$ 本身
- 每次更新 $w$，目标 $y$ 也随之变化 → "追逐移动的靶子"
- 造成训练振荡甚至发散

**解决方案**：

| 网络 | 参数 | 作用 | 更新方式 |
|------|------|------|---------|
| 在线网络 | $w$ | 选择动作 + 梯度更新 | 每步 SGD |
| 目标网络 | $w^-$ | 计算 TD 目标 | 每 N 步复制 $w^- \leftarrow w$ |

$$J(w) = E\left[(r + \gamma\max_{a'}\hat{Q}(s',a';w^-) - \hat{Q}(s,a;w))^2\right]$$

**效果**：解耦"选择动作（在线网络）"和"评估动作（目标网络）"的过程，避免追逐移动的高误差目标，降低高方差的影响。

### 创新技术二：经验回放（Experience Replay）

**解决的问题**：数据时序相关性

- 智能体连续采样的数据 $(s_t, a_t, r_t, s_{t+1})$ 具有强时序相关性
- 违反 SGD 的 i.i.d. 假设 → 训练不稳定
- 连续数据相似度高 → 网络容易过拟合到近期经验

**解决方案**：

1. 每次选择动作后，存储样本 $(s, a, r, s')$ 到经验池（Replay Buffer）
2. 每次迭代从经验池中**随机均匀**抽取 mini-batch 更新网络

**效果**：
- 降低样本次序关联性 → 稳定收敛
- 重复利用历史数据 → 提高样本效率
- 减少计算量 → 加快训练

### 少了哪个会怎样？

| 缺失组件 | 后果 |
|---------|------|
| **去掉目标网络** | TD 目标随每次更新变化 → 优化目标不稳定 → Q 值估计振荡发散；过高估计问题加剧（在线网络同时选择和评估动作） |
| **去掉经验回放** | 训练数据高度相关 → 梯度估计有偏 → 网络过拟合近期经验 → 灾难性遗忘早期学到的知识；样本效率极低（数据用一次就丢） |
| **两者都去掉** | 回退到朴素的非线性 Q-Learning + TD，几乎无法在复杂任务上收敛（Atari 早期实验已验证） |

### 二者的互补关系

```
经验回放：解决数据层面的问题（样本相关性）
目标网络：解决优化层面的问题（目标不稳定）
二者共同作用 → 稳定训练
```

## Q2：PPO 的 Clip 机制和 KL 惩罚机制各有什么优劣？

### 共同背景：为什么需要约束？

On-Policy 方法样本效率低（数据只能用一次）。PPO 用**重要性采样**实现旧数据多次复用：

$$J^{\theta_k}(\theta) = E_{(s,a)\sim\pi_{\theta_k}}\left[\frac{\pi_\theta(a|s)}{\pi_{\theta_k}(a|s)}A^{\theta_k}(s,a)\right]$$

但当 $\pi_\theta$ 和 $\pi_{\theta_k}$ 差距过大时，重要性权重极端 → 方差爆炸。**必须限制策略更新幅度**。

### PPO-KL（KL 惩罚版本）

$$J_{PPO}^{\theta_k}(\theta) = J^{\theta_k}(\theta) - \beta\text{KL}(\theta, \theta_k)$$

**自适应 $\beta$ 机制**：
- 若 $\text{KL}(\theta, \theta_k) > \text{KL}_{max}$ → 增大 $\beta$（更新太大了，收紧约束）
- 若 $\text{KL}(\theta, \theta_k) < \text{KL}_{min}$ → 减小 $\beta$（更新太保守，放松约束）

| 优点 | 缺点 |
|------|------|
| 有明确的理论基础（KL 散度有信息论含义） | 需要额外计算 KL 散度 |
| 约束是"软"的，更灵活 | 需要调节 $\beta$、$\text{KL}_{max}$、$\text{KL}_{min}$ 三个超参数 |
| 自适应机制可根据训练状态调节约束强度 | $\beta$ 的自适应规则依赖启发式，可能不够稳定 |
| 对策略更新幅度有精确的度量 | 计算开销大（每步需计算 KL 散度） |

### PPO-Clip（裁剪版本，最常用）

记 $r_t(\theta) = \frac{\pi_\theta(a_t|s_t)}{\pi_{\theta_k}(a_t|s_t)}$：

$$J_{PPO2}(\theta) = \sum_{s_t,a_t}\min\left(r_t(\theta)A_t,\;\text{clip}(r_t(\theta), 1-\varepsilon, 1+\varepsilon)A_t\right)$$

**Clip 机制直觉**：
- $A > 0$（好动作），当 $r_t > 1+\varepsilon$ 时截断 → 防止概率过度增加
- $A < 0$（坏动作），当 $r_t < 1-\varepsilon$ 时截断 → 防止概率过度降低

| 优点 | 缺点 |
|------|------|
| **实现极其简单**（只需一个 min + clip 操作） | 没有明确的理论保证（不直接约束 KL） |
| 只需调一个超参数 $\varepsilon$（通常 0.1~0.2） | Clip 边界是"硬"的，不够平滑 |
| 计算开销小（无需计算 KL 散度） | 在某些极端情况下约束可能不够紧 |
| 实践效果优异，工业界广泛采用（如 ChatGPT 的 RLHF） | 对 $\varepsilon$ 的选择有一定敏感性 |
| 标准 SGD 即可优化 | 理论上允许多步累积突破信赖域 |

### 对比总结

| 维度 | PPO-KL | PPO-Clip |
|------|--------|----------|
| 约束类型 | 软惩罚（Lagrangian） | 硬截断 |
| 超参数数量 | 多（$\beta$, $\text{KL}_{max}$, $\text{KL}_{min}$） | 少（仅 $\varepsilon$） |
| 实现复杂度 | 较高 | **极低** |
| 计算开销 | 较大（需计算 KL） | **小** |
| 理论保证 | 更强（有明确 KL 约束） | 较弱（启发式） |
| 实践表现 | 好 | **同样好或更好** |
| 工业应用 | 较少 | **广泛使用** |

**结论**：PPO-Clip 因其简洁性和优异实践效果成为事实标准。PPO-KL 理论更优雅但实现复杂，实际效果并不显著优于 Clip。

## Q3：A3C 的异步更新是否会引入梯度噪声？如何权衡？

### A3C 的异步更新机制

```
Global Network (θ, θ_v)
    ↑ 异步推送梯度 ↑           ↓ 复制参数 ↓
Worker 1 | Worker 2 | ... | Worker n
 Env 1   |  Env 2   | ... |  Env n
```

每个 Worker 的流程：
1. 从全局网络**复制**参数 $\theta' \leftarrow \theta$
2. 与本地环境**交互**，收集一段经验
3. 用本地参数 $\theta'$ **计算**梯度 $d\theta$
4. **异步推送** $d\theta$ 给全局网络
5. 全局网络**立即更新** $\theta \leftarrow \theta + \alpha \cdot d\theta$

### 是否会引入梯度噪声？——会！

**梯度延迟（Stale Gradient）问题**：

- Worker 在步骤 1 复制参数后，全局网络可能已被其他 Worker 更新多次
- Worker 计算梯度用的参数 $\theta'$ 已经**过时**
- 推送到全局的梯度实际上是**针对旧参数**计算的 → 对当前参数来说是"噪声"

**形式化**：Worker $i$ 推送的梯度为 $\nabla_{\theta'_i} J(\theta'_i)$，但全局参数已从 $\theta'_i$ 变为 $\theta_{current}$。当 $\theta_{current} \neq \theta'_i$ 时，这个梯度方向可能不再是全局参数的正确下降方向。

### 噪声的来源

| 噪声来源 | 说明 |
|---------|------|
| 参数延迟 | Worker 使用的参数与全局参数不同步 |
| 环境多样性 | 不同 Worker 在不同环境状态下采样 |
| 更新冲突 | 多个 Worker 同时推送梯度，可能方向矛盾 |

### 如何权衡？——多样性带来的好处 > 噪声的坏处

| 异步带来的好处 | 异步带来的代价 |
|---------------|--------------|
| **数据多样性**：多个 Worker 在不同环境探索，天然打破数据相关性 | 梯度延迟 → 更新方向有噪声 |
| **不需要经验回放**：并行提供的多样性替代了经验回放的功能 | 可能降低收敛精度 |
| **训练速度**：多核 CPU 并行，显著加速 | 异步冲突可能导致偶尔的不稳定 |
| **探索能力**：不同 Worker 探索不同策略区域 | Worker 数量过多时延迟过大 |

### 缓解噪声的手段

1. **熵正则化**：$L = L_{policy} + \lambda L_V - \beta H(\pi)$
   - 策略熵 $H(\pi) = -\sum_a\pi(a|s)\log\pi(a|s)$ 鼓励探索
   - 防止某个 Worker 的噪声梯度导致策略过早收敛

2. **梯度累积**：Worker 累积多步梯度后再推送，减少通信频率，让每次推送的梯度更稳定

3. **适当的 Worker 数量**：Worker 数量不宜过多（论文使用 16 个 CPU 核），太多会加剧延迟问题

4. **参数同步频率**：每个 Worker 在每个片段（segment）开始时与全局参数同步，控制延迟上限

### 实验验证

论文结果表明：
- A3C（16 CPU 核）在 57 个 Atari 游戏上的表现**优于** DQN（单 Nvidia K40 GPU）
- 训练时间更短、最终性能更好
- 说明异步并行带来的**数据多样性和训练加速**的收益远大于梯度噪声的代价

### 对比：A3C vs DQN 解决数据相关性的不同路径

| | DQN | A3C |
|--|-----|-----|
| 解决数据相关性的方式 | 经验回放（存储 + 随机采样） | 多 Worker 异步并行 |
| 硬件需求 | GPU + 大内存（存储缓冲区） | 多核 CPU |
| 额外代价 | 内存开销、旧数据过时 | 梯度延迟噪声 |
| 动作空间 | 仅离散 | 离散 + 连续 |
