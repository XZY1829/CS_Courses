# 第三阶段验收清单

## 使用方法

先闭卷作答并录音或让同伴追问，再依据“正确、完整、结构化、能应对追问”四项评分。每项 0—2 分：0 为错误/不会，1 为主体正确但遗漏，2 为完整且能追问。核心清单总分达到 75%，计网与 OS 均不低于 70%，才结束；否则进入对应强化日。

## 计网核心

- [ ] 能从五层模型解释封装、解封装和每层寻址对象。
- [ ] 能区分带宽、吞吐量、传播时延、传输时延、排队时延和 RTT。
- [ ] 能计算 CIDR 网络范围，并解释最长前缀匹配。
- [ ] 能解释同网段/跨网段通信中 IP、MAC、ARP 和网关的变化。
- [ ] 能对比 TCP/UDP，并基于场景做取舍。
- [ ] 能用序号、ACK、重传、窗口解释 TCP 可靠性。
- [ ] 能完整解释三次握手、四次挥手、TIME_WAIT。
- [ ] 能区分流量控制与拥塞控制，并解释慢启动/拥塞避免。
- [ ] 能解释 HTTP 方法、状态码、长连接、缓存和 HTTP/2 多路复用。
- [ ] 能串联证书、密钥协商、对称加密与完整性说明 HTTPS。
- [ ] 能画 DNS 查询和缓存链路。
- [ ] 能写出 TCP 客户端/服务端 Socket 调用顺序。

## OS 核心

- [ ] 能区分程序、进程、线程，以及资源拥有与调度单位。
- [ ] 能解释用户态/内核态、系统调用和上下文切换。
- [ ] 能比较管道、消息队列、共享内存和 Socket IPC。
- [ ] 能说明数据竞争、临界区、互斥与原子性的区别。
- [ ] 能正确使用锁、条件变量、信号量解释生产者消费者。
- [ ] 能列出死锁四条件并给出预防/避免思路。
- [ ] 能解释虚拟地址、页表、TLB、缺页和换页。
- [ ] 能比较分页/分段、内部/外部碎片、多级页表。
- [ ] 能说明进程地址空间的大致区域与栈/堆增长特征。
- [ ] 能区分阻塞/非阻塞与同步/异步两个维度。
- [ ] 能从用户调用 `read` 讲到内核、页缓存、设备与返回。

## 设计模式核心

- [ ] Strategy：可替换算法族，优先组合；能说明与简单函数参数的边界。
- [ ] Observer：一对多通知；能说明生命周期、退订和重入风险。
- [ ] Factory：隔离对象创建；能区分简单工厂、工厂方法、抽象工厂的复杂度。
- [ ] Decorator：运行时叠加职责；能与继承爆炸对比。
- [ ] Adapter：转换接口以复用既有实现；能与 Facade 区分。
- [ ] Singleton：能说出全局状态、测试、并发和生命周期风险，不把它当默认方案。
- [ ] 能从项目中给出 3 个真实场景，并明确说明不用某模式时的替代方案。

## 高频压力题

- [ ] 浏览器输入 URL 后发生了什么？连续讲 15 分钟。
- [ ] TCP 为什么三次握手、四次挥手？如果两次/三次会怎样？
- [ ] TIME_WAIT 太多一定是故障吗？先解释作用，再谈诊断方向。
- [ ] 进程与线程除了“资源开销”还有哪些隔离和并发差异？
- [ ] mutex 与 semaphore 如何选择？condition_variable 为什么要带谓词循环？
- [ ] 一个虚拟地址如何变成物理地址？TLB miss 和 page fault 是一回事吗？
- [ ] 设计模式会不会过度设计？怎样判断一个变化点值得抽象？
