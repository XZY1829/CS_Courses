标准设备
•
设备提供的接⼝(interface) 通常由若⼲寄存器组成
• 状态寄存器(status register): 设备当前的状态
• 命令寄存器(command register): 指示设备执⾏特定的任务
• 数据寄存器(data register): 将数据传递给设备或从设备获取数据

中断机制（Interrupts）
•已经在系统调用（syscalls）和时钟中断（timer）中介绍过中断！
•一旦发出I/O 请求，当前线程进入睡眠状态（其他线程可以被调度运行）
•I/O 完成时，硬件会触发中断，执行中断处理程序
•唤醒发起请求的线程
利用中断减少CPU开销
利用中断减少CPU开销（续）
利用中断减少CPU开销（续）
•
轮询机制（Programmed I/O，PIO ）：CPU发出请求后无法执行其他任务（忙等待）
•
中断机制：CPU 发出请求后切换执行其他任务（线程2）
利用中断减少CPU 开销（续）
•
中断机制是最优方案吗？
•并非如此。对于快速I/O，轮询（Polling）有时效果更好
•在高频网络场景中，中断可能导致活锁（Livelock）问题
•
其他优化方法：
•混合机制（Hybrid）：先轮询一小段时间，再考虑使用中断
•中断合并（Coalescing）：合并多个中断事件，减少中断次数
•
理想方案：
•不让CPU 参与数据传输！
•使用直接内存访问（Direct Memory Access, DMA）
Direct Memory Access (DMA)
直接内存访问(Direct Memory Access, DMA): 依靠⼀个特殊的硬件控制器来协调内存
和设备寄存器之间的数据传输
• 操作系统⾸先向DMA 发送指令(where the data lives in, how much data to copy, 
and which device to send it to …) 
• 随后由DMA 和I/O 设备进⾏交互
• 当I/O 操作结束时，DMA 控制器向CPU 发送中断信号

解决方案：DMA（直接内存访问）负责数据拷贝，CPU可以立刻切换进程

CPU如何与设备通信：端口映射（明确指令）
•
每个控制寄存器被分配⼀个I/O端⼝号
•
使⽤明确的I/O指令（在x86上为in和out）
•
这些指令通常是特权指令
CPU如何与设备通信：内存映射
•
内存映射I/O：
•
将所有控制寄存器映射到内存地址空间中
•
每个控制寄存器被分配⼀个唯⼀的内存地址
•
为了访问特定的寄存器，操作系统发出⼀个load指令（读取）或store指
令（写⼊）该地址
•
然后硬件将load/store指令指向到设备⽽不是主存储器
纳入OS：设备驱动程序
•
操作系统创建了⼀个分层的结构视图
‣ 即使在内核内部抽象也是不断使⽤的技术！
•
分层⽅法允许更低层部分容易更改
‣ 例如，⽂件系统的实现独⽴于磁盘类型
•
管理I/O 设备的代码在内核设备驱动程序(device drivers)
‣ 70%的Linux 代码是设备驱动程序，因为有太多不同的设备，每个设备都不同！
‣ 设备驱动程序是内核错误的最常⻅来源
- 这是由于给定的驱动程序可能只被少数系统使⽤，所以它不会被⾼度使⽤
或仔细检查。
