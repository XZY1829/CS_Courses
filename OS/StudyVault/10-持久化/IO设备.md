# I/O 设备（★★）

#persistence #io-device

## 概览表（一目了然）

| 条目 | 要点 |
|------|------|
| 设备接口 | 状态寄存器 + 命令寄存器 + 数据寄存器 |
| 交互方式 | 轮询（PIO）→ 中断 → DMA |
| 通信方式 | 端口映射 I/O vs 内存映射 I/O |
| 软件层次 | 文件系统 → 通用块层 → **设备驱动**（占 Linux 70% 代码） |

## 设备交互方式演进

### 1. 轮询/PIO（忙等待）
CPU 反复检查状态寄存器 → 简单但**浪费 CPU**。

### 2. 中断
发出 I/O 请求后当前线程**睡眠** → I/O 完成时硬件触发中断 → 唤醒线程。

优化：混合机制（先轮询再中断）、中断合并。

### 3. DMA（直接内存访问）
专用硬件控制器负责内存↔设备的数据传输 → CPU 只需发出指令，**不参与数据拷贝**。

## CPU 与设备通信

| 方式 | 实现 | 特点 |
|------|------|------|
| **端口映射** | 专用 I/O 指令（in/out） | 特权指令，端口号寻址 |
| **内存映射** | load/store 到特定内存地址 | 硬件重定向到设备 |

## 设备驱动程序

- 管理 I/O 设备的内核代码
- Linux 70% 代码是设备驱动 → 内核 bug 最常见来源
- 文件系统实现独立于磁盘类型（通过抽象层）

## 考试/测试常见模式

| 场景/关键词 | 答案 |
|-------------|------|
| "PIO 的问题" | CPU **忙等待**，无法做其他事 |
| "DMA 的作用" | 让**专用硬件**处理数据传输，释放 CPU |
| "中断 vs 轮询" | 中断适合慢设备；快速设备轮询可能更好（避免活锁） |
| "设备驱动为什么重要" | 占内核大部分代码，是 bug 最常见来源 |
