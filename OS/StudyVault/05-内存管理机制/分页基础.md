# 分页基础（★★★）

#virtualization #memory #paging

## 概览表（一目了然）

| 条目 | 要点 |
|------|------|
| 核心思想 | 将地址空间分割为**固定大小**的页（Page），物理内存分为页帧（Frame） |
| 优势 | 灵活（无需假设堆栈增长方向）、简便（易管理空闲空间） |
| 地址构成 | 虚拟地址 = VPN（虚拟页号） + Offset（页内偏移） |
| 数据结构 | 页表（Page Table）：VPN → PFN 的映射 |

## 地址转换

```
虚拟地址: | VPN (虚拟页号) | Offset (页内偏移) |
                ↓ 查页表
物理地址: | PFN (物理帧号) | Offset (不变)     |
```

**示例**：64字节地址空间，16字节页面
- 6位虚拟地址 = 2位VPN + 4位Offset
- 虚拟地址 21 = 01|0101 → VPN=1, Offset=5
- 查页表 VPN 1 → PFN 7 → 物理地址 = 7×16+5 = 117

## 页表项（PTE）的标志位

| 标志位 | 含义 |
|--------|------|
| **Valid Bit** | 该页表项是否有效 |
| **Protection Bit** | 读/写/执行权限 |
| **Present Bit** | 页面是否在物理内存中（vs 被换出到磁盘） |
| **Dirty Bit** | 页面自载入后是否被修改过 |
| **Reference/Access Bit** | 页面是否被访问过（用于页面替换） |
| **PFN** | 对应的物理帧号 |

## 页表大小计算

32位地址空间 + 4KB 页面 + 4字节/PTE：
- VPN 位数 = 32 - 12 = **20位** → 2²⁰ = 1M 个页表项
- 页表大小 = 1M × 4B = **4MB/进程**

> [!warning] 分页的性能问题
> 每次内存访问需要**两次**物理内存访问：一次查页表 + 一次访问数据。解决方案：**TLB**。

## x86 页表项

| 位 | 含义 |
|----|------|
| P | 存在位 Present |
| R/W | 读/写 |
| U/S | 用户/超级用户 |
| A | 访问位 |
| D | 脏位 |
| PFN | 页帧号 |

## 考试/测试常见模式

| 场景/关键词 | 答案 |
|-------------|------|
| "分页 vs 分段" | 分页=固定大小、无外部碎片；分段=可变大小、有外部碎片 |
| "页表大小计算" | (地址空间/页大小) × PTE大小 |
| "分页为什么慢" | 每次访问需**两次内存访问**（查页表+访问数据） |
| "VPN 和 PFN" | VPN=虚拟页号(索引页表)；PFN=物理帧号(页表项内容) |
