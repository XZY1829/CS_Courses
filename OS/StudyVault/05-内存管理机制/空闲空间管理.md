# 空闲空间管理（★★）

#virtualization #memory

## 概览表（一目了然）

| 条目 | 要点 |
|------|------|
| 核心问题 | 如何管理变长的空闲空间，避免碎片化 |
| 底层机制 | 分割(Splitting)、合并(Coalescing)、头部块追踪大小 |
| 基本策略 | Best-Fit / Worst-Fit / First-Fit / Next-Fit |
| 高级方法 | 分离列表(Slab)、伙伴分配(Buddy) |

## 底层机制

### 分割（Splitting）
空闲块大于请求 → 拆分为两部分：一部分分配，一部分保留为空闲块。

### 合并（Coalescing）
释放内存时，如果相邻块也是空闲的 → 合并为更大的空闲块。

### 追踪已分配区域大小
- `free(ptr)` 不包含 size 参数 → 分配器在**头部块**中记录大小（+ 魔数用于完整性检查）
- 实际占用 = 头部大小 + 用户请求大小

### 嵌入式空闲列表
空闲列表节点直接存放在空闲内存块中（不能用 malloc 来构建列表本身）。

## 四种基本策略

| 策略 | 做法 | 特点 |
|------|------|------|
| **Best-Fit** | 找最小的够大块 | 减少浪费，但搜索慢 |
| **Worst-Fit** | 找最大块 | 保留大块，但碎片多 |
| **First-Fit** | 找第一个够大块 | 快速，列表前端碎片多 |
| **Next-Fit** | 从上次位置继续找 | 分散碎片 |

## 高级方法

### Slab 分配器
为特定大小的对象（锁、inode等）维护专用缓存 → 减少碎片、加速分配。

### 伙伴分配（Buddy Allocation）
- 按 **2 的幂**递归分割空间
- 优势：合并简单（伙伴块可快速合并为更大块）
- 缺点：可能有**内部碎片**（请求不是2的幂时浪费空间）

## 考试/测试常见模式

| 场景/关键词 | 答案 |
|-------------|------|
| "free 如何知道释放大小" | 分配器在**头部块**中存储了 size 信息 |
| "Best-Fit 找 15 字节" | 在空闲列表中找**最接近** 15 字节的块 |
| "伙伴分配优势" | **合并简单**：检查伙伴块是否空闲即可 |
| "Slab 分配器用途" | 为固定大小对象（锁、inode）维护专用缓存 |
