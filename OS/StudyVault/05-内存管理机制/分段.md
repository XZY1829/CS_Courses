# 分段（★★★）

#virtualization #memory #segmentation

## 概览表（一目了然）

| 条目 | 要点 |
|------|------|
| 核心思想 | 为每个逻辑段（代码/堆/栈）各维护一对 base+bound |
| 优势 | 避免整块地址空间连续分配导致的内部碎片 |
| 段的确定 | 显式方法（高位比特）或隐式方法（地址来源） |
| 主要问题 | **外部碎片**（物理内存中零散空闲空间） |

## 分段机制

每个段有自己的 base 和 bound → 段可以放在物理内存的**不同位置**（不需要连续）。

### 地址转换

**物理地址 = 偏移量 + 该段基址**

- 示例：虚拟地址 4200（堆区），堆起始 4096 → 偏移量 104 → 物理地址 = 104 + 堆基址

### 如何确定属于哪个段

| 方法 | 实现 | 缺点 |
|------|------|------|
| **显式** | 虚拟地址高几位指示段号 | 浪费位数、限制段大小 |
| **隐式** | 根据地址来源（PC→代码，SP→栈等） | 实现复杂 |

### 栈段的特殊处理

栈向**低地址增长** → 需要额外硬件支持（增长方向位：1=正向，0=反向）

**栈段地址计算**：
```
负偏移量 = 偏移量 - 最大段大小
物理地址 = 负偏移量 + 栈段基址
```

示例：虚拟地址 15KB → 段号=3, 偏移量=3KB → 负偏移=-1KB → 物理=28KB-1KB=27KB

## 共享支持

段可以在进程间**共享**（如代码段），需要**保护位**（读/写/执行权限）。

## 外部碎片

> [!warning] 分段的核心问题
> 段大小可变 → 物理内存中产生大量零散空闲空间（外部碎片）→ 可能无法满足大请求。

| 解决方案 | 说明 | 代价 |
|----------|------|------|
| **紧凑化** | 重新排列现有段 | 停进程+拷贝数据+更新寄存器 |
| **空闲列表算法** | Best-Fit / Worst-Fit / Buddy | 不同策略各有优劣 |

## 考试/测试常见模式

| 场景/关键词 | 答案 |
|-------------|------|
| "分段 vs 基址+界限" | 分段为**每个段**维护一对 base+bound，更灵活 |
| "段错误(Segfault)" | 访问超出段界限的地址 → 硬件生成异常 |
| "栈段地址计算" | 负偏移 = offset - 最大段大小 → 物理 = 负偏移 + base |
| "外部碎片 vs 内部碎片" | 外部=空闲空间零散；内部=分配单元内部浪费 |
