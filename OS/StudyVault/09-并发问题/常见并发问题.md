# 常见并发问题（★★★）

#concurrency #deadlock

## 概览表（一目了然）

| 类型 | 占比 | 子类 |
|------|------|------|
| **非死锁** | 多数 | 原子性违反、顺序违反 |
| **死锁** | 少数 | 四条件同时满足时发生 |

## 非死锁错误

### 原子性违反
应一起执行的操作序列被中断 → **加锁**保护。

### 顺序违反
两个线程间的期望执行顺序未被强制保证 → **条件变量**强制顺序。

## 死锁

### 产生条件（四个缺一不可）

| 条件 | 含义 |
|------|------|
| **互斥** | 资源只能被一个线程独占 |
| **持有并等待** | 持有资源的同时等待其他资源 |
| **不可抢占** | 已获取的资源不能被强制夺走 |
| **循环等待** | 线程间形成环形等待链 |

### 预防方法

| 打破条件 | 方法 | 代价 |
|----------|------|------|
| **循环等待** | 对锁**全序排列**（始终先获取编号小的锁） | 需精心设计 |
| **持有并等待** | **一次性获取所有锁** | 降低并发性 |
| **不可抢占** | `trylock()` 尝试获取，失败则**释放所有已持有锁** | 可能活锁 |
| **互斥** | **无锁编程**（CAS 原子操作） | 实现复杂，仍可能活锁 |

> [!warning] 活锁（Livelock）
> 两个线程不断重试获取锁但始终失败 → 没有实际进展。解决：**随机延迟**重试。

### 通过调度避免死锁
需要全局知识 → 确保有冲突的线程不同时运行。限制并发度。

### 银行家算法
- 追踪：系统资源总数 E、最大需求 M、可用资源 A、当前分配 C
- 检查**安全状态**：是否存在一个序列使所有线程都能完成
- 实际意义有限：需提前知道资源数量和线程数，且线程需独立

### 死锁检测与恢复
- 允许死锁偶尔发生
- 定期检测（构建资源分配图，检查环）
- 发现死锁 → 重启或终止相关进程

## 考试/测试常见模式

| 场景/关键词 | 答案 |
|-------------|------|
| "死锁四条件" | 互斥、持有并等待、不可抢占、**循环等待** |
| "打破循环等待" | **全序排列**锁的获取顺序 |
| "trylock 的风险" | 可能导致**活锁**（不断重试但无进展） |
| "银行家算法局限" | 需要提前知道资源/线程数和最大需求 |
| "原子性违反解决" | 给共享变量访问**加锁** |
