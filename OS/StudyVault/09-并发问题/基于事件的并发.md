# 基于事件的并发（★★）

#concurrency

## 概览表（一目了然）

| 条目 | 要点 |
|------|------|
| 核心思想 | 单线程事件循环，等待事件 → 处理事件 → 继续等待 |
| 优势 | 无锁，无死锁，无竞态条件 |
| 关键 API | `select()` / `poll()` — 检查哪些描述符有事件 |
| 核心挑战 | 阻塞调用、状态管理、多核利用 |

## 事件循环

```c
while (1) {
    events = getEvents();    // 等待事件（如 select()）
    for (e in events)
        processEvent(e);     // 处理每个事件
}
```

## select() API

```c
int select(int nfds, fd_set *readfds, fd_set *writefds, 
           fd_set *exceptfds, struct timeval *timeout);
```

- 检查文件描述符集合中哪些已就绪
- timeout=NULL → 无限阻塞；timeout=0 → 立即返回

## 为什么不需要锁？
单线程 → 不会被其他线程中断 → 无竞态条件。

## 核心挑战

### 1. 阻塞系统调用
事件循环中不能阻塞 → 解决：**异步 I/O**（`aio_read()`/`aio_error()`）或 UNIX 信号通知。

### 2. 状态管理
不像多线程自动维护栈 → 需要手动用**延续**（Continuation）机制保存后续操作所需的状态。

### 3. 多核 CPU
单线程无法利用多核 → 需要多事件处理器 → 同步问题重现。

## 考试/测试常见模式

| 场景/关键词 | 答案 |
|-------------|------|
| "事件驱动为什么简单" | **单线程**，无需锁、无死锁 |
| "事件驱动不能做什么" | 不能有**阻塞**系统调用（否则整个服务器阻塞） |
| "异步 I/O 的作用" | 发起 I/O 后立即返回，I/O 完成时通知 |
