# 超越物理内存（★★★）

#virtualization #memory #paging

## 概览表（一目了然）

| 条目 | 要点 |
|------|------|
| 核心思想 | 用磁盘上的**交换空间**扩展物理内存 |
| 关键位 | PTE 中的 **Present Bit**：标示页面是否在内存中 |
| 页错误 | 访问不在内存中的页面 → OS 从磁盘换入 |
| 替换策略 | FIFO、随机、LRU、时钟算法 |

## 交换机制（Mechanism）

### 交换空间（Swap Space）
磁盘上预留的区域，用于存放被换出的页面（以页为单位）。

### 页错误处理流程

```
访问虚拟地址 → 查页表 → Present Bit = 0
    ↓ 页错误（Page Fault）
OS 介入 → 查 PTE 中的磁盘地址 → 发出磁盘读请求
    ↓ 读取完成
更新页表（PFN + Present=1）→ 重新执行指令
```

### 交换守护进程（Swap Daemon）
- 后台线程监控空闲页面数量
- 可用页 < **低水位线** → 开始逐出页面
- 逐出至 **高水位线** → 停止

## 交换策略（Policy）

### 评估指标
**AMAT = (P_hit × T_memory) + (P_miss × T_disk)**

### 替换策略比较

| 策略 | 做法 | 特点 |
|------|------|------|
| **最优** | 替换未来最远访问的页 | 理论下界，不可实现 |
| **FIFO** | 替换最早进入的页 | 简单但不考虑重要性；Belady 异常 |
| **随机** | 随机选择 | 简单，性能看运气 |
| **LRU** | 替换最近最少使用的页 | 利用局部性，但精确实现昂贵 |

> [!warning] Belady 异常
> FIFO 下增大缓存反而可能**增加**页错误次数。LRU 等基于栈的算法不会出现此异常。

### 时钟算法（近似 LRU）
- 页面排成**环形列表**，时钟指针循环扫描
- 检查 Use Bit：=1 → 清零并跳过；=0 → **驱逐此页**
- 可优先驱逐**干净页**（未修改，无需写回磁盘）

### 三种工作负载表现

| 负载 | 最优 | LRU | FIFO/随机 |
|------|------|-----|-----------|
| 无局部性 | 最好 | ≈ FIFO | 差别不大 |
| **80-20** | 最好 | 好（保留热门页） | 差 |
| 循环序列 | 最好 | 差（超出缓存时全 miss） | 同样差 |

## 页选择策略

| 策略 | 说明 |
|------|------|
| **预取** | 猜测即将使用的页面，提前加载 |
| **聚类/分组写** | 收集多个脏页一次性写回磁盘 |

## 抖动（Thrashing）
进程内存需求 > 物理内存 → 频繁换入换出 → 性能急剧下降。

解决：准入控制（减少运行进程数）、OOM Killer（终止进程）。

## 考试/测试常见模式

| 场景/关键词 | 答案 |
|-------------|------|
| "页错误处理流程" | 查PTE→陷入OS→磁盘读取→更新页表→重新执行 |
| "Belady 异常发生在" | **FIFO** 策略（增大缓存反而更多页错误） |
| "时钟算法如何工作" | 环形扫描 Use Bit：1→清零跳过；0→驱逐 |
| "抖动的原因" | 内存过度订阅，进程频繁换入换出 |
| "脏页 vs 干净页" | 脏页需写回磁盘再驱逐，干净页可直接驱逐 |
