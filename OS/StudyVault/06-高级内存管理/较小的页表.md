# 较小的页表（★★★）

#virtualization #memory #paging

## 概览表（一目了然）

| 方法 | 核心思想 | 优点 | 缺点 |
|------|----------|------|------|
| 更大页面 | 减少页表项数量 | 简单 | 内部碎片 |
| 分页+分段混合 | 每段一个页表 | 节省 87.5%+ | 稀疏堆仍浪费 |
| **多级页表** | 树状结构，按需分配 | 按使用比例分配 | 时间开销增加 |
| 倒排页表 | 按物理帧索引 | 全系统一个页表 | 查找慢 |

## 混合方法：分页+分段

- 每个段一个页表（而非整个地址空间一个页表）
- base 寄存器存储该**段页表的物理地址**，bound 指示页表结束
- 节省示例：纯分页 1M 项 vs 混合 128K 项 → **节省 87.5%**

## 多级页表（重点）

### 核心思想
- 将线性页表**分成页大小的块**
- 无效的整页页表项**不分配内存**
- 用**页目录**（Page Directory）追踪哪些页表页有效

### 地址结构（两级页表）

```
虚拟地址: | Page Directory Index | Page Table Index | Offset |
                   ↓                      ↓
           页目录 → PDE → 页表页 → PTE → PFN + Offset = 物理地址
```

### 页目录项（PDE）
- **Valid bit**：如果无效 → 该页表页不存在（不分配）
- **PFN**：指向下一级页表页的物理帧

### 转换示例
虚拟地址 0x3F80 = 11 1111 1000 0000
- PDIndex = 1111 → PDE 有效，PFN=101
- PTIndex = 1110 → PTE 有效，PFN=55
- Offset = 000000
- 物理地址 = 55 << 6 + 0 = 0x0DC0

### 优缺点

| 优点 | 缺点 |
|------|------|
| 按实际使用分配（空间节省） | 多次内存访问（时间-空间权衡） |
| 页表页可放任意物理位置 | 实现复杂 |

### 超过两级的页表
当页目录本身太大（>1页）→ 进一步拆分 → 三级、四级页表。

## 倒排页表（Inverted Page Table）

- 全系统**一个页表**，每项对应一个**物理帧**
- 每项记录：哪个进程、哪个虚拟页使用该物理帧
- 优点：节省空间；缺点：查找需搜索整个表（可用哈希加速）

## 考试/测试常见模式

| 场景/关键词 | 答案 |
|-------------|------|
| "多级页表如何节省空间" | 无效的**整页**页表项不分配内存，用页目录追踪 |
| "两级页表地址转换步骤" | PDIndex→PDE→PFN→PTIndex→PTE→PFN→物理地址 |
| "多级页表缺点" | 每级增加一次内存访问（时间-空间权衡） |
| "倒排页表特点" | 按物理帧索引，全系统一个表，每项记录进程+VPN |
