# TLB 快速地址转换（★★★）

#virtualization #memory #tlb

## 概览表（一目了然）

| 条目 | 要点 |
|------|------|
| 定义 | TLB = MMU 中的硬件缓存，加速虚拟→物理地址转换 |
| 结构 | 全相联（fully associative），32/64/128 条目，并行搜索 |
| 命中 | 直接从 TLB 获取 PFN → 一次内存访问 |
| 未命中 | 访问页表获取映射 → 更新 TLB → 重新执行指令 |

## TLB 基本算法

```
提取 VPN → 查 TLB
  ├─ 命中 → 从 TLB 获取 PFN → 合成物理地址 → 访问内存
  └─ 未命中 → 访问页表查找映射 → 更新 TLB → 重新执行
```

### 命中率示例
访问 10 个数组元素（16字节页面）：miss, hit, hit, miss, hit, hit, hit, miss, hit, hit → **命中率 70%**

依赖**空间局部性**：同一页面内的后续访问都命中。

## 谁处理 TLB 未命中？

| 架构 | 处理方式 |
|------|----------|
| **CISC**（x86） | 硬件遍历页表、更新 TLB（硬件管理 TLB） |
| **RISC** | 引发 Trap → OS 中的处理程序查页表、更新 TLB（软件管理 TLB） |

## TLB 条目内容

| 字段 | 说明 |
|------|------|
| VPN | 虚拟页号 |
| PFN | 物理帧号 |
| Valid bit | 条目是否有效 |
| Protection bits | 读/写/执行权限 |
| **ASID** | 地址空间标识符（区分不同进程） |
| Dirty bit | 页面是否被修改 |

## TLB 两大问题

### 问题1：上下文切换
不同进程的 VPN 映射不同 → TLB 中可能混杂多个进程的条目。

**解决**：ASID 字段区分进程（类似进程 PID，但位数更少）。

### 问题2：替换策略
TLB 条目满时需要替换 → **LRU**（最近最少使用）利用局部性。

> [!tip] TLB 支持页面共享
> 两个进程可以将不同的 VPN 映射到**同一 PFN**（如共享库代码），减少物理内存使用。

## 考试/测试常见模式

| 场景/关键词 | 答案 |
|-------------|------|
| "TLB 是什么" | MMU 中的**硬件缓存**，缓存常用的 VPN→PFN 映射 |
| "TLB 未命中处理" | CISC=硬件自动遍历页表；RISC=OS Trap 处理程序 |
| "上下文切换 TLB 问题" | 不同进程 VPN 冲突 → 用 **ASID** 区分 |
| "TLB 命中率如何提高" | 利用**空间和时间局部性**，增大页面大小 |
