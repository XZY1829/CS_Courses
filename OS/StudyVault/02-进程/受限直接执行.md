# 受限直接执行（★★★）

#virtualization #process

## 概览表（一目了然）

| 条目 | 要点 |
|------|------|
| 核心问题 | 如何**高效**运行进程，同时**保留**对 CPU 的控制？ |
| 解决方案 | 受限直接执行（Limited Direct Execution, LDE） |
| 两大挑战 | ① 受限操作（系统调用）② 进程间切换（时钟中断） |
| 关键硬件 | 用户/内核模式、Trap 指令、陷阱表、时钟中断 |

## 问题1：如何执行受限操作

### 用户模式 vs 内核模式

| 模式 | 权限 | 用途 |
|------|------|------|
| **用户模式** | 不能完全访问硬件 | 运行应用程序 |
| **内核模式** | 可访问全部资源 | OS 执行特权操作 |

### 系统调用流程

```
用户程序 → Trap指令 → 切换到内核模式 → 内核执行操作
                                              ↓
用户程序 ← Return-from-Trap ← 降回用户模式 ←———
```

| 指令 | x86 | x86-64 | 作用 |
|------|-----|--------|------|
| Trap | INT | SYSCALL | 跳入内核，提升特权级 |
| Return-from-Trap | IRET | SYSRET | 返回用户程序，降低特权级 |

### 陷阱表（Trap Table / IDT）

- **启动时**内核设置，CPU 记住其地址
- 存储各类异常、中断、系统调用的**处理程序入口**
- 用户通过**服务号**（而非地址）调用特定操作 → 防止直接内存访问

> [!important] Trap 指令执行前的信息保存
> PC、标志寄存器、重要寄存器被推入**每个进程的内核栈**（kernel stack）。Return-from-Trap 时从栈弹出恢复。

## 问题2：如何在进程间切换

### 合作式方法（Cooperative）
- 进程通过 `yield()` **主动让出** CPU
- 问题：如果进程陷入无限循环 → 只能**重启**！

### 非合作式方法（时钟中断）
- **时钟中断**（Timer Interrupt）：硬件每隔固定毫秒触发中断
- 触发时：暂停当前进程 → 保存状态 → 运行**调度器**

### 上下文切换（Context Switch）

OS 决定切换时执行：
1. **保存**当前进程的 PC、寄存器、SP → 存入 PCB
2. **选择**下一个进程（调度策略）
3. **恢复**新进程的 PC、寄存器、SP
4. **切换**到新进程，更新调度信息

## LDE 协议总结

| 阶段 | 操作 |
|------|------|
| **引导时** | 内核初始化陷阱表，CPU 记住地址，启动时钟 |
| **运行进程时** | 创建进程条目、分配内存，通过 Return-from-Trap 进入用户模式 |
| **系统调用时** | Trap → 内核执行 → Return-from-Trap 回到进程 |
| **时钟中断时** | 保存上下文 → 调度器决策 → 恢复新进程上下文 |

## 中断分类（x86）

| 类型 | 说明 |
|------|------|
| **中断** | 异步硬件事件（I/O完成、INT指令） |
| **Traps** | 立即报告，继续到 trap 后的下一条指令 |
| **Faults** | 立即报告，跳到故障处理程序 |
| **Abort** | 严重错误，硬件失败（蓝屏） |

## 并发安全

- 中断处理中**禁用中断**：x86 使用 CLI（禁用）和 STI（启用）
- 使用**锁机制**保护内部数据结构的并发访问

## 考试/测试常见模式

| 场景/关键词 | 答案 |
|-------------|------|
| "用户程序如何执行特权操作" | 通过系统调用(Trap指令) 切换到内核模式 |
| "陷阱表何时设置" | **系统启动时**由内核设置 |
| "OS 如何重获 CPU 控制权" | **时钟中断**（非合作式方法） |
| "上下文切换保存什么" | PC、寄存器、SP → 存入 PCB |
| "Trap vs Fault vs Abort" | Trap=正常返回下一条；Fault=跳到处理程序；Abort=严重错误 |
