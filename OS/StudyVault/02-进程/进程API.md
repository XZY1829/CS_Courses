# 进程 API（★★★）

#virtualization #process

## 概览表（一目了然）

| 系统调用 | 功能 | 关键行为 |
|----------|------|----------|
| `fork()` | 创建子进程 | 子进程获得独立的地址空间、寄存器、PC |
| `exec()` | 加载并运行新程序 | **不创建新进程**，替换当前进程的代码/数据 |
| `wait()` | 等待子进程结束 | 使父进程输出顺序确定化 |
| `exit()` | 终止进程 | 资源由 OS 回收 |
| `kill()` | 向进程发送信号 | SIGINT(中断)、SIGSTOP(暂停)、SIGCONT(恢复) |

## fork() 系统调用

- 创建一个与父进程**几乎一致**的新进程（子进程）
- 子进程拥有**私有的**、独立的地址空间、寄存器、PC
- 子进程从 `fork()` 调用之后开始执行
- **返回值**：子进程中返回 `0`，父进程中返回子进程的 PID
- **执行顺序不确定**：由调度器决定

> [!warning] fork() 后的独立性
> 父子进程共享相同的**代码段**，但数据、堆栈是**独立**的。修改一方不影响另一方。

## exec() 系统调用

- **不创建新进程**，而是将当前进程替换为新程序
- 执行后进程具有**不同的**代码、静态数据、地址空间、寄存器、PC
- `exec()` 成功后**不返回**（后续代码被彻底替换）

## wait() 系统调用

- 父进程调用 `wait()` → 阻塞直到子进程结束
- 使输出顺序**确定化**（父进程必须在子进程终止后才继续）

## fork() + exec() 分离的意义

这是 Unix/Linux 启动新程序的**经典模式**。分离允许 Shell 在 `fork()` 后、`exec()` 前修改环境：

| 特性 | 实现方式 |
|------|----------|
| **I/O 重定向** (`>`, `<`) | fork 后关闭 STDOUT，open 新文件获得 fd=1 |
| **管道** (`\|`) | `pipe()` 系统调用连接两个进程的 STDIN/STDOUT |
| **后台运行** (`&`) | 子进程在后台执行，Shell 继续接收命令 |

## 进程层级关系

- `systemd`（PID=1）是所有进程的祖先
- 进程形成**树状层级**（可用 `pstree` 查看）
- **孤儿进程**：父进程先于子进程终止 → 被 init/systemd 收养
- **僵尸进程**：子进程终止但父进程未 `wait()` → 占据进程表

## 进程终止

- 最常见方式：从 `main()` 返回
- OS 回收其占有的资源（物理内存等）

## 考试/测试常见模式

| 场景/关键词 | 答案 |
|-------------|------|
| "fork 返回值" | 子进程返回 0，父进程返回子进程 PID |
| "exec 会创建新进程吗" | **不会**，只是替换当前进程的程序 |
| "如何实现重定向" | fork 后关闭 STDOUT，open 文件获得 fd=1，再 exec |
| "管道实现原理" | pipe() 创建两个 fd，连接一个进程的 STDOUT 到另一个的 STDIN |
| "孤儿 vs 僵尸进程" | 孤儿=父先死(被收养)；僵尸=子先死(父未wait) |
