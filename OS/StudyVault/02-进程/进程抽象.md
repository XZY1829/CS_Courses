# 进程抽象（★★★）

#virtualization #process

## 概览表（一目了然）

| 条目 | 要点 |
|------|------|
| 定义 | 进程 = 正在执行的程序（程序本身是"lifeless"） |
| 构成 | 地址空间（代码+数据）、寄存器（PC、SP）、I/O信息 |
| 核心数据结构 | PCB（进程控制块）存储进程所有信息 |
| 状态 | Running → Ready ↔ Blocked（+ Initial、Final） |
| CPU 虚拟化 | 时分共享 + 上下文切换 → 制造多CPU假象 |

## CPU 虚拟化

OS 通过**时分共享**（Time Sharing）让有限的 CPU 支持多个进程：
- 让一个进程运行一个**时间片**，然后切换到另一个
- 代价：每个进程运行速度变慢
- 核心机制：**上下文切换**（context switch）

> [!important] 机制 vs 策略
> - **机制（How）**：底层方法，如上下文切换协议
> - **策略（Which）**：决策算法，如调度策略决定先运行谁

## 进程的构成

| 组成部分 | 说明 |
|----------|------|
| **地址空间** | 代码段 + 数据段（进程可访问的地址范围） |
| **寄存器** | PC（程序计数器）、SP（栈指针）、FP（帧指针）等 |
| **I/O 信息** | 打开文件列表（默认：stdin=0, stdout=1, stderr=2） |

## 进程创建步骤

```
磁盘上的程序（ELF/PE格式）
    ↓ 1. 载入代码/静态数据到内存（lazily）
    ↓ 2. 分配运行时栈（初始化argc, argv）
    ↓ 3. 分配堆空间（用于malloc）
    ↓ 4. I/O设置（3个默认文件描述符）
    ↓ 5. 从main()启动，OS转交CPU控制权
    ↓
正在运行的进程
```

## 进程状态

```
         调度(scheduled)
Initial → Ready ←————————→ Running → Final
            ↑                  |
            |    I/O完成       | I/O请求
            ←———— Blocked ←———
              取消调度
              (descheduled)
```

| 状态 | 含义 |
|------|------|
| **Running** | 正在CPU上执行指令 |
| **Ready** | 准备好运行，但OS未调度 |
| **Blocked** | 等待某事件（如I/O完成） |
| Initial | 创建中 |
| Final（Zombie） | 已退出但尚未清理 |

> [!warning] 僵尸进程
> 子进程已终止但父进程尚未调用 `wait()` 回收，进程表项仍被占用（`ps` 显示 `Z`/`<defunct>`）。

## 关键数据结构

- **进程/任务列表**：跟踪所有 Ready、Blocked、Running 的进程
- **寄存器上下文**（Register Context）：上下文切换时保存/恢复
- **PCB**（Process Control Block）：包含进程所有信息的 C 结构体

## 考试/测试常见模式

| 场景/关键词 | 答案 |
|-------------|------|
| "进程 vs 程序" | 程序是磁盘上的静态指令，进程是正在执行的程序实例 |
| "进程三状态转换" | Ready↔Running（调度/取消调度），Running→Blocked（I/O），Blocked→Ready（I/O完成） |
| "PCB 包含什么" | 进程状态、PC、寄存器、内存信息、I/O信息等 |
| "僵尸进程产生原因" | 子进程结束但父进程未调用 wait() |
