# MLFQ 与比例份额调度（★★★）

#virtualization #scheduling

## 概览表（一目了然）

| 调度器 | 核心思想 | 特点 |
|--------|----------|------|
| MLFQ | 多队列 + 反馈 + 优先级 | 无需预知运行时间，近似 SJF |
| 彩票调度 | 随机抽签，概率分配 | 简单、轻量 |
| 步长调度 | 确定性分配，按步长轮转 | 精确比例 |
| CFS | 虚拟运行时间 + 红黑树 | Linux 默认调度器 |

## MLFQ 五条规则

| 规则 | 内容 |
|------|------|
| **R1** | Priority(A) > Priority(B) → A 运行 |
| **R2** | Priority(A) = Priority(B) → A 和 B 使用 **RR** |
| **R3** | 新进程进入**最高优先级**队列 |
| **R4** | 进程在某队列中**消耗完时间片**（无论放弃多少次 CPU），优先级降低 |
| **R5** | 每隔时间 S，**所有进程**提升到最高优先级队列（优先级提升） |

### MLFQ 解决的三个问题

| 问题 | 解决方案 |
|------|----------|
| 饥饿 | R5 定期优先级提升 |
| 调度器作弊 | R4 按累计时间片计算而非单次 |
| 行为变化 | R5 允许 CPU 密集型进程重获高优先级 |

> [!tip] MLFQ 的时间片设计
> 高优先级队列 → 短时间片（如 10ms）；低优先级队列 → 长时间片（如 40ms）

## 比例份额调度

### 彩票调度（Lottery Scheduling）
- 每个进程持有彩票，代表 CPU 份额
- 每个时间片**随机抽奖** → 运行中奖进程
- 机制：彩票货币（本地↔全局转换）、彩票转让、彩票通胀
- 优点：简单、轻量、避免边界情况
- 缺点：短时间内可能不公平

### 步长调度（Stride Scheduling）
- **确定性**公平调度器
- 步长 = 大数 / 票数（票多步长小 → 更频繁被选中）
- 每次运行按步长增加 **pass 值** → 选择 pass 值最小的进程
- 问题：新进程 pass=0 会独占 CPU

### CFS（完全公平调度器）

Linux 默认调度器，核心概念：

| 概念 | 说明 |
|------|------|
| **vruntime** | 虚拟运行时间，调度选择 vruntime 最小的进程 |
| **sched_latency** | 一轮调度时间（典型 48ms），时间片 = sched_latency / n |
| **min_granularity** | 最小时间片（典型 6ms），防止 n 过大时时间片过小 |
| **nice 值** | [-20, +19]，映射到权重表，影响时间片和 vruntime 增速 |
| **红黑树** | O(log n) 查找 vruntime 最小的进程 |

**vruntime 计算**：`vruntime += (weight₀ / weightᵢ) × runtime`

> [!warning] CFS 睡眠进程处理
> 长时间睡眠的进程唤醒后 vruntime 很小 → 可能独占 CPU。解决：将唤醒进程的 vruntime 设为红黑树中**最小值**。

## 考试/测试常见模式

| 场景/关键词 | 答案 |
|-------------|------|
| "MLFQ 如何防止饥饿" | **R5 优先级提升**：定期将所有进程移到最高队列 |
| "MLFQ 如何防止作弊" | **R4**：按累计消耗时间片判断，而非单次是否用完 |
| "CFS 用什么数据结构" | **红黑树**（O(log n) 查找最小 vruntime） |
| "步长调度 vs 彩票调度" | 步长=确定性精确；彩票=概率性，新进程处理更好 |
| "nice 值 -5 vs 0" | -5 权重更高 → 时间片更长、vruntime 增速更慢 |
