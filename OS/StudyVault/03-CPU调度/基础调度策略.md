# 基础调度策略（★★★）

#virtualization #scheduling

## 概览表（一目了然）

| 策略 | 类型 | 优化指标 | 抢占 | 关键问题 |
|------|------|----------|------|----------|
| FCFS/FIFO | 非抢占 | — | 否 | 护航效应 |
| SJF | 非抢占 | 周转时间 | 否 | 延迟到达时护航 |
| STCF/PSJF | 抢占 | 周转时间 | 是 | 响应时间差 |
| RR | 抢占 | 响应时间 | 是 | 周转时间差 |

## 调度指标

| 指标 | 公式 | 说明 |
|------|------|------|
| **周转时间** | T_turnaround = T_completion − T_arrival | 性能指标 |
| **响应时间** | T_response = T_firstrun − T_arrival | 交互性指标 |
| **公平性** | 每个进程都有公平的 CPU 机会 | 与性能常矛盾 |

## FCFS（先来先服务）

- 按到达顺序执行，非常简单
- **护航效应**（Convoy Effect）：短进程在长进程后面排队，平均周转时间很差
- 示例：A=100s, B=C=10s → ATT = (100+110+120)/3 = 110s

## SJF（最短作业优先）

- 先执行最短进程 → 最小化平均周转时间
- **非抢占**：已运行的进程不会被打断
- 问题：如果短进程晚到达，仍要等长进程完成

## STCF（最短完成时间优先）

- 在 SJF 基础上加**抢占**机制
- 新进程到达时比较剩余时间 → 调度剩余时间最短者
- **最优周转时间**（假设已知运行时间）
- 缺点：对响应时间不友好

## RR（轮转/时间片调度）

- 每个进程运行一个**时间片** q → 切换到队列中下一个
- 时间片必须是时钟中断周期的倍数
- **公平**，对响应时间好；但周转时间差

> [!warning] 时间片长度的权衡
> - **过短**：上下文切换代价主导性能
> - **过长**：响应时间变差
> - 上下文切换代价不仅仅是寄存器复制，还包括**缓存、TLB** 等

## 融合 I/O

- 进程发起 I/O → 状态变为 **Blocked** → 调度其他进程
- I/O 完成 → 中断 → 状态变为 **Ready** → 可被重新调度
- 通过**重叠**（overlap）CPU 和 I/O 提高资源利用率

## 考试/测试常见模式

| 场景/关键词 | 答案 |
|-------------|------|
| "FCFS 最大问题" | **护航效应**：短进程等待长进程 |
| "优化周转时间用什么" | **STCF**（抢占式 SJF） |
| "优化响应时间用什么" | **RR**（轮转调度） |
| "RR 的周转时间" | 通常较差，所有进程几乎同时完成 |
| "需要预知运行时间吗" | SJF/STCF 需要；RR/FCFS 不需要 |
