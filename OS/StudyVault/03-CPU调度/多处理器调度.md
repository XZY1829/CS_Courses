# 多处理器调度（★★）

#virtualization #scheduling

## 概览表（一目了然）

| 条目 | 要点 |
|------|------|
| 前提 | 多核处理器需要**并行化**（线程）才能充分利用 |
| 三大问题 | 缓存一致性、同步、缓存亲和性 |
| 两种方法 | SQMS（单队列）、MQMS（多队列） |
| 负载均衡 | 任务迁移、工作窃取 |

## 缓存基础

- **缓存**：小而快的存储器，存储主存常用数据副本
- **时间局部性**：最近访问的数据可能再次被访问
- **空间局部性**：访问地址 x 后，很可能访问 x 附近的地址

## 三大问题

### 1. 缓存一致性（Cache Coherence）
多个 CPU 各有缓存，共享同一内存 → 一个 CPU 更新数据，其他缓存可能过期。

**解决方案**：总线嗅探（Bus Snooping）— 每个缓存监视总线，发现更新时使副本**失效**或**更新**。

### 2. 同步（Synchronization）
多核同时访问和修改共享数据 → 需要**互斥锁**（mutex）保证正确性。

### 3. 缓存亲和性（Cache Affinity）
进程在某 CPU 上运行后，缓存中存有其状态 → 应**尽量保持在同一 CPU** 上运行。

## SQMS（单队列多处理器调度）

- 所有作业放入**单一队列**，每个 CPU 从中取出作业
- **优点**：简单
- **缺点**：缺乏可扩展性（需要全局锁）、缓存亲和性差

## MQMS（多队列多处理器调度）

- 每个 CPU 维护**自己的调度队列**
- **优点**：高扩展性、高缓存亲和性
- **缺点**：可能**负载不均**

### 负载均衡：工作窃取（Work Stealing）
- 空闲（或少任务）的队列偶尔查看其他队列
- 发现目标队列负载高 → "窃取"一个或多个进程
- 缺点：带来额外开销

## Linux 多处理器调度器

| 调度器 | 特点 |
|--------|------|
| O(1) | 基于优先级，多队列，优化交互性 |
| CFS | 确定性比例公平，红黑树，多队列 |
| BF | 单队列，EEVDF 算法，低延迟 |

## 考试/测试常见模式

| 场景/关键词 | 答案 |
|-------------|------|
| "缓存一致性解决方案" | **总线嗅探**（Bus Snooping） |
| "SQMS vs MQMS" | SQMS 简单但不扩展；MQMS 扩展性好但可能负载不均 |
| "如何解决负载不均" | **工作窃取**：空闲队列窃取繁忙队列的任务 |
| "缓存亲和性含义" | 尽量让进程在**同一 CPU** 上运行以利用缓存 |
