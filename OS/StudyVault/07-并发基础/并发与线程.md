# 并发与线程（★★★）

#concurrency #thread

## 概览表（一目了然）

| 条目 | 要点 |
|------|------|
| 线程 | 进程内的执行单元，共享地址空间，各有独立栈和 PC |
| 与进程区别 | ① 上下文切换时地址空间不变 ② 每个线程有独立栈 |
| 用线程的原因 | ① 并行加速计算 ② 避免 I/O 阻塞进度 |
| 核心问题 | 共享数据的非原子操作 → 竞态条件 |

## 线程 vs 进程

| 特性 | 线程 | 进程 |
|------|------|------|
| 地址空间 | **共享**同一进程的地址空间 | 各自独立 |
| 栈 | 每个线程**私有**栈 | 单一栈 |
| 堆 | **共享**（需同步） | 独立 |
| 切换开销 | 小（地址空间不变） | 大（需切换地址空间） |
| 数据结构 | TCB（线程控制块） | PCB |

## 竞态条件（Race Condition）

当多个线程并发访问共享数据且至少一个是写操作时：
```
Thread 1: load counter → eax    (eax=50)
Thread 1: add eax, 1            (eax=51)
  ← 上下文切换 →
Thread 2: load counter → eax    (eax=50)
Thread 2: add eax, 1            (eax=51)
Thread 2: store eax → counter   (counter=51)
  ← 切换回 →
Thread 1: store eax → counter   (counter=51)  ← 期望52，实际51！
```

## 关键概念

| 概念 | 定义 |
|------|------|
| **临界区** | 访问共享变量的代码，不能被多个线程同时执行 |
| **竞态条件** | 结果取决于线程的执行顺序/时序 |
| **原子性** | 操作要么全部完成要么不执行，无中间状态 |
| **互斥** | 确保临界区同一时刻只有一个线程执行 |

## 解决方案预览

| 机制 | 用途 |
|------|------|
| **锁** | 互斥访问临界区 |
| **条件变量** | 线程间等待/唤醒 |
| **信号量** | 互斥 + 同步的通用工具 |

## 考试/测试常见模式

| 场景/关键词 | 答案 |
|-------------|------|
| "线程共享什么" | **地址空间（代码+堆）**，但栈是私有的 |
| "竞态条件根本原因" | 对共享数据的操作**不是原子的** + 线程调度不可控 |
| "临界区含义" | 访问共享变量的代码段，必须互斥执行 |
