# 锁（★★★）

#concurrency #lock

## 概览表（一目了然）

| 条目 | 要点 |
|------|------|
| 目的 | 确保临界区像单个原子指令一样执行 |
| 评价标准 | 互斥性、公平性、性能 |
| 实现层次 | 软件方法 → 硬件原子指令 → OS 支持 |

## 锁的状态

- **可用**（available/unlocked/free）：无线程持有
- **占用**（acquired/locked/held）：有且仅有一个线程持有

## 构建锁的方法

### 方法一：禁用中断（仅单处理器）
临界区内禁用中断 → 不会被抢占。

问题：过度信任应用程序、不适用多处理器、效率低。

### 方法二：硬件原子指令

| 指令 | 语义 | 特点 |
|------|------|------|
| **Test-and-Set** | 原子地返回旧值并设置新值 | 最基本的自旋锁 |
| **Compare-and-Swap** | 如果 *ptr == expected → 更新为 new | 更强大，可用于无锁编程 |
| **Load-Linked + Store-Conditional** | 条件式存储，上次加载后地址未被修改才成功 | RISC 架构常用 |
| **Fetch-and-Add** | 原子返回旧值并+1 | 用于 Ticket 锁 |

### 自旋锁评估

| 标准 | 评价 |
|------|------|
| 互斥性 | ✅ 正确 |
| 公平性 | ❌ 无保证，可能饥饿 |
| 性能 | 单核差（自旋浪费时间片）；多核+短临界区可接受 |

### Ticket 锁（公平的自旋锁）
使用 Fetch-and-Add：`ticket`（领号）+ `turn`（当前服务号）→ **保证 FIFO 顺序**。

### 方法三：OS 支持（避免过度自旋）

| 方法 | 机制 | 特点 |
|------|------|------|
| **yield()** | 让出 CPU → Ready 状态 | 上下文切换开销大，仍可能饥饿 |
| **队列+park/unpark** | 让等待线程**睡眠** | 避免自旋和饥饿 |
| **futex**（Linux） | futex_wait(addr, expected) / futex_wake(addr) | 高效的用户态+内核混合方案 |

### 两阶段锁
1. **第一阶段**：自旋一段时间（希望锁很快释放）
2. **第二阶段**：如果没获得锁 → 睡眠等待

## 考试/测试常见模式

| 场景/关键词 | 答案 |
|-------------|------|
| "Test-and-Set 语义" | **原子地**返回旧值并设置新值 |
| "自旋锁公平吗" | **不公平**，可能饥饿 |
| "如何实现公平锁" | **Ticket 锁**（Fetch-and-Add） |
| "如何避免过度自旋" | 用 **park/unpark** 或 **futex** 让线程睡眠 |
| "CAS vs TAS" | CAS 检查值是否匹配后再更新，更灵活 |
