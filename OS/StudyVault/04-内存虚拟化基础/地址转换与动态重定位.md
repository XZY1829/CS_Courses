# 地址转换与动态重定位（★★★）

#virtualization #memory #address-translation

## 概览表（一目了然）

| 条目 | 要点 |
|------|------|
| 核心 | 地址转换：硬件将虚拟地址 → 物理地址 |
| 方法 | 基址+界限寄存器（Base and Bound） |
| 硬件支持 | MMU（内存管理单元）、基址/界限寄存器 |
| 四大优点 | 保护、重定位、数据共享、多路复用 |

## 地址转换的四大优点

| 优点 | 说明 |
|------|------|
| **保护** | 不同进程映射到不重叠的物理内存 |
| **重定位** | 进程可加载到任意物理地址 |
| **数据共享** | 不同虚拟地址可映射到同一物理地址 |
| **多路复用** | 不同时间将虚拟地址映射到相同物理内存 |

## 基址加界限机制（Dynamic Relocation）

**物理地址 = 虚拟地址 + 基址寄存器**

约束：虚拟地址 < 界限寄存器（否则异常）

```
虚拟地址 128 + 基址 32KB = 物理地址 32896
虚拟地址 15KB + 基址 32KB = 物理地址 47KB
```

### 界限寄存器的两种定义

| 方式 | 含义 |
|------|------|
| 地址空间视角 | 界限 = 地址空间大小（如 16KB） |
| 物理内存视角 | 界限 = 地址空间结束的物理地址（如 48KB） |

## OS 在动态重定位中的四个关键时刻

| 时刻 | OS 操作 |
|------|---------|
| **进程启动** | 在物理内存中找空间（维护空闲列表），设置 base/bound |
| **进程终止** | 释放内存，归还空闲列表 |
| **上下文切换** | 保存/恢复 base 和 bound 寄存器（存入 PCB） |
| **系统启动** | 设置异常处理程序（特权指令） |

## 内部碎片问题

> [!warning] 基址+界限的局限
> 整个地址空间连续分配 → 堆和栈之间的大量空间被**浪费**（内部碎片）。需要更复杂机制：**分段**或**分页**。

## 考试/测试常见模式

| 场景/关键词 | 答案 |
|-------------|------|
| "物理地址计算" | **虚拟地址 + base**（需检查 < bound） |
| "谁修改 base/bound" | 只有**内核模式**可以修改 |
| "上下文切换时" | 必须保存/恢复 base 和 bound 寄存器 |
| "内部碎片产生原因" | 分配的连续空间中，堆栈之间有大量未使用空间 |
