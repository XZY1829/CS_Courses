# 地址空间（★★）

#virtualization #memory

## 概览表（一目了然）

| 条目 | 要点 |
|------|------|
| 定义 | 地址空间 = 运行程序看到的内存视图 |
| 组成 | 代码段、堆（↑增长）、栈（↓增长） |
| 关键抽象 | 每个进程独立的虚拟地址空间 → 映射到物理内存 |
| 三大目标 | 透明性、效率、保护/隔离 |

## 地址空间结构

```
高地址 ┌─────────────────┐
       │   内核空间       │  （进程无法直接访问）
       ├─────────────────┤
       │ 命令行参数/环境  │
       ├─────────────────┤
       │   栈 Stack ↓    │  局部变量、函数调用
       │                 │
       │   （空闲区域）   │
       │                 │
       │   堆 Heap ↑     │  动态内存分配 (malloc)
       ├─────────────────┤
       │ 未初始化数据 BSS │  全局/静态变量
       ├─────────────────┤
       │ 已初始化数据     │  全局/静态变量
       ├─────────────────┤
低地址 │ 代码段 Code      │  程序指令
       └─────────────────┘
```

## 虚拟内存系统的目标

| 目标 | 说明 |
|------|------|
| **透明性** | 进程不知道虚拟化的存在，以为独占内存 |
| **效率** | 时间和空间上都不能有太多开销（依赖 TLB 等硬件） |
| **保护/隔离** | 一个进程不能访问其他进程或内核的内存 |

---

## 考试/测试常见模式

| 场景/关键词 | 答案 |
|-------------|------|
| "堆和栈的增长方向" | 堆向**高地址**增长，栈向**低地址**增长 |
| "虚拟地址 vs 物理地址" | 进程只看到虚拟地址，OS+MMU 负责映射到物理地址 |
| "地址空间包含什么" | 代码段、已/未初始化数据、堆、栈 |
