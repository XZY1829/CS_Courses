# 基于锁的并发数据结构（★★）

#concurrency #lock #synchronization

## 概览表（一目了然）

| 数据结构 | 策略 | 扩展性 |
|----------|------|--------|
| 并发计数器 | 近似计数器（per-CPU 局部计数器 + 全局计数器） | 好 |
| 并发链表 | 单锁（简单）或锁耦合（per-node锁） | 一般 |
| 并发队列 | 头锁 + 尾锁 + dummy node | 好 |
| 并发哈希表 | 每桶一个锁 | 优秀 |

## 近似计数器

传统计数器用单锁 → 线程越多性能越差。近似计数器的改进：

- 每个 CPU 维护**局部计数器**（各有独立锁）
- 一个**全局计数器**（独立锁）
- 局部值达到阈值 **S** 时 → 获取全局锁 → 转移到全局 → 局部清零

| S 值 | 性能 | 精度 |
|------|------|------|
| 小 | 差（频繁全局同步） | 高 |
| 大 | 好（少同步） | 低（全局值有滞后） |

## 并发队列（Michael-Scott）

- **两个锁**：head 锁（出队用）+ tail 锁（入队用）
- **dummy node**：使头尾操作完全分离
- 入队和出队可**并发**进行

## 并发哈希表

- 每个桶（bucket）一个锁 → 不同桶的操作完全并行
- 使用并发链表构建每个桶
- **扩展性优秀**

## 考试/测试常见模式

| 场景/关键词 | 答案 |
|-------------|------|
| "近似计数器的 S 越大" | **性能越好**但全局值**精度越低** |
| "并发队列为什么用 dummy" | 使 head 和 tail 操作**分离**，各用不同锁 |
| "并发哈希表为什么扩展好" | **每桶一锁**，不同桶的操作无竞争 |
