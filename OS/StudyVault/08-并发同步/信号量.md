# 信号量（★★★）

#concurrency #synchronization

## 概览表（一目了然）

| 条目 | 要点 |
|------|------|
| 定义 | 具有整数值的对象，通过 `sem_wait()`（P）和 `sem_post()`（V）操作 |
| 二进制信号量 | 初始值=1 → 等价于**互斥锁** |
| 条件同步 | 初始值=0 → 等价于**条件变量**（等待/通知） |
| 负值含义 | 信号量为负 → |负值| = 正在等待的线程数 |

## sem_wait() 和 sem_post()

| 操作 | 行为 |
|------|------|
| `sem_wait()` (P) | 值-1；如果值<0 → 线程**阻塞** |
| `sem_post()` (V) | 值+1；如果有线程等待 → **唤醒一个** |

## 三种用法

### 1. 互斥锁（Binary Semaphore）
初始值 = **1**
```c
sem_wait(&mutex);   // 进入临界区（值→0）
// 临界区
sem_post(&mutex);   // 离开临界区（值→1）
```

### 2. 条件同步（Ordering）
初始值 = **0**
```c
// 子线程                      // 父线程
// ... 工作 ...               sem_wait(&s);  // 等待（值→-1，阻塞）
sem_post(&s);  // 通知完成     // 唤醒后继续
```

### 3. 生产者消费者
- `full` 信号量（初始=0）：跟踪已填充槽位
- `empty` 信号量（初始=MAX）：跟踪空闲槽位
- `mutex` 信号量（初始=1）：保护缓冲区

> [!warning] 死锁陷阱
> 如果先获取 mutex 再等待 full/empty → **死锁**（mutex 已持有但 full/empty 无法被满足）。
> 正确做法：**mutex 的 wait/post 在 full/empty 的内侧**。

## 读写锁（Reader-Writer Lock）

- **读者**可并发：第一个读者加写锁，最后一个读者放写锁
- **写者**独占：获取写锁（writelock）
- 问题：读者可能使**写者饥饿**

## 哲学家就餐问题

- 5 个哲学家 + 5 把叉子，每人需要左右两把叉子吃饭
- 直接实现 → **死锁**（所有人拿左叉等右叉）
- **解决**：最后一个哲学家以**相反顺序**获取叉子 → 打破循环等待

## 信号量 vs 互斥锁+条件变量

| 特性 | 信号量 | 互斥锁+条件变量 |
|------|--------|----------------|
| 互斥 | ✅ 可以（初始值=1） | ✅ 原生支持 |
| 同步 | ✅ 方便 | ✅ 方便 |
| 灵活性 | 不太好实现条件变量 | 可以实现信号量 |

## 考试/测试常见模式

| 场景/关键词 | 答案 |
|-------------|------|
| "二进制信号量初始值" | **1**（等价互斥锁） |
| "条件同步信号量初始值" | **0** |
| "生产者消费者死锁原因" | **先 mutex 后 full/empty** → 持有 mutex 等待缓冲区条件 |
| "哲学家死锁解决" | 一个哲学家**反序**获取叉子，打破循环等待 |
