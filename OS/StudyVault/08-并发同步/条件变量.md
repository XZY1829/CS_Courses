# 条件变量（★★★）

#concurrency #synchronization

## 概览表（一目了然）

| 条目 | 要点 |
|------|------|
| 定义 | 显式等待队列：条件不满足时线程加入队列睡眠 |
| 操作 | `wait(cond, mutex)` — 释放锁+睡眠；`signal(cond)` — 唤醒一个 |
| 关键规则 | ① 始终用 **while** 循环检查条件 ② **wait 必须传已锁 mutex** |

## 条件变量的正确使用

```c
// 等待方
pthread_mutex_lock(&mutex);
while (!condition)                   // 必须用 while，不能用 if
    pthread_cond_wait(&cond, &mutex); // 释放锁+睡眠
// 条件已满足，执行临界区
pthread_mutex_unlock(&mutex);

// 信号方
pthread_mutex_lock(&mutex);
condition = true;
pthread_cond_signal(&cond);          // 唤醒一个等待者
pthread_mutex_unlock(&mutex);
```

> [!important] 为什么必须用 while
> **Mesa 语义**：唤醒的线程不保证立即运行，其他线程可能抢先改变条件。必须重新检查。

## 生产者/消费者问题演进

| 版本 | 问题 |
|------|------|
| 单条件变量 + if | 多消费者时消费者可能在空缓冲区上操作 |
| 单条件变量 + while | 消费者可能唤醒**另一个消费者**（而非生产者） |
| **两个条件变量 + while** | ✅ 正确：生产者等 empty 信号 fill；消费者等 fill 信号 empty |
| 多缓冲区槽位 | ✅ 更好的并发和效率 |

### 最终方案要点
- 两个条件变量：`empty`（缓冲区有空位）和 `fill`（缓冲区有数据）
- 生产者在**所有**缓冲区满时才睡眠
- 消费者在**所有**缓冲区空时才睡眠

## 覆盖条件

当多个线程等待不同大小的分配时，`signal()` 可能唤醒错误的线程。

**解决**：`pthread_cond_broadcast()` 唤醒所有等待者，让它们重新检查条件。

## 考试/测试常见模式

| 场景/关键词 | 答案 |
|-------------|------|
| "为什么不能用 if 检查条件" | Mesa 语义下唤醒后条件可能已变，必须用 **while** 重新检查 |
| "单条件变量的问题" | 消费者可能唤醒**另一个消费者**而非生产者 |
| "正确的生产者消费者" | **两个条件变量**（empty + fill）+ while 循环 |
| "broadcast vs signal" | broadcast 唤醒所有等待者（覆盖条件场景） |
