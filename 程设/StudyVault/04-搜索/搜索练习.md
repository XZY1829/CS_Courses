## 第 1 题 - BFS 最优性 [recall]

> BFS 为什么能保证找到最短路径？

> [!answer]- 查看答案
> BFS 按**层次**扩展节点：从起点出发，距离为 1 的点先入队，距离为 2 的点后入队……
> 保证**第一次**到达目标点时，所经步数即为最短。
> 因为所有更短的路径对应的节点一定已在更早的层被访问过。

## 第 2 题 - DFS 回溯三步 [recall]

> DFS 回溯的三步操作是什么？

> [!answer]- 查看答案
> 1. **做选择**：标记 visited / push 到路径
> 2. **递归**：进入下一层决策 `dfs(next_state)`
> 3. **撤销选择**：取消标记 / pop 路径，尝试其他分支

## 第 3 题 - BFS 基本模板 [recall]

> 写出 BFS 的基本模板（含队列、visited 数组）。

> [!answer]- 查看答案
> ```cpp
> queue<Node> que;
> bool vis[MAXN][MAXN];
> vis[sx][sy] = true;
> que.push({sx, sy, 0});
> while (!que.empty()) {
>     Node u = que.front(); que.pop();
>     if (u.x == tx && u.y == ty) return u.dist;
>     for (int i = 0; i < 4; i++) {
>         int nx = u.x + dx[i], ny = u.y + dy[i];
>         if (valid(nx, ny) && !vis[nx][ny]) {
>             vis[nx][ny] = true;
>             que.push({nx, ny, u.dist + 1});
>         }
>     }
> }
> ```

## 第 4 题 - 木棒剪枝 [recall]

> 木棒问题的 4 种剪枝策略分别是什么？

> [!answer]- 查看答案
> 1. **只枚举因子**：目标长度 S 必须是所有木棍长度之和的因子
> 2. **从大到小排序**：DFS 前按长度降序，优先拼长棍
> 3. **二分查找**：在剩余木棒中二分找第一个 ≤ 剩余长度的位置
> 4. **跳过相同失败**：某长度木棒在某位置拼接失败后，跳过其余同长度木棒

## 第 5 题 - 城堡位运算 [recall]

> 城堡问题中如何用位运算判断某方向是否有墙？

> [!answer]- 查看答案
> 设格子值为 `val`（题目编码的墙信息）：
>
> | 方向 | 判断 |
> |------|------|
> | 西 | `val % 2 == 1` |
> | 北 | `(val / 2) % 2 == 1` |
> | 东 | `(val / 4) % 2 == 1` |
> | 南 | `(val / 8) % 2 == 1` |
>
> 对应位为 1 表示该方向有墙，不能通行。

## 第 6 题 - 拯救公主 visited [recall]

> 拯救公主问题中 visited 数组为什么是三维的？

> [!answer]- 查看答案
> 状态不仅是位置 `(x, y)`，还包括**已收集的宝石种类集合**。
> 同一位置在不同宝石组合下可能仍需继续搜索（例如先拿 A 再拿 B 与只拿 B 是不同状态）。
> 因此用 `used[x][y][gem_mask]`，其中 `gem_mask` 用二进制压缩表示已获得的宝石种类（0~4 共 5 种，最多 2⁵=32 种状态）。

## 第 7 题 - 迷宫 BFS 初始化 [application]

> 给定一个 5×5 迷宫，起点 (0,0) 终点 (4,4)，用 BFS 求最短路径。描述 visited 数组和队列的初始化方式。

> [!answer]- 查看答案
> ```cpp
> bool vis[5][5] = {false};
> queue<pair<int,int>> que;
> vis[0][0] = true;          // 起点标记已访问
> que.push({0, 0});          // 起点入队
> int dx[] = {0,0,1,-1}, dy[] = {1,-1,0,0};
> while (!que.empty()) {
>     auto [x, y] = que.front(); que.pop();
>     if (x == 4 && y == 4) { /* 找到最短路 */ break; }
>     for (int i = 0; i < 4; i++) {
>         int nx = x + dx[i], ny = y + dy[i];
>         if (nx >= 0 && nx < 5 && ny >= 0 && ny < 5
>             && maze[nx][ny] == 0 && !vis[nx][ny]) {
>             vis[nx][ny] = true;
>             que.push({nx, ny});
>         }
>     }
> }
> ```
> 关键：入队时**立即**标记 visited，避免同一节点重复入队。

## 第 8 题 - 生日蛋糕 DFS 签名 [application]

> 设计生日蛋糕问题的 DFS 函数签名和参数含义。

> [!answer]- 查看答案
> ```cpp
> void dfs(int curr, int sumS, int sumV, int r, int h);
> ```
>
> | 参数 | 含义 |
> |------|------|
> | `curr` | 剩余待安排的层数（从底层往上数） |
> | `sumS` | 当前已建部分的表面积（不含 π，即 S 值） |
> | `sumV` | 当前已建部分的体积（不含 π） |
> | `r` | 上一层的半径（底层时为 N，约束下一层 < r） |
> | `h` | 上一层的高度（约束下一层 < h） |
>
> 终止：`curr == 0` 且 `sumV == N` 时更新 `best = min(best, sumS)`。

## 第 9 题 - 木棒剪枝效果 [analysis]

> 对比木棒问题使用/不使用剪枝时的搜索空间大小。为什么"从大到小排序"能显著减少搜索量？

> [!answer]- 查看答案
> **不使用剪枝**：S 可枚举到 `[max(a), sum]` 的每个整数，DFS 可任意选木棒组合，搜索树接近指数级。
>
> **使用剪枝后**：
> - 因子枚举将 S 候选从 O(sum) 降到 O(√sum) 量级
> - 二分查找将每层候选从 O(n) 降到 O(log n) 定位
> - 对称性剪枝消除等价分支
>
> **从大到小排序的原因**：长棍选择少、约束强，先确定长棍后短棍"填空"更灵活；若先拼短棍，大量等价排列会在失败后才被剪掉，搜索树膨胀。排序使**最优性/对称性剪枝更早生效**。

## 第 10 题 - 拯救公主判重反例 [analysis]

> 在拯救公主问题中，为什么不能简单地用 `visited[x][y] = true` 来判重？设计一个反例。

> [!answer]- 查看答案
> **原因**：同一格子 `(x, y)` 在不同宝石集合下是**不同状态**，简单二维 visited 会错误地剪掉仍需探索的路径。
>
> **反例**（K=2，需集齐两种宝石）：
> ```
> S . 0
> . 1 E
> ```
> 路径 A：S → 宝石0 → 宝石1 → E（11 步，可行）
> 路径 B：S → 宝石1 → 回到某格 → 再取宝石0 → E
>
> 若 `(x, y)` 在只持有宝石1时被标记 visited，则后续"持有 {0,1} 经过同一格"的状态会被错误跳过，可能漏掉更优或唯一可行解。
>
> 正确做法：`used[x][y][gem_mask]`，其中 `gem_mask = Σ 2^i`（i 为已收集的宝石种类）。
