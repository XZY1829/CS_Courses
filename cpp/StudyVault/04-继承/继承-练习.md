## 第 1 题 - protected理解 [recall]

> protected访问控制解决了什么矛盾？它和private、public各有什么区别？

> [!answer]- 查看答案
> 解决**继承与封装的矛盾**：派生类需要访问基类内部数据来实现新功能，但private阻止了这种访问。
> - **private**：本类+友元可访问，派生类和外部都不行
> - **protected**：本类+友元+派生类可访问，外部不行
> - **public**：所有人可访问

## 第 2 题 - 继承方式辨析 [application]

> 基类A有一个public成员f()和一个protected成员g()。分别在public、protected、private继承后，在派生类的外部能否调用f()和g()？

> [!answer]- 查看答案
> | 继承方式 | f()在外部 | g()在外部 |
> |----------|----------|----------|
> | public | ✓ (仍为public) | ✗ (仍为protected) |
> | protected | ✗ (变为protected) | ✗ (仍为protected) |
> | private | ✗ (变为private) | ✗ (变为private) |
> 
> 规则：继承方式是"天花板"，基类成员权限不会超过继承方式。

## 第 3 题 - 构造顺序分析 [application]

> 写出以下代码的输出：
> ```cpp
> class A { public: A() { cout << "A"; } ~A() { cout << "~A"; } };
> class B { public: B() { cout << "B"; } ~B() { cout << "~B"; } };
> class C : public A {
>     B b;
> public:
>     C() { cout << "C"; }
>     ~C() { cout << "~C"; }
> };
> int main() { C c; }
> ```

> [!answer]- 查看答案
> **输出**：`ABC~C~B~A`
> 
> 构造顺序：基类A → 成员对象b → 自身C
> 析构顺序：自身~C → 成员对象~B → 基类~A

## 第 4 题 - 名字隐藏陷阱 [application]

> 以下代码有什么问题？如何修复？
> ```cpp
> class Base {
> public:
>     void print(int x) { cout << x; }
>     void print(string s) { cout << s; }
> };
> class Derived : public Base {
> public:
>     void print() { cout << "hello"; }
> };
> Derived d;
> d.print(42);  // ?
> ```

> [!answer]- 查看答案
> **编译错误！** Derived中定义了`print()`，隐藏了Base中**所有**名为print的函数（包括`print(int)`和`print(string)`）。
> 
> 修复方案：
> 1. 使用 `using` 声明：在Derived中加 `using Base::print;`
> 2. 显式限定：`d.Base::print(42);`
> 
> ```cpp
> class Derived : public Base {
> public:
>     using Base::print;  // 引入基类所有print
>     void print() { cout << "hello"; }
> };
> ```

## 第 5 题 - 子类型转换 [recall]

> public继承下，为什么派生类对象可以赋值给基类引用？这背后的原理是什么？

> [!answer]- 查看答案
> - public继承建立了**IS-A关系**（子类型关系）
> - 派生类对象在内存中**包含**一个完整的基类子对象
> - 基类引用绑定到派生类对象时，实际上绑定到其中的基类子对象部分
> - 通过基类引用只能访问基类定义的接口，派生类的扩展部分被"切割"掉
> - 这是**类型安全**的：基类接口所有操作对派生类都有效

## 第 6 题 - 基类无默认构造 [application]

> 以下代码为何编译失败？如何修复？
> ```cpp
> class Animal {
>     string name;
> public:
>     Animal(string n) : name(n) {}
> };
> class Dog : public Animal {
>     int age;
> public:
>     Dog(int a) : age(a) {}
> };
> ```

> [!answer]- 查看答案
> **编译失败原因**：Animal只有`Animal(string)`构造函数，没有默认构造函数。Dog的构造函数没有在初始化表中指定调用哪个基类构造函数，编译器尝试调用`Animal()`失败。
> 
> **修复**：
> ```cpp
> Dog(int a) : Animal("unnamed"), age(a) {}
> // 或者更好的设计：
> Dog(string name, int a) : Animal(name), age(a) {}
> ```

## 第 7 题 - 继承与友元 [recall]

> "基类的友元不是派生类的友元"——解释这句话的含义并举例说明。

> [!answer]- 查看答案
> 含义：如果函数f是基类A的友元，它能访问A的private成员，但**不能**访问派生类B的private成员。
> ```cpp
> class A {
>     int x;
>     friend void show(A&);
> };
> class B : public A {
>     int y;  // show无法访问y！
> };
> void show(A& a) {
>     cout << a.x;  // OK，A的友元
>     // B& b = dynamic_cast<B&>(a);
>     // cout << b.y;  // Error! 不是B的友元
> }
> ```
> 友元关系**不继承**：这是友元"三不"原则之一。

## 第 8 题 - 切片问题 [application]

> 什么是对象切片(Slicing)？以下代码有什么问题？
> ```cpp
> class Base { int x; public: Base(int a):x(a){} };
> class Derived : public Base { int y; public: Derived(int a,int b):Base(a),y(b){} };
> Derived d(1, 2);
> Base b = d;  // 发生了什么？
> ```

> [!answer]- 查看答案
> **对象切片**：将派生类对象赋值给基类对象（非引用/指针），派生类独有的部分被"切掉"。
> - `b` 只包含 `Base` 部分（x=1），`Derived` 的 y=2 被丢弃
> - `b` 是一个纯粹的 Base 对象，不再与 Derived 有关
> - 这与通过基类引用/指针访问不同：引用/指针保留完整对象
> 
> **避免方法**：使用基类引用或指针来操作派生类对象

## 第 9 题 - 继承中的拷贝构造 [analysis]

> 如果派生类自定义了拷贝构造函数但忘记调用基类的拷贝构造函数，会发生什么？

> [!answer]- 查看答案
> 基类部分会调用**默认构造函数**（而不是拷贝构造函数）！
> 
> ```cpp
> class Derived : public Base {
> public:
>     Derived(const Derived& d) {  // 没有 : Base(d)
>         // 基类部分用默认构造初始化 → 基类数据不是从d复制的！
>     }
> };
> ```
> 
> 正确写法：
> ```cpp
> Derived(const Derived& d) : Base(d) { ... }
> // d 会隐式转换为 const Base& 传给基类拷贝构造
> ```

## 第 10 题 - 继承的设计选择 [analysis]

> 什么情况下应该用public继承？什么情况下用组合(has-a)更好？举例说明。

> [!answer]- 查看答案
> **public继承（IS-A）**：派生类"是一种"基类
> - Dog IS-A Animal ✓ → `class Dog : public Animal`
> - Student IS-A Person ✓
> 
> **组合（HAS-A）**：一个类"拥有"另一个类的对象
> - Car HAS-A Engine ✓ → `class Car { Engine engine; };`
> - Student HAS-A Name ✓
> 
> **错误示例**：
> - Stack继承自Vector ✗ — Stack不是一种Vector（接口不同）
> - 正确：Stack组合Vector（内部用Vector实现）
> 
> **判断原则**：如果B继承A，那么A的所有接口对B是否都有意义？如果不是，应该用组合。
