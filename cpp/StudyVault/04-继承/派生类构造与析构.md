# 派生类构造与析构（★★★）

#cpp #inheritance #constructor #destructor

## 概览表（一目了然）

| 条目 | 要点 |
|------|------|
| 构造顺序 | 基类 → 成员对象 → 派生类自身 |
| 析构顺序 | 派生类自身 → 成员对象 → 基类（与构造相反） |
| 指定基类构造 | 在成员初始化表中 `Base(args)` |
| 默认行为 | 不指定则调用基类默认构造函数 |
| 常见错误 | 基类无默认构造函数且派生类未显式调用 |

## 派生类构造函数

```cpp
class Base {
    int x;
public:
    Base(int a) : x(a) {}    // 无默认构造函数
};

class Derived : public Base {
    int y;
    MemberClass m;
public:
    Derived(int a, int b, int c) 
        : Base(a), m(c) {    // 初始化表中调用基类构造
        y = b;               // 自身初始化
    }
};
```

### 构造执行顺序详解

```
Derived d(1, 2, 3);
    │
    ├─ ① 调用 Base(1)          ← 基类子对象构造
    ├─ ② 调用 m 的构造函数      ← 成员对象构造（按声明顺序）
    └─ ③ 执行 Derived 构造体    ← 派生类自身
```

### 析构执行顺序

```
d 消亡时:
    │
    ├─ ① 执行 ~Derived()       ← 派生类析构体
    ├─ ② 调用 m 的析构函数      ← 成员对象（声明逆序）
    └─ ③ 调用 ~Base()          ← 基类子对象
```

## 常见场景与陷阱

### 场景1：基类无默认构造函数

```cpp
class Base {
public:
    Base(int x) {}  // 只有带参构造，没有默认构造
};

class Derived : public Base {
public:
    Derived() {}  // Error! 无法调用Base的默认构造函数
    Derived() : Base(0) {}  // OK! 显式指定
};
```

### 场景2：多层继承的构造

```cpp
class A { public: A(int); };
class B : public A { public: B(int x) : A(x) {} };
class C : public B { public: C(int x) : B(x) {} };
// C的构造 → 调用B(x) → B调用A(x)
// 每个类只负责自己直接基类的初始化
```

### 场景3：拷贝构造中的基类部分

```cpp
class Derived : public Base {
public:
    Derived(const Derived& d) : Base(d) {  // 用d初始化基类部分
        // d会被隐式转换为Base引用（子类型转换）
        // ...
    }
};
```

> [!warning] 如果派生类自定义拷贝构造但不调用基类拷贝构造
> 基类部分会调用**默认构造函数**而非拷贝构造，导致基类成员未正确复制！

## 考试/测试常见模式

| 场景/关键词 | 答案 |
|-------------|------|
| "构造顺序" | 基类→成员对象→自身 |
| "析构顺序" | 与构造完全相反 |
| "不指定基类构造" | 调用基类默认构造函数 |
| "基类无默认构造" | 派生类必须显式指定，否则编译错误 |
| "谁负责初始化基类" | 直接派生类（每层只管自己的直接基类） |
