## 第 1 题 - 类的访问控制 [recall]

> class和struct在C++中有什么区别？在什么情况下选用struct更合适？

> [!answer]- 查看答案
> **唯一区别**：默认访问控制不同
> - `class`：默认 private
> - `struct`：默认 public
> 
> **选用struct的场景**：
> - 简单数据聚合体（只有数据，少量或无方法）
> - 希望所有成员默认公开（如POD类型）
> - 与C代码兼容

## 第 2 题 - this指针理解 [recall]

> 什么是this指针？它的类型是什么？为什么静态成员函数没有this？

> [!answer]- 查看答案
> - **this** 是每个非静态成员函数的隐藏参数，指向调用该函数的对象
> - **类型**：`ClassName *const this`（指针本身是常量，不可修改指向）
> - **静态成员函数没有this**的原因：静态成员函数不属于任何具体对象，而是属于类本身。它们不需要对象就可以调用（如 `A::staticFunc()`），因此没有"当前对象"的概念。

## 第 3 题 - 链式调用分析 [application]

> 分析以下代码的输出：
> ```cpp
> class Counter {
>     int n;
> public:
>     Counter() : n(0) {}
>     Counter& add() { n++; return *this; }
>     Counter copy_add() { n++; return *this; }
>     void print() { cout << n << endl; }
> };
> Counter c;
> c.add().add().add();
> c.print();           // 输出？
> Counter d;
> d.copy_add().copy_add().copy_add();
> d.print();           // 输出？
> ```

> [!answer]- 查看答案
> - `c.print()` 输出 **3**：`add()` 返回引用，三次操作都作用于c本身
> - `d.print()` 输出 **1**：`copy_add()` 返回副本，第一次后链式操作在临时副本上进行，d只被增加了1次

## 第 4 题 - 构造函数重载 [application]

> 以下代码哪些行会编译错误？为什么？
> ```cpp
> class A {
> public:
>     A() {}
>     A(int x) {}
>     A(int x, int y = 0) {}
> };
> A a1;
> A a2(1);
> A a3(1, 2);
> ```

> [!answer]- 查看答案
> - `A a1;` — **OK**，调用 `A()`
> - `A a2(1);` — **编译错误！歧义**：可以匹配 `A(int x)` 也可以匹配 `A(int x, int y=0)`
> - `A a3(1, 2);` — **OK**，只匹配 `A(int x, int y=0)`
> 
> 教训：带默认参数的构造函数与其他重载可能产生歧义。

## 第 5 题 - 成员初始化表 [recall]

> 为什么const成员和引用成员必须用成员初始化表而不能在构造函数体中用赋值？

> [!answer]- 查看答案
> - **const成员**：const变量一旦初始化就不可修改。进入构造函数体时，成员已经完成了"默认初始化"，此时赋值实际上是"修改"，对const非法。
> - **引用成员**：引用必须在定义时绑定，且绑定后不可更改。在函数体中"赋值"给引用只是修改引用所指向对象的值，而不是重新绑定。
> - 成员初始化表是**真正的初始化**发生的地方，构造函数体内只是**赋值**。

## 第 6 题 - 初始化顺序陷阱 [application]

> 以下代码中，x和y的最终值分别是什么？
> ```cpp
> class A {
>     int x;
>     int y;
> public:
>     A() : y(10), x(y) {}
> };
> ```

> [!answer]- 查看答案
> - **x = 未定义值（垃圾值）！** 
> - **y = 10**
> 
> 原因：初始化顺序由**声明顺序**决定（先x后y），而非初始化表的书写顺序。
> - x先被初始化为y的值，但此时y还没初始化 → x得到垃圾值
> - 然后y被初始化为10
> 
> 这是一个典型的陷阱！应确保初始化表的书写顺序与声明顺序一致。

## 第 7 题 - 析构函数设计 [application]

> 为以下类编写析构函数，解释为什么需要自定义析构函数：
> ```cpp
> class DynamicArray {
>     int *data;
>     int size;
> public:
>     DynamicArray(int n) : size(n) { data = new int[n]; }
> };
> ```

> [!answer]- 查看答案
> ```cpp
> ~DynamicArray() { delete[] data; }
> ```
> **需要自定义析构函数的原因**：
> - 构造函数中用 `new int[n]` 额外申请了堆内存
> - 如果不自定义析构函数，对象消亡时只回收对象本身的内存（data指针和size），不会回收data指向的堆内存
> - 结果：**内存泄漏** — 每创建一个DynamicArray对象就泄漏一块堆内存

## 第 8 题 - 对象创建方式辨析 [recall]

> 比较直接方式和间接方式创建对象的区别，各适用于什么场景？

> [!answer]- 查看答案
> | 维度 | 直接方式 | 间接方式 (new) |
> |------|----------|---------------|
> | 存储位置 | 栈或静态区 | 堆 |
> | 生命周期 | 自动管理（离开作用域消亡） | 手动管理（必须delete） |
> | 访问方式 | 对象名 (`a.f()`) | 指针 (`p->f()`) |
> | 适用场景 | 生命周期确定、不太大的对象 | 生命周期不确定、大对象、需要多态 |
> | 性能 | 分配快（移动栈指针） | 分配慢（堆管理开销） |
> | 风险 | 栈溢出（对象太大） | 内存泄漏（忘记delete） |

## 第 9 题 - 对象作为参数传递 [analysis]

> 比较以下三种函数参数声明的区别，各有什么优缺点？
> ```cpp
> void f1(A a);
> void f2(A &a);
> void f3(const A &a);
> ```

> [!answer]- 查看答案
> | 声明 | 传递方式 | 是否复制 | 能否修改原对象 | 适用场景 |
> |------|----------|---------|---------------|---------|
> | `A a` | 传值 | 复制一份 | 不能 | 需要独立副本 |
> | `A &a` | 传引用 | 不复制 | 能 | 需要修改实参 |
> | `const A &a` | const引用 | 不复制 | 不能 | 只读大对象（最常用） |
> 
> **推荐原则**：
> - 小类型(int, double等)：直接传值
> - 大对象只读：`const A &`
> - 大对象需修改：`A &`
> - 需要副本：传值或 `A` 然后 move

## 第 10 题 - 构造析构顺序 [analysis]

> 分析以下代码的构造和析构顺序：
> ```cpp
> class A { public: A() { cout << "A"; } ~A() { cout << "~A"; } };
> class B { public: B() { cout << "B"; } ~B() { cout << "~B"; } };
> class C {
>     A a;
>     B b;
> public:
>     C() { cout << "C"; }
>     ~C() { cout << "~C"; }
> };
> int main() { C c; }
> ```

> [!answer]- 查看答案
> **输出**：`ABC~C~B~A`
> 
> **构造顺序**：
> 1. 成员对象按声明顺序构造：先 a(输出A)，后 b(输出B)
> 2. 然后执行C的构造函数体（输出C）
> 
> **析构顺序**（与构造相反）：
> 1. 先执行C的析构函数体（输出~C）
> 2. 成员对象按声明逆序析构：先 b(输出~B)，后 a(输出~A)
