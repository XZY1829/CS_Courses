# 智能指针（★★★）

#cpp #oop #smart-pointer #RAII #memory-management

## 概览表（一目了然）

| 条目 | 要点 |
|------|------|
| 问题 | 裸指针易导致内存泄漏、悬空指针、双重释放 |
| 解决 | 用对象管理指针，析构时自动释放（RAII） |
| 核心原理 | 重载 `*` 和 `->` 操作符，表现得像指针 |
| 标准库 | `unique_ptr`（独占）、`shared_ptr`（共享）、`weak_ptr`（弱引用） |

## 智能指针的原理

利用**RAII**（资源获取即初始化）+ **操作符重载**：

```cpp
template<class T>
class SmartPtr {
    T *ptr;
public:
    SmartPtr(T *p = nullptr) : ptr(p) {}
    ~SmartPtr() { delete ptr; }       // 自动释放！
    T& operator*() { return *ptr; }   // 解引用
    T* operator->() { return ptr; }   // 成员访问
};

// 使用
{
    SmartPtr<int> p(new int(42));
    cout << *p;  // 输出42
}   // 离开作用域 → p析构 → 自动delete！
```

## 三种标准智能指针

### unique_ptr — 独占所有权

```cpp
unique_ptr<int> p1(new int(10));
// unique_ptr<int> p2 = p1;  // Error! 不能复制
unique_ptr<int> p2 = move(p1);  // OK，转移所有权
```

- 同一时刻只有一个unique_ptr拥有资源
- 不可复制，只可移动
- 开销最小（无额外引用计数）

### shared_ptr — 共享所有权

```cpp
shared_ptr<int> p1 = make_shared<int>(10);
shared_ptr<int> p2 = p1;  // OK! 引用计数+1
// p1和p2都指向同一对象
// 最后一个shared_ptr销毁时释放资源
```

- 引用计数：跟踪有多少个shared_ptr共享资源
- 计数降为0时自动释放
- 额外开销：引用计数的内存和原子操作

### weak_ptr — 弱引用（不增加计数）

```cpp
shared_ptr<int> sp = make_shared<int>(42);
weak_ptr<int> wp = sp;  // 不增加引用计数
// 使用前需要lock()转为shared_ptr
if (auto p = wp.lock()) {
    cout << *p;
}
```

- 解决shared_ptr的**循环引用**问题
- 不拥有资源，只是观察者

## 裸指针 vs 智能指针

| 维度 | 裸指针 | 智能指针 |
|------|--------|----------|
| 释放 | 手动delete | 自动（析构时） |
| 异常安全 | 可能泄漏 | 异常安全 |
| 所有权 | 不明确 | 明确（unique/shared） |
| 开销 | 无 | 极小(unique)/小(shared) |
| 推荐 | 仅观察性使用 | 拥有资源时始终使用 |

## 考试/测试常见模式

| 场景/关键词 | 答案 |
|-------------|------|
| "智能指针原理" | RAII + 重载*和-> |

| "shared_ptr特点" | 共享所有权，引用计数 |
| "循环引用问题" | 两个shared_ptr互指→永不释放→用weak_ptr打破 |
| "为什么需要智能指针" | 防止内存泄漏，异常安全，所有权明确 |
