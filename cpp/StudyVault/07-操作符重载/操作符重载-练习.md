## 第 1 题 - 成员vs友元选择 [recall]

> 哪些操作符必须用成员函数重载？哪些适合用友元？为什么？

> [!answer]- 查看答案
> **必须成员**：`=`, `[]`, `()`, `->`, 类型转换
> - 原因：语言规定，防止全局版本干扰
> 
> **适合友元**：`<<`, `>>`, 对称二元操作符(+, ==)
> - `<<`/`>>`：左操作数是ostream/istream，不是本类
> - 对称操作符：两个操作数都需要隐式转换的能力

## 第 2 题 - 赋值操作符四步 [recall]

> 自定义赋值操作符的标准四步是什么？每步为什么必要？

> [!answer]- 查看答案
> 1. **自赋值检查** `if(this==&s) return *this;` — 防止释放后从已释放内存读取
> 2. **释放旧资源** `delete[] str;` — 防止内存泄漏
> 3. **深复制** `str = new char[...]; strcpy(...)` — 获取独立副本
> 4. **返回*this** `return *this;` — 支持链式赋值 `a=b=c`

## 第 3 题 - 前缀后缀++输出 [application]

> 写出输出结果：
> ```cpp
> class N {
>     int val;
> public:
>     N(int v):val(v){}
>     N& operator++() { val++; return *this; }
>     N operator++(int) { N old=*this; val++; return old; }
>     friend ostream& operator<<(ostream& os, const N& n) { return os<<n.val; }
> };
> N a(5);
> cout << a++ << " " << ++a << " " << a;
> ```

> [!answer]- 查看答案
> 注意：C++中函数参数求值顺序**未定义**！不同编译器可能不同。
> 
> 但如果分开写：
> ```cpp
> N a(5);
> cout << a++;  // 输出5（返回旧值），a变6
> cout << ++a;  // a变7，输出7
> cout << a;    // 输出7
> ```
> 输出：`5 7 7`
> 
> 教训：不要在同一表达式中对同一对象多次++。

## 第 4 题 - String类实现（机试核心题） [application]

> 为String类实现operator+（字符串拼接），要求返回新String。

> [!answer]- 查看答案
> ```cpp
> class String {
>     char *str; int len;
> public:
>     // 假设已有构造函数和析构函数
>     friend String operator+(const String& a, const String& b) {
>         String result;
>         result.len = a.len + b.len;
>         result.str = new char[result.len + 1];
>         strcpy(result.str, a.str);
>         strcat(result.str, b.str);
>         return result;
>     }
> };
> ```
> 关键：返回值而非引用（创建了新对象），内部新分配内存。

## 第 5 题 - []操作符设计 [application]

> 为什么下标操作符通常需要两个版本（const和非const）？

> [!answer]- 查看答案
> ```cpp
> int& operator[](int i) { return data[i]; }              // 可读写
> const int& operator[](int i) const { return data[i]; }  // 只读
> ```
> - **非const版本**：用于普通对象，返回引用可以赋值 `v[0] = 10;`
> - **const版本**：用于const对象，只能读取 `const Vector cv; int x = cv[0];`
> - 如果只有非const版本，const对象无法使用[]

## 第 6 题 - 函数对象设计 [application]

> 设计一个函数对象InRange，判断给定值是否在[low, high]范围内。

> [!answer]- 查看答案
> ```cpp
> class InRange {
>     int low, high;
> public:
>     InRange(int l, int h) : low(l), high(h) {}
>     bool operator()(int x) const {
>         return x >= low && x <= high;
>     }
> };
> // 使用
> InRange r(1, 10);
> cout << r(5);   // 1 (true)
> cout << r(15);  // 0 (false)
> // 与STL配合
> count_if(v.begin(), v.end(), InRange(1,10));
> ```

## 第 7 题 - 智能指针引用计数（机试题） [application]

> 解释以下SmartPointer代码中，为什么ref_count需要用指针(int*)而非普通int？

> [!answer]- 查看答案
> ```cpp
> class SmartPtr {
>     int *ptr;
>     int *ref_count;  // 为什么是指针？
> };
> ```
> 因为**多个SmartPtr对象需要共享同一个计数**。
> - 如果是 `int ref_count`，每个SmartPtr有自己的count副本，无法同步
> - 用 `int*` 指向堆上同一个int，所有共享同一资源的SmartPtr修改的是同一个count
> - 拷贝时：新SmartPtr的ref_count指向相同位置，`(*ref_count)++`

## 第 8 题 - <<操作符链式调用 [recall]

> 为什么operator<<必须返回ostream&？如果返回void会怎样？

> [!answer]- 查看答案
> 返回`ostream&`的原因：支持链式调用 `cout << a << b << c`
> 
> 展开：`((cout << a) << b) << c`
> - `cout << a` 返回 `ostream&`(即cout本身)
> - 然后对返回的cout调用 `<< b`
> 
> 如果返回void：
> - `cout << a` 返回void
> - `void << b` → 编译错误！无法链式

## 第 9 题 - 类型转换操作符 [application]

> 以下代码有什么潜在问题？如何修复？
> ```cpp
> class Fraction {
> public:
>     operator double() const { return (double)num/den; }
>     operator int() const { return num/den; }
> };
> Fraction f(3,2);
> double d = f + 1.0;  // 可能歧义？
> ```

> [!answer]- 查看答案
> **潜在问题**：隐式类型转换可能导致意外行为或歧义。
> - `f + 1.0`：编译器不确定该用operator double()还是operator int()
> - 可能在不期望的地方发生隐式转换
> 
> **修复**：C++11使用 `explicit` 关键字
> ```cpp
> explicit operator double() const { return (double)num/den; }
> // 必须显式转换：double d = static_cast<double>(f) + 1.0;
> ```

## 第 10 题 - Rule of Five [analysis]

> C++11的"五法则"(Rule of Five)是什么？为什么从"三法则"扩展到"五法则"？

> [!answer]- 查看答案
> **Rule of Five**：如果自定义了以下任一，应该考虑全部自定义：
> 1. 析构函数
> 2. 拷贝构造函数
> 3. 拷贝赋值操作符
> 4. **移动构造函数**（C++11新增）
> 5. **移动赋值操作符**（C++11新增）
> 
> **为什么扩展**：C++11引入了右值引用和移动语义。如果类管理资源，应该提供移动操作以避免不必要的深拷贝，提高效率。
> 
> 例如：返回局部String对象时，有移动构造则"窃取"资源（O(1)），无则深拷贝（O(n)）。
