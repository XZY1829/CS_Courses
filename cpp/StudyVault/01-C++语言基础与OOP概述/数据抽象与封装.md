# 数据抽象与封装（★★★）

#cpp #oop #encapsulation #abstraction

## 概览表（一目了然）

| 条目 | 要点 |
|------|------|
| 数据抽象 | 将数据的表示与操作捆绑在一起，对外只暴露操作接口 |
| 封装 | 将实现细节隐藏起来，只通过公开接口访问 |
| 信息隐藏 | 封装的目的：保护内部数据不被外部直接修改 |
| ADT | 抽象数据类型 = 数据表示 + 操作集合 |
| C++实现 | 通过 class 的 public/private/protected 访问控制 |

## 什么是数据抽象

**核心思想**：把数据和对数据的操作作为一个整体来对待。

- **过程抽象**（传统）：把一组操作抽象为一个函数，隐藏操作细节
- **数据抽象**（OOP）：把数据和操作捆绑在一起，隐藏数据的内部表示

```
过程式思维：数据 + 函数（分离）
OOP思维：  对象 = 数据 + 操作（统一）
```

## 封装 (Encapsulation)

**定义**：将对象的属性（数据）和行为（操作）结合为一个独立整体，隐藏内部实现，只暴露有限的外部接口。

**三层含义**：
1. **组合** — 数据和操作放在一起
2. **隐藏** — 内部细节对外不可见
3. **保护** — 外部只能通过指定接口操作数据

**类比**：
- 电视机 = 封装体
- 遥控器按钮 = 公开接口 (public)
- 内部电路 = 隐藏实现 (private)

## 信息隐藏 (Information Hiding)

| 公开的 | 隐藏的 |
|--------|--------|
| 操作接口（做什么） | 数据表示（用什么存） |
| 函数原型 | 函数实现细节 |
| 类的public成员 | 类的private成员 |

**好处**：
- 修改内部实现不影响外部代码
- 防止外部代码依赖实现细节
- 强制通过接口操作，保证数据一致性

## 抽象数据类型 (ADT)

**ADT = 数据值的集合 + 定义在该集合上的操作**

```
ADT Stack:
  数据：一组元素（后进先出）
  操作：push(x), pop(), top(), isEmpty()
```

C++中，**class 就是 ADT 的实现机制**：

```cpp
class Stack {
private:
    int data[100];  // 数据表示（隐藏）
    int top_idx;
public:
    void push(int x);  // 操作接口（公开）
    int pop();
    int top();
    bool isEmpty();
};
```

## 访问控制

| 关键字 | 可访问范围 | 设计意图 |
|--------|-----------|----------|
| `public` | 任何地方 | 对外接口 |
| `private` | 仅本类成员函数 | 隐藏实现 |
| `protected` | 本类 + 派生类 | 继承时开放 |

> [!important] class vs struct 的默认访问权限
> - `class`：默认 **private**
> - `struct`：默认 **public**
> - 除此之外，class和struct在C++中完全等价

## 封装的意义

```
         ┌─────────────────────┐
  外部 → │  public 接口         │ ← 唯一访问入口
         ├─────────────────────┤
         │  private 数据+实现   │ ← 修改不影响外部
         └─────────────────────┘
```

1. **可维护性**：内部表示可自由修改
2. **正确性**：数据操作受控，不会出现非法状态
3. **模块化**：类是自包含的模块单元
