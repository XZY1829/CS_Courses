## 第 1 题 - inline函数与宏定义 [recall]

> 内联函数相比带参数的宏定义有哪些优势？列举至少三点。

> [!answer]- 查看答案
> 1. **类型检查**：inline函数遵循函数调用规定，编译器会进行参数类型检查和转换
> 2. **无重复计算**：宏展开时参数可能被多次求值（如`max(a++,b)`），inline不会
> 3. **调试友好**：调试器可以在inline函数上设断点，宏在预处理后不存在
> 4. **不需要大量括号**：宏需要给每个参数加括号防止运算优先级问题

## 第 2 题 - new/delete vs malloc/free [recall]

> 在C++中创建动态对象时，为什么推荐使用new/delete而不是malloc/free？如果混用会怎样？

> [!answer]- 查看答案
> - `new`除了分配内存，还会调用对象的**构造函数**进行初始化
> - `delete`除了释放内存，还会调用对象的**析构函数**进行清理
> - `malloc/free`只管内存分配和释放，不涉及构造/析构
> - 混用后果：如果`new`分配后用`free`释放，析构函数不会被调用，可能导致资源泄漏（如文件未关闭、内存未释放等）
> - **规则**：new配delete，new[]配delete[]，malloc配free

## 第 3 题 - 引用类型辨析 [recall]

> 引用类型与指针类型有哪些区别？至少列举四点。

> [!answer]- 查看答案
> | 引用 | 指针 |
> |------|------|
> | 定义时必须初始化 | 可以不初始化（但不推荐） |
> | 初始化后不可重绑定 | 可改变指向 |
> | 不能为null | 可以为nullptr |
> | 语法与普通变量相同 | 需要`*`解引用、`&`取地址 |
> | 底层实现为隐藏指针 | 显式指针 |
> | 更安全（不可能悬空引用...理论上） | 可能野指针 |

## 第 4 题 - 函数重载绑定 [application]

> 给定以下重载函数，分析每个调用绑定到哪个函数：
> ```cpp
> void f(int x);       // (1)
> void f(double x);    // (2)
> void f(char x);      // (3)
> ```
> 调用：`f(3.14f)`、`f('a')`、`f(10L)`

> [!answer]- 查看答案
> - `f(3.14f)`：float通过**提升匹配**→double，绑定到 **(2)**
> - `f('a')`：
>   - 精确匹配(3) char ✓，绑定到 **(3)**
> - `f(10L)`：long类型
>   - 无精确匹配；提升匹配无适用规则
>   - 标准转换：long可转int也可转double也可转char → **歧义，编译失败！**

## 第 5 题 - const引用参数 [recall]

> 为什么函数参数中经常看到 `const int &x` 这种写法？它起什么作用？

> [!answer]- 查看答案
> 两个作用：
> 1. **效率**：使用引用避免复制大对象（对int等小类型效果不明显，但对大struct/class有意义）
> 2. **安全**：const保证函数内部不会修改实参的值
> 额外好处：const引用可以绑定到临时量（右值），如`f(3+5)`，而非const引用不行。

## 第 6 题 - 缺省参数陷阱 [application]

> 以下代码是否能编译通过？为什么？
> ```cpp
> void f(int a, int b=1, int c);
> ```

> [!answer]- 查看答案
> **不能编译通过。** 
> 规则：有默认值的参数必须全部位于参数表的右部。b有默认值但c没有，c在b右边，违反规则。
> 正确写法：`void f(int a, int c, int b=1);` 或 `void f(int a, int b=1, int c=0);`

## 第 7 题 - 名空间使用 [recall]

> C++中，using namespace std; 做了什么？为什么有些编码规范不推荐在头文件中使用它？

> [!answer]- 查看答案
> - `using namespace std;` 将std名空间中所有标识符引入当前作用域，无需再写`std::`前缀
> - 不推荐在**头文件**中使用的原因：头文件可能被很多源文件include，污染所有包含它的文件的全局名空间，可能导致名冲突
> - 推荐做法：在.cpp源文件中使用，或只用 `using std::cout;` 引入特定标识符

## 第 8 题 - 内存泄漏分析 [application]

> 分析以下代码的内存泄漏问题：
> ```cpp
> void f() {
>     int *p = new int[100];
>     // ... 使用p ...
>     if (someCondition) return;  // 提前返回
>     delete[] p;
> }
> ```

> [!answer]- 查看答案
> 当`someCondition`为true时，函数提前return，`delete[] p`不会执行。
> - p指向的100个int的动态数组永远无法被释放 → **内存泄漏**
> - 修复方案1：在return前加`delete[] p;`
> - 修复方案2：使用智能指针`std::unique_ptr<int[]> p(new int[100]);`，自动管理生命周期

## 第 9 题 - 引用返回值陷阱 [application]

> 以下代码输出什么？存在什么问题？
> ```cpp
> int& f() {
>     int x = 42;
>     return x;
> }
> int main() {
>     int &r = f();
>     cout << r;
> }
> ```

> [!answer]- 查看答案
> **未定义行为！** 
> - 函数f返回局部变量x的引用
> - f返回后，x的栈空间被回收
> - r绑定到已无效的内存，读取r是未定义行为
> - 可能输出42（运气好，栈还没被覆盖），也可能输出垃圾值或崩溃
> - **规则**：永远不要返回局部变量的引用或指针！

## 第 10 题 - 封装的意义 [recall]

> 面向对象编程中"封装"的三层含义是什么？为什么说封装提高了可维护性？

> [!answer]- 查看答案
> 三层含义：
> 1. **组合**：数据和操作放在同一个类中
> 2. **隐藏**：内部实现细节对外不可见（private）
> 3. **保护**：外部只能通过public接口操作数据
> 
> 提高可维护性的原因：
> - 修改类的内部数据表示（如数组改成链表）不影响外部代码
> - 外部代码只依赖接口，接口不变则外部不需修改
> - 数据通过接口操作，保证了状态的一致性

## 第 11 题 - 过程式vs面向对象 [analysis]

> 比较过程式程序设计和面向对象程序设计在"软件复用"方面的差异。为什么说OOP更有利于复用？

> [!answer]- 查看答案
> **过程式复用的困难**：
> - 函数通常针对特定程序的具体功能设计，通用性低
> - 数据与操作分离，复用操作时还需关心数据格式
> - 修改接口可能影响所有调用者
>
> **OOP复用的优势**：
> - 类具有通用性，是自包含的模块（数据+操作）
> - **继承**：子类自动获得父类的能力，只需添加/修改差异部分
> - **组合**：通过包含其他类对象复用功能
> - 封装保证了接口稳定性，内部修改不影响复用者
> - 多态机制使得程序可以面向接口编程，新增类型无需修改已有代码

## 第 12 题 - 动态绑定场景 [analysis]

> 什么情况下必须使用动态绑定而非静态绑定？举例说明动态绑定如何使程序更易扩展。

> [!answer]- 查看答案
> **必须使用动态绑定的场景**：
> 通过父类指针或引用向对象发送消息时，编译时无法确定对象的实际类型。
> 
> **示例**：
> ```cpp
> class Shape { public: virtual void draw() = 0; };
> class Circle : public Shape { void draw() { /*画圆*/ } };
> class Rect : public Shape { void draw() { /*画矩形*/ } };
> 
> void render(Shape *shapes[], int n) {
>     for (int i=0; i<n; i++)
>         shapes[i]->draw();  // 动态绑定：运行时决定调哪个draw
> }
> ```
> 
> **易扩展性**：新增Triangle类只需继承Shape并实现draw()，render函数完全不需修改。这就是"对扩展开放，对修改关闭"的OCP原则。
