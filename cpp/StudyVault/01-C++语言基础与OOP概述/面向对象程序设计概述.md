| 条目 | 要点 |
|------|------|
| 核心思想 | 以数据（对象）为中心，操作依附于数据 |

## 面向对象程序设计的基本概念

### 对象 (Object)

- 程序的基本计算单位
- 包含**数据**（属性/状态）和**操作**（行为/方法）
- 对象之间通过**消息**交互

### 类 (Class)

- 对象的"模板"或"蓝图"
- 描述一类对象的共同特征
- 对象是类的**实例**

### 消息 (Message)

- 对象之间的通信机制
- 向对象发消息 = 调用对象的成员函数
- `obj.method(args)` ← 向obj发送method消息

## OOP的四大核心特征

### 1. 抽象 (Abstraction)

控制复杂度，只关注问题的关键特征。

### 2. 封装 (Encapsulation)

数据和操作捆绑，保护内部细节。参见 [[数据抽象与封装]]。

### 3. 继承 (Inheritance)

```
     ┌────────┐
     │ 基类    │ ← 公共特征
     └────┬───┘
     ┌────┴────┐
  ┌──┴──┐  ┌──┴──┐
  │子类A │  │子类B │ ← 特化/扩展
  └─────┘  └─────┘
```

- **单继承**：一个子类只有一个基类
- **多继承**：一个子类有多个基类
- 实现**代码复用**：子类自动拥有基类的成员

### 4. 多态 (Polymorphism)

"一名多用" — 相同操作在不同对象上有不同行为。

**多态的分类**：

| 类型 | 说明 | 示例 |
|------|------|------|
| 函数名重载 | 同名不同参 | `print(int)`, `print(double)` |
| 操作符重载 | 同一操作符不同含义 | `+`对整数和字符串 |
| 类属（泛型） | 一份代码适用多类型 | `template<class T>` |
| OOP多态 | 子类重写父类行为 | 虚函数+动态绑定 |

**OOP特有的多态**（继承带来的）：
- **对象类型多态**：子类对象既属于子类，也属于父类
- **对象标识多态**：父类指针/引用可指向子类对象
- **消息多态**：父子类对同一消息给出不同处理

### 绑定 (Binding)

| 绑定方式 | 时机 | 适用 |
|----------|------|------|
| 静态绑定 | 编译时 | 函数重载、操作符重载 |
| 动态绑定 | 运行时 | 虚函数、多态消息 |

## 过程式 vs 面向对象

| 维度 | 过程式 | 面向对象 |
|------|--------|----------|
| 中心 | 功能（过程） | 数据（对象） |
| 抽象 | 过程抽象 | 数据抽象 |
| 封装 | 操作封装（数据公开） | 数据+操作封装 |
| 模块 | 子程序 | 对象类 |
| 复用 | 困难（针对特定功能） | 继承+组合（通用性强） |
| 维护 | 功能易变，维护困难 | 类相对稳定，维护方便 |
| 模型 | 与问题空间差距大 | 与问题空间自然对应 |

## OOP带来的好处

1. **抽象** → 控制复杂度
2. **封装** → 保护信息
3. **模块化** → 组织和管理大程序
4. **软件复用** → 缩短开发周期
5. **可维护性** → 延长软件寿命
6. **自然度** → 缩小问题空间与解题空间的间隙
