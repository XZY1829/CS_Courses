# 消息传递机制（★★☆）

#cpp #oop #polymorphism #message-passing

## 概览表（一目了然）

| 条目 | 要点 |
|------|------|
| 消息 | 对对象的函数调用就是向对象"发送消息" |
| 消息多态性 | 不同类型对象可处理相同消息，但方式不同 |
| 静态绑定 | 编译时确定消息处理函数（根据声明类型） |
| 动态绑定 | 运行时确定消息处理函数（根据实际类型） |
| 触发条件 | 基类指针/引用 + virtual函数 |

## 面向对象中的"消息"

在OOP中，"消息"是一个隐喻：调用对象的成员函数 = 向对象发送消息。

```cpp
a.f();    // 向对象a发送消息"f"
p->g(x);  // 通过指针向对象发送消息"g"，附带参数x
```

**消息的三要素**：接收者（对象） + 消息名（函数名） + 参数

## 消息的多态性

不同类型的对象可以处理相同的消息，但处理方式不同：

```cpp
class A {
public:
    void f() { cout << "A处理消息f" << endl; }
};
class B {
public:
    void f() { cout << "B处理消息f" << endl; }
};

A a; B b;
a.f();  // A的方式处理
b.f();  // B的方式处理
```

## 静态绑定 vs 动态绑定

### 静态绑定

编译时根据变量**声明类型**确定调用哪个函数：

```cpp
void func(A& x) {
    x.f();  // 始终调用A::f（编译时已确定）
}
A a; func(a);  // A::f
B b; func(b);  // 仍然是A::f！（B是A的派生类）
```

### 动态绑定

运行时根据对象**实际类型**确定调用哪个函数：

```cpp
class A {
public:
    virtual void f();  // 声明为虚函数
};
class B : public A {
public:
    void f();  // 重写
};

void func(A& x) {
    x.f();  // 动态绑定：看x实际引用的是什么
}
A a; func(a);  // 调用A::f
B b; func(b);  // 调用B::f ← 动态绑定的效果
```

## 动态绑定的三个必要条件

1. 基类中函数声明为 `virtual`
2. 派生类中**重写**（override）该函数（同名、同参数、同返回类型）
3. 通过**基类指针或引用**调用

> [!warning] 三者缺一不可
> - 没有virtual → 静态绑定
> - 不是重写（参数不同） → 调用基类版本
> - 不通过指针/引用（直接用对象） → 静态绑定

## 消息传递的实际应用

```cpp
// 统一接口处理不同对象
void drawAll(Shape* shapes[], int n) {
    for (int i = 0; i < n; i++)
        shapes[i]->draw();  // 消息"draw"被不同子类处理
}
```

这就是**多态**的本质：同一条消息，不同对象以不同方式响应。
