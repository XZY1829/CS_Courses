# 事件驱动程序设计（★★☆）

#cpp #event-driven #message-loop #callback #windows

## 概览表（一目了然）

| 条目 | 要点 |
|------|------|
| 核心思想 | 程序的每个动作都由事件(消息)激发 |
| 消息循环 | 取消息→分发→处理，直到WM_QUIT |
| 消息处理 | switch-case分发到不同处理逻辑 |
| 层次 | 过程式(WinAPI) → OOP(MFC/Qt) → 框架 |
| Windows消息 | WM_KEYDOWN, WM_PAINT, WM_COMMAND... |

## 事件驱动 vs 顺序执行

| 维度 | 顺序执行（控制台） | 事件驱动（GUI） |
|------|-------------------|----------------|
| 流程控制 | 程序决定执行顺序 | 用户事件决定 |
| 等待 | 阻塞等待输入 | 消息循环等待 |
| 交互 | 按程序安排的顺序 | 任意时刻任意操作 |

## Windows消息机制

```
用户操作(键盘/鼠标)
        │
        ↓
   Windows系统
        │
        ↓ (消息放入队列)
 ┌─────────────────┐
 │ 应用程序消息队列  │
 └───────┬─────────┘
         │ GetMessage()
         ↓
    消息循环(while)
         │ DispatchMessage()
         ↓
   窗口消息处理函数
    switch(message)
```

## 过程式事件驱动 (Windows API)

```cpp
// 主函数框架
int WinMain(...) {
    RegisterClass(...);          // 注册窗口类
    CreateWindow(...);           // 创建主窗口
    while (GetMessage(&msg,...)) // 消息循环
        DispatchMessage(&msg);   // 分发消息
    return msg.wParam;
}

// 消息处理函数
LRESULT WindowProc(HWND hWnd, UINT msg, WPARAM w, LPARAM l) {
    switch (msg) {
        case WM_KEYDOWN: /* 键盘按下 */ break;
        case WM_PAINT:   /* 窗口刷新 */ break;
        case WM_CLOSE:   DestroyWindow(hWnd); break;
        case WM_DESTROY: PostQuitMessage(0); break;
        default: return DefWindowProc(hWnd, msg, w, l);
    }
    return 0;
}
```

## 面向对象的事件驱动

将消息处理从switch-case改为**类的方法**：

```
┌──────────────────────┐
│  CWnd (窗口基类)      │
│  ├ OnKeyDown()       │
│  ├ OnPaint()         │
│  ├ OnCommand()       │
│  └ ...               │
├──────────────────────┤
│  CMyWnd (自定义窗口)  │
│  └ OnKeyDown() 重写  │
└──────────────────────┘
```

消息映射(Message Map)：将Windows消息映射到类的成员函数。

## 基于应用框架的程序设计

MFC/Qt等框架提供：
- 主程序结构（消息循环已封装）
- 窗口类层次（继承自框架基类）
- 消息映射机制
- 程序员只需：继承 + 重写消息处理函数

> [!tip] 框架 = 更高层次的代码复用
> 框架提供程序骨架，程序员填充具体业务逻辑。
> 这是**好莱坞原则**："Don't call us, we'll call you"

## 考试/测试常见模式

| 场景/关键词 | 答案 |
|-------------|------|
| "消息循环是什么" | 不断取消息→分发→处理的循环 |
| "WM_QUIT的作用" | 终止消息循环，结束程序 |
| "事件驱动vs顺序" | 用户决定流程 vs 程序决定流程 |
| "MFC/框架的好处" | 封装消息循环+提供类层次+消息映射 |
| "好莱坞原则" | 框架调用你的代码，而不是你调用框架 |
