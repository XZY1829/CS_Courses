# 友元（★★☆）

#cpp #class #friend #access-control

## 概览表（一目了然）

| 条目 | 要点 |
|------|------|
| 定义 | 被授权访问类的private/protected成员的外部实体 |
| 三种形态 | 友元函数、友元类、友元成员函数 |
| 声明位置 | 在被访问类内部用 `friend` 关键字声明 |
| "三不"原则 | 不对称、不传递、不继承 |
| 设计意义 | 在封装和效率/便利之间的折中 |

## 为什么需要友元

封装是OOP核心，但某些场景完全封闭会导致代码臃肿：
- **操作符重载**：`cout << myObj` 需要访问私有成员
- **类间紧密协作**：频繁get/set降低性能和可读性

友元 = 有选择地开放私有成员给受信任的外部代码。

## 三种形态

### 1. 友元函数 (Friend Function)

```cpp
class A {
    int x;
    friend void show(const A& a);  // 授权全局函数
};

void show(const A& a) {
    cout << a.x;  // 可以直接访问private成员
}
```

### 2. 友元类 (Friend Class)

```cpp
class A {
    int x;
    friend class B;  // B的所有成员函数都能访问A的私有成员
};

class B {
public:
    void access(A& a) { a.x = 10; }  // OK
};
```

### 3. 友元成员函数

```cpp
class A;  // 前向声明
class B {
public:
    void special(A& a);  // 只有这个函数是A的友元
};

class A {
    int x;
    friend void B::special(A& a);  // 仅授权B的special函数
};
```

## 友元的"三不"原则（必记）

| 原则 | 说明 | 类比 |
|------|------|------|
| **不对称** | A是B的友元 ≠ B是A的友元 | 你把别人当朋友，别人未必 |
| **不传递** | A是B友元，B是C友元 ≠ A是C友元 | 朋友的朋友不是你的朋友 |
| **不继承** | 基类的友元 ≠ 派生类的友元 | 父亲的朋友不是儿子的朋友 |

## 友元的设计取舍

| 优点 | 缺点 |
|------|------|
| 提高效率（不需要通过接口） | 破坏了封装 |
| 方便操作符重载 | 增加耦合度 |
| 简化紧密协作类的交互 | 不利于维护 |

> [!tip] 使用原则
> 能不用友元就不用。只在操作符重载、紧密协作等确实需要的场景使用。

## 考试/测试常见模式

| 场景/关键词 | 答案 |
|-------------|------|
| "友元破坏封装吗" | 是的，友元是封装的受控破坏 |
| "友元关系三不" | 不对称、不传递、不继承 |
| "友元声明放在哪" | 被访问类的内部（任何位置） |
| "friend class B 意味着" | B的所有成员函数都能访问本类私有成员 |
| "cout << obj 为什么用友元" | operator<<的第一个参数是ostream&，不能是成员函数 |
