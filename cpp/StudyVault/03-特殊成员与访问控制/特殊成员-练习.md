## 第 1 题 - 浅拷贝问题诊断 [application]

> 以下代码运行后会出什么问题？如何修复？
> ```cpp
> class Buffer {
>     char *data;
>     int size;
> public:
>     Buffer(int n) : size(n) { data = new char[n]; }
>     ~Buffer() { delete[] data; }
> };
> Buffer a(100);
> Buffer b(a);  // 使用隐式拷贝构造
> ```

> [!answer]- 查看答案
> **问题**：隐式拷贝构造执行浅拷贝，a.data和b.data指向同一块内存。
> - 修改b会影响a（共享数据）
> - a和b析构时会**double free**同一块内存 → 程序崩溃
> 
> **修复**：自定义拷贝构造函数实现深拷贝：
> ```cpp
> Buffer(const Buffer& other) : size(other.size) {
>     data = new char[size];
>     memcpy(data, other.data, size);
> }
> ```

## 第 2 题 - 拷贝构造触发时机 [recall]

> 列举触发拷贝构造函数的三种场景，并分别给出代码示例。

> [!answer]- 查看答案
> 1. **用同类对象初始化新对象**：`A a2(a1);` 或 `A a2 = a1;`
> 2. **对象作为值参数传给函数**：`void f(A x); f(a);` — 创建x时调用拷贝构造
> 3. **对象作为函数返回值**：`A f() { A a; return a; }` — 创建返回值临时对象时调用
> 
> 注意：`A a2 = a1;` 是**初始化**（调用拷贝构造），不是赋值！
> 而 `a2 = a1;`（a2已存在）是**赋值**（调用赋值操作符）。

## 第 3 题 - move语义理解 [recall]

> 什么是转移构造函数？它和拷贝构造函数的区别是什么？什么时候使用std::move？

> [!answer]- 查看答案
> - **转移构造函数**：参数为右值引用 `A&&`，通过"窃取"源对象的资源（而非复制）来初始化新对象
> - **区别**：拷贝构造"复制"资源（新申请+拷贝），转移构造"转移"资源（指针交换+源置空）
> - **std::move的使用**：当确定一个左值对象后续不再使用，想把它的资源转移给另一个对象时
> ```cpp
> A a;
> A b(std::move(a));  // a的资源转给b，a变为空/无效状态
> ```
> 注意：move后的对象处于"有效但未指定"状态，不应再使用它的值。

## 第 4 题 - const成员函数 [application]

> 以下代码哪些行会编译错误？为什么？
> ```cpp
> class A {
>     int x;
>     int *p;
> public:
>     A() : x(0), p(new int(5)) {}
>     void f() const {
>         x = 10;          // (1)
>         p = new int(20); // (2)
>         *p = 30;         // (3)
>         cout << x;       // (4)
>     }
> };
> ```

> [!answer]- 查看答案
> - (1) **Error** — const函数不能修改数据成员x
> - (2) **Error** — const函数不能修改指针成员p本身
> - (3) **编译通过！** — p的值（地址）没变，只修改了p指向的内容。编译器不检查这种间接修改
> - (4) **OK** — 只读取，不修改
> 
> 这是一个经典陷阱：const成员函数**不保护指针所指向的数据**。

## 第 5 题 - 静态数据成员 [recall]

> 静态数据成员为什么必须在类外初始化？不初始化会怎样？

> [!answer]- 查看答案
> **原因**：
> - 静态数据成员属于类，不属于任何对象
> - 类定义通常在头文件中，如果在类内初始化，每个包含该头文件的源文件都会生成一份定义 → 链接错误（多重定义）
> - 类外定义保证只有一份实体
> 
> **不初始化的后果**：链接错误 — "undefined reference to ClassName::member"
> 
> ```cpp
> // .h 文件
> class A { static int count; };  // 只是声明
> // .cpp 文件
> int A::count = 0;  // 定义+初始化（必须）
> ```

## 第 6 题 - 静态成员函数限制 [application]

> 以下代码有什么错误？如何修复？
> ```cpp
> class A {
>     int x;
>     static int y;
> public:
>     static void f() {
>         y = 10;    // (1)
>         x = 20;    // (2)
>         g();       // (3)
>     }
>     void g() { x = y; }
> };
> ```

> [!answer]- 查看答案
> - (1) **OK** — 静态函数可以访问静态成员
> - (2) **Error** — 静态函数没有this，不知道是哪个对象的x
> - (3) **Error** — g()是非静态成员函数，需要this指针
> 
> **修复方案**：如果需要在静态函数中操作具体对象，传入对象引用：
> ```cpp
> static void f(A& obj) {
>     y = 10;
>     obj.x = 20;
>     obj.g();
> }
> ```

## 第 7 题 - 友元关系判断 [application]

> 以下哪些访问是合法的？
> ```cpp
> class A { int x; friend class B; };
> class B { int y; friend class C; };
> class C {
>     void f(A& a, B& b) {
>         a.x = 1;  // (1)
>         b.y = 2;  // (2)
>     }
> };
> ```

> [!answer]- 查看答案
> - (1) `a.x = 1` — **Error！** C不是A的友元（友元关系**不传递**：B是A的友元，C是B的友元，但C不是A的友元）
> - (2) `b.y = 2` — **OK**。C是B的友元，可以访问B的私有成员

## 第 8 题 - 对象计数器设计 [application]

> 使用静态成员设计一个类，能跟踪当前存活的对象数量（机试考点）。

> [!answer]- 查看答案
> ```cpp
> class Tracker {
>     static int alive;
> public:
>     Tracker() { alive++; }
>     Tracker(const Tracker&) { alive++; }  // 拷贝也是新对象
>     ~Tracker() { alive--; }
>     static int count() { return alive; }
> };
> int Tracker::alive = 0;
> ```
> 关键点：
> - 拷贝构造也要增加计数（易遗漏！）
> - 析构时减少计数
> - 使用静态成员函数查询（不需要对象即可调用）

## 第 9 题 - 深拷贝完整实现 [analysis]

> 一个类如果需要自定义拷贝构造函数，通常还需要自定义哪些函数？为什么？（Rule of Three/Five）

> [!answer]- 查看答案
> **Rule of Three**（C++11前）：如果需要自定义以下任一，通常三个都需要：
> 1. **拷贝构造函数** — 深拷贝资源
> 2. **赋值操作符** — 释放旧资源+深拷贝新资源
> 3. **析构函数** — 释放资源
> 
> **Rule of Five**（C++11后）增加：
> 4. **转移构造函数** — 高效转移资源
> 5. **转移赋值操作符** — 释放旧资源+转移新资源
> 
> **原因**：需要自定义说明类管理了外部资源。所有涉及对象创建、复制、赋值、销毁的操作都需要正确处理该资源。

## 第 10 题 - 综合辨析 [analysis]

> 比较const成员函数、static成员函数和friend函数在"访问私有成员"方面的异同。

> [!answer]- 查看答案
> | 维度 | const成员函数 | static成员函数 | friend函数 |
> |------|--------------|---------------|-----------|
> | 有this吗 | 有（const this） | 没有 | 没有（不是成员） |
> | 能访问私有成员 | 能（只读） | 能（仅静态的） | 能（全部） |
> | 能修改数据 | 不能（除mutable） | 不能修改非静态的 | 能 |
> | 属于类吗 | 是 | 是 | 不是（被授权） |
> | 通过什么访问 | `obj.f()` | `Class::f()` 或 `obj.f()` | `f(obj)` |
> | 设计目的 | 保证只读操作 | 操作类级别数据 | 高效协作/操作符重载 |
