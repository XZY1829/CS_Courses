拷贝构造函数
在创建一个对象时，如果用另一个同类的对象对其进行初始化，将会去调用对象类中的一个特殊构造函数--拷贝构造函数。
拷贝构造函数的参数类型为本类的引用。例如：
class A
{	......
public:
A();  //默认构造函数
A(const A& a);  //拷贝构造函数
};

============================================================
=== Slide 3 ===
============================================================

何时将会调用拷贝构造函数？
在下面三种情况下，会去调用拷贝构造函数：
1. 创建对象时显式指出用另一个同类对象对其初始化 这是最直接和常见的使用场景，即在代码中明确要求用一个已有的对象来作为一个新诞生对象的初始状态。 例如：
A a1;
A a2(a1);  //创建对象a2，用对象a1对其进行初始化
2. 把对象作为值参数传给函数 当函数的参数类型是类的对象本身（即按值传递，而不是传递引用 & 或指针 *），在调用该函数时，系统需要在内存中创建一个局部的形参对象。此时，就会调用拷贝构造函数，用你传入的实参对象去初始化这个形参对象。 代码示例：
void f(A x); // 函数的形参 x 是一个按值传递的对象
//......
A a;
f(a); // 调用函数 f 时，系统创建形参对象 x，并用传入的对象 a 对其初始化，触发拷贝构造函数
3.把对象作为函数的返回值时。例如：
A f()
{	A a;
......
return a; //创建不可见的返回值临时对象，用局部对象 a 对其进行初始化，触发拷贝构造函数
}

隐式拷贝构造函数
在程序中，如果没有为某个类提供拷贝构造函数，则编译器将会为其生成一个隐式拷贝构造函数。
隐式拷贝构造函数将逐个成员进行拷贝初始化：
对于非对象成员，它采用通常的拷贝操作（如把 b1.z 赋值给 b2.z）
对于成员对象，则调用成员对象类的拷贝构造函数来对成员对象进行初始化（递归定义！）

自定义拷贝构造函数
一般情况下，编译程序提供的隐式拷贝构造函数的行为足以满足要求，类中不需要自定义拷贝构造函数。
但在一些特殊情况下，必须要自定义拷贝构造函数，否则，将会产生设计者未意识到的严重程序错误。
浅拷贝的危机：当类内部包含指针时（如 String 类包含 char *str），隐式拷贝只会复制指针地址。
必须自定义的场景：在一些特殊情况下（如涉及动态内存分配），必须要自定义拷贝构造函数，否则会产生设计者未意识到的严重程序错误。
深拷贝 (Deep Copy)：
重新申请新空间 (new)。
拷贝指针指向的值 (strcpy)

自定义拷贝构造函数
它带来的问题是：
如果对一个对象（s1或s2）操作之后修改了这块空间的内容，则另一个对象将会受到影响。如果不是设计者特意所为，这将是一个隐藏的错误。
当对象s1和s2消亡时，将会分别去调用它们的析构函数，这会使得同一块内存区域将被归还两次，从而导致程序运行错误。
当对象s1和s2中有一个消亡，另一个还没消亡时，则会出现使用已被归还的空间问题！
系统提供的隐式拷贝构造函数实施的是浅拷贝（shallow copy）：
对于指针成员，只拷贝指针的值，不拷贝它指向的值

自定义拷贝构造函数
核心注意点：自定义的拷贝构造函数不会自动调用成员对象类的拷贝构造函数！
class A
{		int x,y;
public:
A() { x = y = 0; }
void inc() { x++; y++; }
};
class B
{    int z;
A a;
public:
B() { z = 0; }
B(const B& b)            { z = b.z; }
void inc() { z++; a.inc(); }
};
B b1;  /b1.z、b1.a.x和b1.a.y均为0
b1.inc();  //b1.z、b1.a.x和b1.a.y均变成了1
B b2(b1); //b2.z为1，调用A类的默认构造函数： b2.a.x和b2.a.y均为0
上面b2.a是用A的默认构造函数初始化的！
如果要用b1.a对b2.a进行拷贝初始化，需要在B类自定义拷贝构造函数的成员初始化表中显式指出！
: a(b.a)

拷贝构造存在的问题
当用一个临时或即将消亡的对象去初始化另一个同类的对象时，自定义的拷贝构造函数的效率有时是不高的。
例如
class A
{ char *p;
public:
A(const char *str)
{ p = new char[strlen(str)+1]; //申请内存空间
strcpy(p,str);
}
A(const A& x) //拷贝构造函数
{ p = new char[strlen(x.p)+1]; //申请内存空间
strcpy(p,x.p); //内容复制
}
~A()
{ if (p != NULL) delete[]p; //归还内存空间
p = NULL;
}
void g() { ...... }
};

=== Slide 13 ===
============================================================

拷贝构造存在的问题
在编译器没有优化的情况下，下面的代码效率不高：
A f()
{ A t("1234"); //创建局部对象t(调用构造函数申请空间)
......
return t; //创建返回值对象(调用拷贝构造函数申请空间,内容复制)
//然后，局部对象t消亡（调用析构函数归还空间）
}
int main()
{ ......
f().g();   //使用函数f的返回值对象，然后，
//该返回值对象消亡（调用析构函数归还空间）
......
}
问题：执行“return t;”时，由于局部对象t即将消亡，它申请的空间不再使用，为什么不把它申请的空间转移给返回值对象呢？这样可省掉返回值对象申请空间、内容复制以及对象t消亡归还空间的开销，从而提高效率。

返回值优化（RVO）
当函数返回一个对象时，有些情况下，编译器会进行返回值优化（Return Value Optimization，RVO）。
例如，在编译器优化的情况下，下面的“return t;”不会创建返回值对象，而是直接把t返回：
A f()
{ A t("1234");
......
return t; //这里并没有创建返回值对象，而是直接把t返回了！
//这样就省掉了调用返回值对象的拷贝构造函数和t的析构函数
}
问题：t是局部对象，函数返回后其生存期就结束了，应该是不能再使用它的，那优化是如何实现的？

============================================================
=== Slide 15 ===
============================================================

返回值优化（RVO）
当函数的返回值类型为结构或类时，编译器通常会采用下面的方式为返回值分配空间：
函数调用前，会在调用者的栈空间中为返回值分配一块临时内存空间；
函数调用时，会把这个临时内存空间的地址作为额外的参数传给被调用者，被调用者通过这个地址存储返回值。
函数返回后，调用者通过这块内存空间获得返回值。

============================================================
=== Slide 16 ===
============================================================

返回值优化（RVO）
如果函数把一个与返回值同类型的局部对象（如前面例子中的对象t）返回，编译器有时会优化这个局部对象的空间分配，实现策略是：
不再为这个局部对象单独分配空间，而是把返回值对象的空间分配给它。
这样，返回值对象与这个局部对象就是同一个对象，函数返回时直接把这个局部对象返回，而不会去调用拷贝构造函数再创建返回值对象。
由于这个局部对象的空间是在调用者的栈空间中，函数返回后，它仍然有效！即，前面例子中的对象t在函数返回后仍然有效。

转移构造函数
如果一个构造函数的参数类型为本类的右值引用，则该构造函数叫做转移构造函数（move constructor）。
例如，下面就是一个转移构造函数：
A(A&& x); //参数为本类的右值引用类型：&&
由于右值引用类型的参数只接受右值，因此，当用一个临时对象或即将消亡的对象（它们属于右值）去初始化另一个对象时，将会去调用转移构造函数进行对象初始化。
注意：如果对象类中没有自定义转移构造函数，系统不会提供一个隐式转移构造函数！

同类对象如何共享数据？

静态成员函数
在一些“纯”面向对象程序设计语言（如Smalltalk）中，把类也看作对象，用元类（meta class）来描述类这个对象。

友元
虽然封装（Encapsulation）是面向对象的核心，但在某些场景下，完全的封锁会导致代码变得极其臃肿或低效。
操作符重载： 最典型的例子是重载 << 输出流。如果你想写 cout << myObj;，由于 cout 是 ostream 类的对象，它无法访问 myObj 的私有数据，这时就需要将该函数设为友元。
类间紧密协作： 两个类逻辑上关系紧密（如“远程控制器”和“电视机”），频繁通过 get/set 函数传递数据会降低性能和可读性。
友元是数据保护和数据访问效率之间的一种折衷方案。

友元
友元的“三不”原则（必记）
友元关系非常特殊，它不遵循类的一般继承规则：
友元关系是单向的： A 是 B 的友元，并不代表 B 是 A 的友元（你把别人当真心朋友，别人可能只把你当工具人）。
友元关系是不传递的： A 是 B 的友元，B 是 C 的友元，A 并不自动成为 C 的友元（你朋友的朋友，不一定是你的朋友）。
友元关系不能继承： 基类的友元对派生类没有特殊访问权限；同样，如果基类是友元，它的派生类也不会自动继承这个友元特权。

void multiply(const Matrix &m, const Vector &v, Vector &r)
{	if (m.dimension_column() != v.dimension() ||
m.dimension_row() != r.dimension()) //判断合法性
{  cerr << "矩阵和向量的尺寸不匹配！\n";
exit(-1);
}
int row=m.dimension_row(),
col=m.dimension_column();
for (int i=0; i<row; i++)
{  r.element(i) = 0;
for (int j=0; j<col; j++) //计算r[i]
r.element(i) += m.element(i,j)*v.element(j);
}
}
由于频繁地通过调用成员函数element来访问矩阵和向量的元素，因此效率不高！

void multiply(const Matrix &m, const Vector &v,
Vector &r)
{	if (m.col != v.num || m.row != r.num)
{	cerr << "矩阵和向量的尺寸不匹配！\n";
exit(-1);
}
int *p_m=m.p_data,*p_r=r.p_data,*p_v;
for (int i=0; i<m.row; i++)
{	*p_r = 0;
p_v = v.p_data;
for (int j=0; j<m.col; j++)
{	*p_r += (*p_m)*(*p_v);
p_m++;
p_v++;
}
p_r++;
}
}
